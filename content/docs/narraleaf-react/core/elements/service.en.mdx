---
title: "Service"
description: The `Service` abstract class for custom, story-registered logic shared across scenes, covering actions, serialization, and async handling.
---
Service is a special abstract class that is used to create custom actions, behaviors, or any other custom logic that can be shared across multiple scenes.

To use it, you need to extend and fully implement the abstract methods.

```typescript
import {Service} from "narraleaf-react";
```

## Example

Here is an example of a custom service that implements a simple gallery service.

```typescript
type GalleryActions = {
    "add": [name: string]
};

class Gallery extends Service<GalleryActions> {
    // custom data
    unlocked: string[] = [];

    constructor() {
        super();

        // register the action handler
        this.on("add", (ctx: ServiceHandlerCtx, name: string) => {
            console.log("Adding", name);
            this.unlocked.push(name);
        })
    }

    /* Implement the serialize and deserialize methods */
    serialize(): Record<string, any> | null {
        return {
            unlocked: this.unlocked
        };
    }
    deserialize(data: Record<string, any>): void {
        this.unlocked = data.unlocked;
    }

    /* Custom service logic */
    add(name: string) {
        // trigger the action
        return this.trigger("add", name);
    }
}
```

and we can use this service in the game:

```typescript
const gallery = new Gallery();

myScene.action([
    gallery
        .add("image1")
        .add("image2")
        .add("image3"),
]);

```

## Creating Custom Service

### Implementing Service

To implement a service, you need to extend the `Service` class and implement the abstract methods.

```typescript
class MyCustomService extends Service {
    /**
     * Serialize the service to data
     *
     * **Note**: data must be JSON serializable, return null if nothing needs to be saved
     */
    serialize(): Record<string, any> | null {
        return null;
    }

    /**
     * Load data to the service
     * @param data data exported from toData
     */
    deserialize(data: Record<string, any>): void {
    }
}
```

### Registering Actions

To register actions, you need to use the `on` method.  
All registration should be done in the constructor.

```typescript
class MyCustomService extends Service {
    constructor() {
        super();

        this.on("myAction", (ctx: ServiceHandlerCtx, ...args: any[]) => {
            // custom logic
        });
    }
}
```

For ServiceHandlerCtx, see [ServiceHandlerCtx](/docs/narraleaf-react/core/types/ServiceHandlerCtx).

To enable type checking, you can define the action types.

```typescript
type MyCustomActions = {
    "myAction": [arg0: string, arg1: number]
};

class MyCustomService extends Service<MyCustomActions> {
    constructor() {
        super();

        this.on("myAction", (ctx: ServiceHandlerCtx, arg0: string, arg1: number) => {
            // custom logic
        });
    }
}
```

### Async Actions

A handler that returns a promise holds the story until the promise settles, the way a line of dialogue does. A handler that returns anything else lets the story carry on at once.

```typescript
this.on("load", async (ctx: ServiceHandlerCtx, url: string) => {
    const response = await fetch(url, { signal: ctx.signal });
    const data = await response.json();
    if (ctx.signal.aborted) return; // cancelled while waiting: leave the game alone

    this.data = data;
});
```

If the promise rejects, the story stops at this action and the error is reported.

<Callout type="info">
    Since `1.3.0` a handler is waited for whenever it returns a promise. Before, only a function declared `async` was: a plain function returning a promise - `(ctx) => fetch(url)` - ran without the story waiting for it, and a promise that rejected left the story waiting forever without reporting anything.
</Callout>

While it holds the story, a handler hears about the player in two ways: it is **cancelled** when the game moves away from it, and it is **asked to hurry** when the player skips.

#### Cancellation

A run is cancelled when the player steps back past it, the story jumps away from it, a `Control.any` it ran in is won by another branch, or a save is loaded. `ctx.signal` is then aborted. It is a standard `AbortSignal`, so it can be handed to `fetch` and anything else that takes one.

A cancellation cannot be refused, and it does not wait for the handler: by the time the signal fires the game has already moved on. It is the **script's responsibility** to stop any work still in flight (network requests, timers, animations) and roll back the side effects created so far, so that running the action again after a step back gives exactly the same result. Check `ctx.signal.aborted` after each `await` before touching the game again. The rejection a cancelled run ends with - the `AbortError` of a `fetch` - is not reported.

#### Skipping

When the player skips - presses the skip key, holds it, or a host calls [skipDialog](/docs/narraleaf-react/core/game/live-game#skipdialog) or [fastForward](/docs/narraleaf-react/core/game/live-game#fastforward) - a handler holding the story is asked to hurry through `ctx.skip`. Being asked does not end it: the handler decides what being skipped means for it.

| Answer | How | Holding the skip key | `fastForward` |
| --- | --- | --- | --- |
| **Finish now** | Put what it was doing into its final state and return, in `ctx.skip.onRequest` | Moves on | Moves on |
| **Ignore it** | Do nothing - what every handler written before `1.3.0` does | Waits for the handler | Waits up to `stepTimeout`, then reports `"stalled"` |
| **Refuse** | `ctx.skip.refuse(message?)` | Waits for the handler | Stops at once and reports `"refused"` |

```typescript
type MinigameActions = {
    countdown: [seconds: number];
    fishing: [];
};

class Minigames extends Service<MinigameActions, null> {
    constructor() {
        super();

        // Finish now: skipping ends the countdown at once.
        this.on("countdown", async (ctx, seconds) => {
            await new Promise<void>(resolve => {
                const timer = setTimeout(resolve, seconds * 1000);
                ctx.skip.onRequest(() => {
                    clearTimeout(timer);
                    resolve();
                });
                ctx.signal.addEventListener("abort", () => clearTimeout(timer));
            });
        });

        // Refuse: a fast-forward cannot play the minigame for the player, so it stops here.
        this.on("fishing", async (ctx) => {
            ctx.skip.refuse("waiting for the fishing minigame");
            await playFishing(ctx.signal);
        });
    }

    serialize() {
        return null;
    }

    deserialize() {
    }
}
```

- `onRequest` is called the first time the player skips, and once more the first time it is in the skip mode (`request.forced`) - the distinction a line of dialogue draws between one press of the skip key, which reveals a line up to its next pause, and holding it, which walks past the pauses too. It is not called for every repeat of the skip mode.
- `refuse` returns a function that withdraws the refusal. Refusals stack: the action can be skipped again once all of them are withdrawn. The message is for people - it is logged and handed back by `fastForward` - and nothing in the engine reads it.
- `ctx.skip.fastForwarding` says whether the game is fast-forwarding right now, for a handler that can go straight to its final state on entry.
- Requests are broadcast, as they are to everything else on the stage: a handler running in a `Control.all` branch or an async one is asked whenever the player skips. A click on the stage is not a request.
- Only a handler that returns a promise is ever asked. A synchronous one has finished before the player could ask.

See [ServiceHandlerCtx](/docs/narraleaf-react/core/types/ServiceHandlerCtx) for every member.

<Callout type="info">
    `ctx.signal` and `ctx.skip` are available since `1.3.0`. `ctx.onAbort`, which fires on the same occasions as `ctx.signal`, is deprecated.
</Callout>

### Trigger Action

To trigger an action, you can use the `trigger` method.

```typescript
const service = new MyCustomService();

scene.action([
    service.trigger("myAction", "foo", 123)
]);
```

or you can wrap the action in a method.

```typescript
class MyCustomService extends Service<MyCustomActions> {
    myAction(arg0: string, arg1: number) {
        return this.trigger("myAction", arg0, arg1);
    }
}

const service = new MyCustomService();

scene.action([
    service.myAction("foo", 123),

    service
        .myAction("foo", 123)  // actions are wrapped and chainable
        .myAction("bar", 456), // the game will manage the chain behavior automatically
]);
```

### Accessing Service

After creating the service, you need to register it in the game.

```typescript
const story = new Story(/* ... */);
story.registerService("gallery", gallery);
```

And you can access the service using ctx.

```tsx
// ex. in a component
const game = useGame();
const liveGame = game.getLiveGame();

const gallery = liveGame.story?.getService<Gallery>("gallery");

return (
    {gallery && gallery.unlocked.map((name) => (
        <div key={name}>{name}</div>
    ))}
);
```

## Public Methods

### on\<K extends StringKeyOf\<Content\>\>

<Steps>
<Step>

Register an action handler.

```typescript
type MyCustomActions = {
    "myAction": [arg0: string, arg1: number]
};

class MyCustomService extends Service<MyCustomActions> {
    constructor() {
        super();

        this.on<"myAction">("myAction", (ctx: ServiceHandlerCtx, arg0: string, arg1: number) => {
            // custom logic
        });
    }
}
```

- `key: K` - The action key
- `handler: ServiceHandler<Content[K]>` - For ServiceHandler, see [ServiceHandlerCtx](/docs/narraleaf-react/core/types/ServiceHandlerCtx)
- Returns `this`
</Step>
</Steps>
