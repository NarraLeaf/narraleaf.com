title: "Camera"

> This class extends [Displayble](/docs/narraleaf-react/core/elements/displayable)

The camera transforms the **whole stage as one unit**: every [Scene](/docs/narraleaf-react/core/elements/scene), its backgrounds and sprites, and any playing [Video](/docs/narraleaf-react/core/elements/video) move together. The dialog box, menus, and NVL layer stay fixed.

Every [Story](/docs/narraleaf-react/core/elements/story) has exactly one camera, reachable as `story.camera`. You author camera actions like any other element action.

```ts
import { Story, Scene, Character } from "narraleaf-react";

const story = new Story("entry");
const scene = new Scene("scene 1");
const aria = new Character("Aria");

scene.action([
    story.camera.zoom(2, 800, "easeInOut"),   // zoom the whole stage in
    story.camera.pan({ xalign: 0.3 }, 800),   // slide the view across
    story.camera.rotate(3, 400),              // tilt
    story.camera.darken(0.6, 500),            // dim the stage
    aria.say`It's getting dark...`,
    story.camera.resetCamera(600),            // return to the neutral pose
]);
```

<Callout type="info">
    The camera reuses the same [Transform](/docs/narraleaf-react/core/animation/transform) pipeline as
    images and layers, so it inherits every chainable transform method from
    [Displayable](/docs/narraleaf-react/core/elements/displayable): `pos`, `zoom`, `scale`, `rotate`,
    `opacity`, `transform`, `filter`, `effect`, and more. They all apply to the whole stage.
</Callout>

## Accessing the camera

<Steps>
<Step>

`story.camera` is a single, always-present camera. There is exactly one per story, its pose persists across scene changes, and it is captured by save/load like any other element.

```ts
scene.action([
    story.camera.zoom(1.5, 600),
    story.camera.darken(0.4, 400),
]);
```
</Step>
</Steps>

## Public Methods

### pan

<Steps>
<Step>

Pan the camera so the given [position](/docs/narraleaf-react/core/animation/transform/properties) sits at the centre of the view. This is an alias of the inherited `pos` method with camera-oriented naming.

```ts
story.camera.pan({ xalign: 0.3 }, 800, "easeInOut");
```
</Step>
</Steps>

### darken

<Steps>
<Step>

Darken the whole stage. `darkness` is a value between `0` (normal) and `1` (black). Under the hood it drives the camera's CSS `filter` to `brightness(1 - darkness)`, the same mechanism as [`Image.darken`](/docs/narraleaf-react/core/elements/image).

```ts
story.camera.darken(0.6, 500, "easeInOut");
```

<Callout type="warning">
    Darken shares the single CSS `filter` channel, so it overwrites (and is overwritten by) other
    filters. To combine darken with another filter such as `blur`, write the full string yourself
    via `camera.filter("blur(4px) brightness(0.4)")`.
</Callout>
</Step>
</Steps>

### shutter

<Steps>
<Step>

> Available since `0.31.0`

Close or open the shutter: two blades that meet in the middle of the frame.

`1` is fully shut and `0` fully open, and everything between is a partial cover — which makes a small standing value a letterbox rather than a blink, `0.12` being about a cinematic matte. A blink is this driven to `1` and back; the timing of one is the story's to choose, so the engine offers the channel rather than a named routine.

- `shutter: number` - Coverage between `0` (open) and `1` (shut). Out-of-range values are clamped
- `duration?: number`
- `easing?: EasingDefinition`

```typescript
scene.action([
    story.camera.shutter(1, 180, "easeInOut"),
    story.camera.shutter(0, 220, "easeInOut"),
]);
```
</Step>
</Steps>

### vignette

<Steps>
<Step>

> Available since `0.31.0`

Darken the corners of the frame.

Unlike [darken](#darken), which is a filter over the picture, this is a plate over the **view**: it does not move with the camera, so a vignette holds still while the stage underneath it zooms, pans and rotates. Adjust its falloff with [lens](#lens).

- `vignette: number` - Strength between `0` (none) and `1`. Out-of-range values are clamped
- `duration?: number`
- `easing?: EasingDefinition`

```typescript
scene.action([
    story.camera.vignette(0.72, 300, "easeInOut"),
    narrator.say`Everything narrowed to the middle of the room.`,
    story.camera.vignette(0, 300, "easeInOut"),
]);
```
</Step>
</Steps>

### lens

<Steps>
<Step>

> Available since `0.31.0`

Set any of the lens channels at once — the two strengths, and the colour and falloff geometry they are drawn with.

The geometry fields take effect the next time the strength they belong to is above `0`, so they are usually set as a cut before the effect is faded in.

```typescript
type CameraLensProps = {
    shutter?: number;        // 0 open, 1 shut. Default 0
    shutterColor?: string;   // Default "#000"
    vignette?: number;       // 0 none, 1 opaque at the edges. Default 0
    vignetteColor?: string;  // Default "#000"
    vignetteInner?: string;  // Radius the vignette starts at. Default "44%"
    vignetteOuter?: string;  // Radius it reaches full strength at. Default "78%"
};
```

- `lens: CameraLensProps`
- `options?: VisualEffectOptions`

```typescript
scene.action([
    story.camera.lens({vignetteColor: "#1a0b2e", vignetteInner: "20%", vignetteOuter: "95%"}),
    story.camera.vignette(0.9, 400),
]);
```
</Step>
</Steps>

### resetCamera

<Steps>
<Step>

Return the camera to its neutral pose: centred, zoom `1`, no rotation, fully opaque, and no filter (which also clears `darken`).

```ts
story.camera.resetCamera(600, "easeInOut");
```

The filter is cleared on the first frame, and the pose eases over the duration given.

Give no duration when a grade is replaced. A filter eased from one chain to another takes the stage through the colors between them.

<Callout type="warning">
    **Renamed in `0.26.0`: this was `camera.reset`.** Every element carries an internal `reset()` —
    the lifecycle hook the engine runs over the cast when a new game starts or a save loads — and
    the camera was spending that name on this authoring helper, so `newGame()` never restored the
    camera's pose and a story that panned or zoomed kept that framing into the next playthrough.

    Rename any `camera.reset(...)` in your script. Calling `reset()` on a camera now reaches the
    lifecycle hook instead: it restores the configured pose at once, animates nothing, and returns
    the camera rather than a chainable action.
</Callout>
</Step>
</Steps>

## Inherited transform methods

The camera is a [Displayable](/docs/narraleaf-react/core/elements/displayable), so its full transform surface moves the whole stage:

- `zoom(factor, duration?, easing?)` — zoom in/out uniformly.
- `scale(scaleX, scaleY, duration?, easing?)` — non-uniform scale.
- `rotate(deg, duration?, easing?)` — rotate the view.
- `pos(position, duration?, easing?)` — pan (see [`pan`](#pan)).
- `opacity(value, duration?, easing?)` — fade the whole stage.
- `filter(css, options?)` / `effect(...)` — colour-grade the stage (e.g. `"contrast(1.2) saturate(1.3)"`).
- `transform(new Transform(...))` — run a full multi-step [Transform](/docs/narraleaf-react/core/animation/transform) sequence.

## Setting the initial pose

There is exactly one camera per story. Pass your own only to set its starting pose:

```ts
import { Story, Camera } from "narraleaf-react";

const story = new Story("entry", {
    camera: new Camera({ zoom: 1.2 }),
});
```

<Callout type="info">
    The camera moves the visual stage only. The dialog box, menus, and the NVL layer are rendered
    outside it and are intentionally unaffected, so text stays readable while the camera moves.
</Callout>
