Game is the main class that represents the game itself. It contains all the game's configuration and [LiveGame](/docs/narraleaf-react/core/game/live-game)s

A `Game` belongs to the [GameProvider](/docs/narraleaf-react/player/game-providers) that owns it — a provider constructs one, and separate providers own separate games. Reach the one you are inside with the `useGame()` hook.

## Public Properties

### preference

<Steps>
<Step>

the [Preference](/docs/narraleaf-react/core/game/preference/preference) instance

- `Preference<GamePreference>` - See [GamePreference](/docs/narraleaf-react/core/types/GamePreference)

```typescript
game.preference.setPreference("autoForward", true);
```
</Step>
</Steps>

### audioBuses

<Steps>
<Step>

The audio bus mixer: the tree declared in `GameConfig.audioBuses`, and what the player has done to
it. Available at any point after `new Game(...)` — before the audio context has unlocked and before
the player has mounted.

- `AudioBusMixer` - See [Audio Buses](/docs/narraleaf-react/core/game/audio-buses)

```typescript
game.audioBuses.setVolume("alice", 0.5);
localStorage.setItem("mixer", JSON.stringify(game.audioBuses.getVolumes()));
```
</Step>
</Steps>

### keyMap

<Steps>
<Step>

Key binding manager of the game

- `KeyMap` - See [KeyMap](/docs/narraleaf-react/core/game/key-map)

```typescript
game.keyMap.setKeyBinding(KeyBindingType.skipAction, "Control");
```
</Step>
</Steps>

### configure

<Steps>
<Step>

Assign a new configuration to the game

> **Note:** This method is designed to be used before the game is initialized.
> 
> Calling this method after the game is initialized will not take effect or not taking effect immediately. Settings in the [Preference](/docs/narraleaf-react/core/game/preference/preference) will take effect immediately.

```typescript
const game = useGame();

useEffect(() => {
    game.configure({
        ratioUpdateInterval: 0, // update the player size immediately

        /* cursor */
        cursor: "cursor.jpeg",
        cursorHeight: 60,
        cursorWidth: 60,
    });
}, []);
```
</Step>
</Steps>

### use

<Steps>
<Step>

Register a plugin to the game. 

> **Note**: Plugins with the same name will not be registered.
>
> A name consists of `namespace` and `name` is recommended.  
> Ex: `"@Namespace/PluginName"`, `"@Author/PluginName"`, `"PluginName"`

```typescript
game.use({
    ... /** plugin register config */
});
```

- `plugin: IGamePluginRegistry` - The plugin registry config, see [Plugin](/docs/narraleaf-react/core/plugin)
</Step>
</Steps>

### dispose

<Steps>
<Step>

Dispose the game and release all the resources.

> **Note**: This action is irreversible.

```typescript
game.dispose();
```
</Step>
</Steps>

### configureAndFreeze

<Steps>
<Step>

Configure the game and freeze specific fields to prevent further modifications.

> **Warning**: This method is not recommended to be used without using NarraLeaf Engine or Plugin Environment.

```typescript
game.configureAndFreeze({
    ratioUpdateInterval: 0,
    cursor: "cursor.jpeg"
});
```

- `config: DeepPartial<GameConfig>` - The game configuration to apply and freeze
</Step>
</Steps>

### freeze

<Steps>
<Step>

Freeze specific configuration fields to prevent further modifications.

> **Warning**: This method is not recommended to be used without using NarraLeaf Engine or Plugin Environment.

```typescript
game.freeze(["ratioUpdateInterval", "cursor"]);
```

- `fields: (StringKeyOf<GameConfig>)[]` - Array of configuration field names to freeze
</Step>
</Steps>

## Lifecycle Events

Two points in a game's start-up can be listened for. Each fires at most once per game lifecycle, and every listener receives the same context object: `{game, gameState, liveGame, storable, scene}`, where `scene` may be `null`.

<Callout type="warning">
    **`preloadComplete` moved in `0.17.0`.** It now fires *before* the game is entered, while a menu may still be on screen — not after `newGame()` has mounted a scene. Use it to gate a loading step; use `firstSceneReady` for "the game has content on screen". See [Preloading](/docs/narraleaf-react/core/game/preload#which-signal-to-wait-on).
</Callout>

### onPreloadComplete

<Steps>
<Step>

Listen for the initial preload pass completing. Since `0.17.0` this is before the game is entered.

```typescript
const token = game.onPreloadComplete(({scene}) => {
    setLoadingBarDone(true);
});

token.cancel();
```

- `fc: (ctx: GameLifecycleEventContext) => void`
- Returns [LiveGameEventToken](/docs/narraleaf-react/core/types/LiveGameEventToken)
</Step>
</Steps>

### oncePreloadComplete

<Steps>
<Step>

Same, removed after the first call.

- `fc: (ctx: GameLifecycleEventContext) => void`
- Returns [LiveGameEventToken](/docs/narraleaf-react/core/types/LiveGameEventToken)
</Step>
</Steps>

### whenPreloadComplete

<Steps>
<Step>

Resolve when the initial preload pass has completed. Resolves immediately if it already has, so this is the safe form when the listener may be registered late.

```typescript
const {scene} = await game.whenPreloadComplete();
```

- `return: Promise<GameLifecycleEventContext>`
</Step>
</Steps>

### isPreloadComplete

<Steps>
<Step>

Whether the initial preload pass has completed.

- `return: boolean`
</Step>
</Steps>

### onFirstSceneReady

<Steps>
<Step>

Listen for the first scene being fully ready: the preload pass has finished, the first scene component has mounted, **and** the browser has had a frame to render it. This is the most direct signal that the game is visually ready for the player.

```typescript
const token = game.onFirstSceneReady(() => hideLoadingOverlay());

token.cancel();
```

- `fc: (ctx: GameLifecycleEventContext) => void`
- Returns [LiveGameEventToken](/docs/narraleaf-react/core/types/LiveGameEventToken)
</Step>
</Steps>

### onceFirstSceneReady

<Steps>
<Step>

Same, removed after the first call.

- `fc: (ctx: GameLifecycleEventContext) => void`
- Returns [LiveGameEventToken](/docs/narraleaf-react/core/types/LiveGameEventToken)
</Step>
</Steps>

### whenFirstSceneReady

<Steps>
<Step>

Resolve when the first scene is fully ready. Resolves immediately if it already is.

```typescript
await game.whenFirstSceneReady();
```

- `return: Promise<GameLifecycleEventContext>`
</Step>
</Steps>

### isFirstSceneReady

<Steps>
<Step>

Whether the first scene is fully ready.

- `return: boolean`
</Step>
</Steps>
