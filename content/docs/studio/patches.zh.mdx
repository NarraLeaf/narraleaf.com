---
title: 补丁
description: 导出补丁文件，让玩家把它加进手上已有的副本，从而改动已经发布的游戏
---

补丁用于改动已经发布的桌面游戏。它把改写的台词、新增的场景、替换的素材和更新的译文带进玩家已经安装的副本。玩家把一个目录放进游戏自己的目录，删掉目录里的文件就回到游戏发布时的样子。

补丁与安装好的游戏并存读取，安装目录里的任何文件都不会被替换或修改，也不会有安装程序运行。

## 补丁能带什么

补丁可以改动：

- 故事、场景和台词
- 页面与 Game UI
- 译文与配音表
- 素材文件
- 插件数据

补丁不改动引擎和游戏可执行文件，这两者随新的构建与新的安装包发布。

<Callout type="info">
桌面构建读取补丁，Web、Android 和 iOS 构建不读取。
</Callout>

## 分发密钥

只有在构建时工程已经有分发密钥，该构建才接受补丁。打开**项目**面板，选择**工程**，在**分发密钥**下选择**创建**。

密钥随工程保存，并随工程进入版本控制，因此参与构建的每个人用的是同一把密钥。页面只报告密钥是否存在以及上次更换的日期，密钥本身不会显示。

**更换**会换上一把新密钥。已经用上一把密钥发布出去的构建，不接受此后做出的补丁。

在发给玩家的那次构建之前创建密钥。在密钥存在之前做出的构建不接受补丁。

## 导出补丁

<Steps>
<Step>

### 修改工程

替换素材、改写台词、新增场景。补丁按工程当前的状态导出。
</Step>
<Step>

### 打开窗口

在顶部操作栏的**运行与构建**下拉菜单中选择**导出补丁…**，打开**导出补丁**窗口。
</Step>
<Step>

### 填写四个字段

**变体**是这个补丁针对的构建变体。补丁只能在它所针对的那个变体的构建里打开。

**这个补丁针对的构建**是补丁与之比对的那次已发布构建。**浏览…**选择打包器写出的那个桌面构建目录。只有与那次构建不同的部分会被装进补丁。留空则整份游戏都装进补丁。

**保存为**是补丁文件的写出位置。Studio 默认给出工程 `dist` 目录下的 `patch` 目录，并按工程名命名文件。导出总是写进这里所选位置下的 `patch` 目录。

**名称**显示在游戏日志里，位于补丁文件名旁边。
</Step>
<Step>

### 导出

选择**导出**。Studio 编译工程，并在 `patch` 目录里写出一个 `.patch.dat` 文件。进度、检查结果和最终体积显示在**控制台**中。
</Step>
</Steps>

导出与正式构建共用同一个会话，因此不能同时进行。

## 导出时关于存档的报告

控制台按两个数报告这个补丁对玩家已有存档做了什么：

- 存档可以停下的位置中，已经不存在的数量。停在这些位置的存档在补丁装着的时候拒绝加载，删掉补丁文件后重新可以打开。
- 存档可以为其保存状态的元素中，已经不存在的数量。这些存档照常加载，为这些元素保存的状态被丢弃。

两条都会点出损失所在的场景名。

新增台词、改写台词和替换素材不会产生这两个数，删除台词或场景会产生。

这些是警告，导出照常进行。**这个补丁针对的构建**留空时，控制台报告没有对已有存档做任何检查。

## 把补丁交给玩家

把 `patch` 目录打成压缩包发送。玩家将它解压到游戏自己的目录，解压后游戏是这样：

<Files>
    <Folder name="patch" defaultOpen>
        <File name="episode-two.patch.dat" />
    </Folder>
    <Folder name="resources" />
    <File name="My Game.exe" />
</Files>

游戏自己的目录就是放着它 `resources` 目录的那一层。在 Windows 和 Linux 上，可执行文件也在这一层；在 macOS 上是应用包内的 `Contents`。

删掉 `.patch.dat` 文件即撤销补丁，游戏回到发布时的样子。

游戏还会读取玩家文件目录下的 `patch` 目录。放在那里的补丁在重装游戏之后依然生效，并且优先于游戏自己目录下的补丁。**项目 ▸ 应用**的**玩家文件**一节列出该目录在各平台的路径。

一个目录里可以同时放多个补丁文件，它们按文件名顺序生效，两个补丁改动同一处时以靠后的那个为准。

## 构建接受哪些补丁

补丁只能在它所针对的工程和变体的构建里打开。为别的工程做的、为别的变体做的，或者导出之后被改动过的文件不会生效，游戏照常启动。游戏日志会记下每一个生效的补丁和每一个没有生效的补丁。
