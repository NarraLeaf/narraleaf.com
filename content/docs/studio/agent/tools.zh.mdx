Studio 的 MCP 服务器自带 54 个工具，列于下文，插件还可以添加更多，见[插件工具](#plugin-tools)。工具说明使用英文，因为它们是写给 Agent 阅读的，每条说明都写明了何时使用该工具。“Studio 中显示为”一列是 Studio 在 **Agent 日志**和状态栏中对该调用的称呼

**修改项目**为“是”的工具在 **允许 Agent 修改工程** 关闭时会被拒绝；作用于已打开项目的，在 Agent 暂停、项目冻结以及 Team 实时会话期间也会被拒绝。其余工具只读取，试玩也属于其中，因此 Agent 无需修改权限即可检查游戏

所有作用于项目的工具都接受可选参数 `project`，即项目目录的绝对路径，仅在同时打开多个项目时需要

## 会话与指南

| 工具 | Studio 中显示为 | 修改项目 | 用途 |
| --- | --- | --- | --- |
| `agent_status` | 查询 Studio 状态 | 否 | 报告 Studio 中打开了哪些项目、是否允许修改、Agent 是否已暂停，以及可以从哪些目录导入文件，应最先调用 |
| `agent_guide` | 阅读指南 | 否 | 以 Markdown 返回 NarraLeaf 游戏制作指南中的一章 |

## 插件工具 [#plugin-tools]

插件可以为 Agent 提供自己的工具。它们与 Studio 的工具列在一起，名称由插件 ID 和工具名组成：其中的 `.` 和 `-` 都换成 `_`，两部分之间用 `__` 连接。Gallery 的 `narraleaf.gallery.add_entries` 以 `narraleaf_gallery__add_entries` 的名称提供

插件的工具只在加载了该插件、并在其中启用了该插件的项目处于打开状态时提供。情况变化时，保持 Studio 通知流打开的客户端会收到列表已变化的通知，其他客户端在下次获取列表时看到新的列表。`agent_status` 会列出每个已打开项目提供的插件工具

插件工具接受与 Studio 自身工具相同的检查，**修改项目**一列的含义也相同。**设置 → Agent 接入 → 插件工具** 可以关闭某个插件的全部工具。插件作者请参阅 [Agent 工具](/zh/docs/studio/plugin/studio/agent-tools)

插件还可以附带一章指南，通过 `agent_guide` 和 `plugin:<plugin id>` 读取

### Gallery

内置的 [Gallery](/zh/docs/studio/blueprint/nodes/built-in-plugins/gallery) 插件用于填充鉴赏界面，其指南章节为 `plugin:narraleaf.gallery`。工具标题由插件自己提供，没有翻译

| 工具 | Studio 中显示为 | 修改项目 | 用途 |
| --- | --- | --- | --- |
| `narraleaf_gallery__list` | Read the gallery | 否 | 鉴赏界面的目录：分组、各类条目（cg、scene、music、voice）及其 id 和变体，以及锁定时的外观 |
| `narraleaf_gallery__add_entries` | Add gallery entries | 是 | 向鉴赏界面添加条目，记为一步撤销 |
| `narraleaf_gallery__update_entries` | Edit gallery entries | 是 | 编辑已有条目，记为一步撤销 |
| `narraleaf_gallery__remove_entries` | Remove gallery entries | 是 | 按 id 从画廊中移除条目，记为一步撤销 |
| `narraleaf_gallery__set_groups` | Set gallery groups | 是 | 按顺序替换画廊的分组列表，记为一步撤销 |
| `narraleaf_gallery__set_settings` | Set the gallery's locked look | 是 | 设置锁定条目在鉴赏界面上的外观，记为一步撤销 |

## 文本格式

Agent 通过三种文本格式读写项目内容：

| 格式 | 内容 | 读取 | 写入 |
| --- | --- | --- | --- |
| `.story` | 一个场景：头部、各行及分支 | `story_show` | `story_apply` |
| `.ui` | 一个页面、游戏 UI 或组件：元素及其属性 | `ui_show` | `ui_apply`、`ui_patch` |
| `.bp` | 一个所有者的蓝图 | `blueprint_show` | `blueprint_apply` |

每次读取都返回一个 `revision`；写入时带回该值，如果内容在此期间有变动，写入会以 `stale_revision` 被拒绝。`story_apply`、`ui_apply`、`ui_patch` 和 `blueprint_apply` 接受 `dryRun: true`，只检查文本，不写入

格式说明见指南的 `story-format`、`ui-format` 和 `blueprint-format` 三章。有哪些命令、控件和节点，由目录类工具回答：`story_commands`、`story_command`、`story_targets`、`ui_widgets`、`ui_widget`、`ui_usage`、`blueprint_nodes` 和 `blueprint_node`，它们从正在运行的 Studio 读取，Agent 应当查询它们，而不是凭记忆书写

## 指南

`agent_guide` 接受一个 `chapter` 参数，不传时列出现有的全部章节：

| 章节 | 内容 |
| --- | --- |
| `workflow` | 从需求确认到构建的工作顺序 |
| `story-format` | `.story` 格式 |
| `ui-format` | `.ui` 格式 |
| `blueprint-format` | `.bp` 格式 |
| `ui-design` | 视觉小说界面的设计 |
| `script-adaptation` | 把剧本转为场景 |
| `verify-and-ship` | 检查、测试、试玩与构建 |
| `troubleshooting` | 各种拒绝及其处理 |
| `plugin:<plugin id>` | 已启用插件附带的章节，例如 `plugin:narraleaf.gallery` |

这些章节同时以 MCP 资源的形式提供，地址为 `narraleaf://guide/<chapter>`，插件的章节为 `narraleaf://guide/plugin/<plugin id>`；`make_game` 提示词以 `workflow` 开始整个流程，可附带可选的 `brief`
