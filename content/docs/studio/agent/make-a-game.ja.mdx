---
title: エージェントでゲームを作る
description: 台本と素材のフォルダーからビルド済みのゲームまで、エージェントが途中で何をするか、そしてそれをどう見守り、どう割り込むか
---

この手順は、エージェントが接続済みで、スキルまたはガイドを持っていることを前提にしています。[エージェントを接続する](/ja/docs/studio/agent/connect)を参照してください。

<Steps>

<Step>

### 台本と素材を用意する

台本をテキストファイルに、画像と音声を 1 つのフォルダーにまとめます。**設定 → エージェント連携**で、そのフォルダーを**素材を読み込めるフォルダー**に追加し、**エージェントによる変更を許可**をオンにします。

立ち絵の背景は透明である必要があります。不透明な立ち絵は四角形として表示されます。Studio が読み込める形式は次のとおりです。

| 種類 | 形式 |
| --- | --- |
| 画像 | PNG、JPEG、WebP、GIF、AVIF、SVG |
| 音声 | MP3、OGG、Opus、WAV、M4A、AAC、FLAC |
| 動画 | WebM、MP4（H.264） |
| フォント | TTF、OTF、WOFF、WOFF2 |

足りない画像があっても作業は止まりません。エージェントがキャプション付きの仮画像を作り、そのことを伝えます。

</Step>

<Step>

### 作りたいものを伝える

たとえば次のように伝えます。

> `~/Documents/winter-story/script.txt` の台本と `~/Documents/winter-story/art` の素材でビジュアルノベルを作って。テキストは日本語、1920x1080、エンディングは 2 つ。

MCP のプロンプトを表示するクライアントでは、`make_game` プロンプトでも同じ作業が始まります。

</Step>

<Step>

### 要件を確認する

エージェントはまず接続を確認し、それから短い要件確認を作者と一緒に行います。タイトル、テキストの言語、解像度、絵柄、キャラクター、エンディング、手元にある素材です。台本を渡された場合は、見つけたシーン、話者、素材に加え、ファイルのない台本上の参照と、台本で使われないファイルを一覧にします。作者がその一覧を認めるまで、プロジェクトには手を付けません。

</Step>

<Step>

### 作業を任せる

作業の順序はスキルが決めています。

| 段階 | エージェントがすること |
| --- | --- |
| 接続 | セッションの状態を読む。開いているプロジェクト、変更できるか、どのフォルダーから読み込めるか |
| 要件 | 作るものを確認する。前の手順のとおり |
| プロジェクト | スケルトンテンプレートからプロジェクトを作るか既存のものを開き、テンプレートのサンプルを再利用する |
| 素材 | 作者のファイルをストーリーで扱いやすい名前で読み込み、足りないものには仮画像を作る |
| キャラクターと変数 | キャラクターのポーズと名前の色、ストーリーに必要な変数を設定する |
| ストーリー | 1 回の呼び出しで 1 シーンずつ分岐も含めて書き、タイトルのスタートボタンを最初のシーンにつなぐ |
| インターフェース | 配色とフォントを決めてから各ページの見た目を整え、1 回ごとにスクリーンショットを確認する |
| インタラクション | テンプレートにない動作にだけブループリントを追加する |
| 検証 | エラーがなくなるまでチェックを実行し、ルートとエンディングのテストを行い、すべてのルートをエンディングまでプレイする |
| 仕上げ | ゲームをビルドし、作ったものと作者に残る作業を報告する |

</Step>

<Step>

### 引き継ぐ

エージェントは最後に報告を出します。作ったシーン、ルート、エンディング、ゲームに残っている仮画像、作者に残る作業、開くべきビルド済みファイルです。プロジェクトは Studio で開いたままなので、そのまま編集を続けることも、エージェントに追加を頼むこともできます。

</Step>

</Steps>

## エージェントを見守る [#watching]

### 追従モード

**エージェントの編集を追う**がオンのとき、Studio は変更が反映されたエディタを開き、変わった要素や行を一時的に枠で示します。既定でオンで、プロジェクトごとに記憶されます。

追従によって Studio が前面に出ることはないので、ほかのアプリケーションでの入力は妨げられません。Studio のタブで入力している最中は、エージェントのタブはその後ろに開きます。

### ステータスバー

エージェントが作業している間、ステータスバーは緑色になります。呼び出しの最中、最後の呼び出しから 15 秒間、そして一時停止している間です。実行中のゲームと実験モードは、それぞれの色のままです。

最初の呼び出しから、ステータスバーにエージェントの様子を示す項目が現れます。

| 表示 | 意味 |
| --- | --- |
| **エージェントが編集中：…** | 呼び出しが、示されたページやシーンを変更している |
| **エージェントが編集しました：…** | 直前の変更。反映後の数秒間表示される |
| **エージェント：…** | 呼び出しの合間。接続中のクライアントを示す |
| **エージェントは一時停止中** | 再開するまで変更はすべて拒否される |

この項目をクリックすると、**エージェントを一時停止**と**エージェントの編集を追う**を選べます。

### エージェントログ

**エージェント → エージェントログ**は、下部のドックのコンソールの隣にパネルを開きます。1 回の呼び出しが 1 行で、時刻、クライアント、何をしたか、何に対してか、結果、所要時間が表示されます。

- 絞り込みで**すべて**、**変更のみ**、**失敗のみ**を切り替えます。
- 何かを変更した行をクリックすると、その変更箇所が開き、枠で示されます。
- 拒否された行を開くと、理由と、エージェントに示された**対処**が表示されます。
- **書き出す…** はログを JSON Lines として保存し、**消去**はログを空にします。

ログはこのウィンドウの直近 500 回の呼び出しをメモリに保持します。記録するのは作者が見ていれば見えた内容で、呼び出しの引数は記録せず、プロジェクトにも書き込みません。

## 作業に割り込む

**一時停止。** ステータスバーの項目または**エージェント**メニューの**エージェントを一時停止**で、**エージェントを再開**するまで、このプロジェクトに対するエージェントの変更はすべて拒否されます。読み取りはできるので、エージェントはその間に作者が変えた内容を把握できます。一時停止はそのセッションの間だけ有効で、Studio を再起動すると解除されます。

**取り消し。** プロジェクトを変更する呼び出しは 1 回ごとに 1 ステップの取り消しになります。**Ctrl+Z**（macOS では **Cmd+Z**）で、自分の変更と同じようにエージェントの直前の変更を取り消せます。スキルは、取り消された変更を「不要」の意思表示として扱い、もう一度試す前に作者に確認するようエージェントに指示しています。

**並行して編集する。** エージェントが作業中のページやシーンを、作者が編集してもかまいません。エージェントの次の書き込みは読み取ったときのリビジョンを伴うので、`stale_revision` で拒否されます。エージェントは作者の版を読み直し、その上で変更をやり直します。作者の編集が優先されます。

**完全に止める。** **エージェントによる変更を許可**をオフにすると、再びオンにするまで、すべてのエージェントの変更が拒否されます。**エージェントの接続を許可**をオフにすると、エンドポイントが停止します。

## たいてい残る作業

エージェントは報告でこれらを挙げます。よくあるものは次のとおりです。

- 背景が不透明な立ち絵。切り抜いた画像を用意するまで四角形のまま表示されます。
- 提供されなかった素材の代わりの仮画像。
- Studio で再生できない形式のファイル。変換が必要です。
- ギャラリーの項目、ほかの言語の翻訳、残ったサンプルの内容。
- アプリケーションのアイコンとコード署名。ビルドダイアログの**識別情報**と**署名**で設定します。[実行とパッケージ化](/ja/docs/studio/getting-started/run-and-package)を参照してください。
