エージェント連携は、コンピューター上のプログラムに、Studio で開いているプロジェクトの読み取りと変更を許します。このページでは、それが何によって守られているかを説明します。

## オンにするまで何も待ち受けない

新しいプロファイルでは**エージェントの接続を許可**はオフです。オンにするまで Studio は何も提供しません。オフにすればエンドポイントはすぐに止まります。

## このコンピューターからのみ

エンドポイントは `127.0.0.1` にだけバインドされるので、ほかのマシンからは到達できません。ただし、ローカルであるだけでは足りません。開いた Web ページは、どれも自分のコンピューターにリクエストを送れるからです。そのため、すべてのリクエストは中身を読む前に検査されます。

- **`Origin` ヘッダーを持つリクエストは拒否します。** ブラウザはこのヘッダーを送りますが、MCP クライアントはプログラムなので送りません。これにより、ポートにリクエストを送る Web ページを締め出します。自分のホスト名を `127.0.0.1` に向けるページも含みます。
- **`Host` ヘッダーはエンドポイントを指している必要があります。** `127.0.0.1` または `localhost` とそのポートです。
- **リクエストにはアクセストークンが必要です。** `Authorization: Bearer <token>` の形で付けます。トークンがない、または誤っているリクエストは拒否されます。
- **1 つのリクエストは最大 4 MB です。** エージェントが送る最大のものは、テキストにしたシーンかページです。

リクエストの内容がコードとして評価されることはありません。各呼び出しの引数は、実行前にツールのスキーマに照らして検査されます。

## アクセストークン

Studio はトークンを、ほかのエージェント連携の設定とともに、ユーザーデータフォルダーの `agent-mcp.json` に保存します。macOS と Linux では、このファイルは自分のアカウントしか読めません。Windows ではユーザーデータフォルダーの権限に依存します。トークンは、エクスポートして共有されることの多い Studio の一般設定には置かれません。

エージェント連携がオンの間、トークンを読めるものは何でもプロジェクトを変更できます。パスワードと同じように扱ってください。**トークンを変更 → 再生成**はすぐに新しいトークンを発行します。古いトークンで設定したクライアントは次のリクエストから拒否され、設定をコピーし直す必要があります。**stdio** のエントリーはトークンを含まないので、そのまま使えます。

トークンがプロジェクトのウィンドウに渡ることはありません。プロジェクトのウィンドウはプラグインのコードを実行するので、その**エージェント**メニューが知らされるのは、エージェント連携がオンか、変更が許可されているか、エンドポイントが動いているかだけです。このメニューからの設定のコピーはウィンドウの外で行われ、直接クリップボードに書き込まれます。

<Callout type="warn">
設定をコピーすると、トークンがシステムのクリップボードに置かれ、ほかのプログラムやクリップボードの履歴から読めるようになります。必要な場所に貼り付け、見られたおそれがあればトークンを再生成してください。
</Callout>

## エージェントが変更できるもの

**変更は既定でオフです。** **エージェントによる変更を許可**がオフの間、エージェントは開いているプロジェクトを読み取れますが、変更はすべて拒否されます。プロジェクトのウィンドウの**エージェント**メニューからオンにするときは、システムのダイアログで確認を求めます。ウィンドウ内のプラグインのコードはこれに答えられません。オフにするときは確認しません。

**一時停止は 1 つのプロジェクトの変更を止めます。** エージェントが一時停止している間、そのプロジェクトへの変更はすべて拒否されます。読み取りはできます。

**取り込み中のプロジェクトは変更を拒否します。** プロジェクトが凍結されている間は変更を受け付けません。過去のバージョンを表示している、手動で凍結した、バージョン管理のマージが終わっていない、Studio がリカバリーモードにある、別の Studio ウィンドウがプロジェクトを引き継いだ、のいずれかです。[Team](/ja/docs/studio/team) のライブセッション中も、参加者と競合しないよう、エージェントの変更は拒否されます。

**変更は Studio を通ります。** エージェントには、プロジェクトフォルダーのファイルに直接書き込むツールがありません。変更はすべて手作業の編集と同じサービスを通るので、エディタに表示され、1 ステップの取り消しになり、手作業と同じようにチェックされます。チェックを通らないシーン、ページ、ブループリントは書き込まれません。

**読み込みは許可したフォルダーからだけです。** エージェントがファイルを読み込めるのは、プロジェクト内と、**素材を読み込めるフォルダー**に登録したフォルダーからだけです。それ以外のパスは拒否されます。

**信頼されていないプロジェクトは実行されません。** Studio が作成したのではないプロジェクトは、信頼するまでテストプレイもビルドもできません。エージェントでも作者でも同じです。ステータスバーの**未信頼**、または**設定 → データ → 信頼済みプロジェクト**で信頼できます。

## エージェントが到達できる範囲

エージェントは、コンピューター上のどのプロジェクトフォルダーでもパスを指定して開けますし、どのフォルダーにでもプロジェクトを作成できます。作者が Studio でできるのと同じです。ビルドは、エージェントが別の場所を指定しない限りプロジェクトのビルドフォルダーに書き出されます。エージェント連携は、エージェントがどのプロジェクトを開くかは制限しません。上記のスイッチが制限するのは、そこで何をしてよいかです。

エージェントが行ったことは、プロジェクトのウィンドウの**エージェントログ**と Studio 自身のログに残ります。[エージェントでゲームを作る](/ja/docs/studio/agent/make-a-game#watching)を参照してください。
