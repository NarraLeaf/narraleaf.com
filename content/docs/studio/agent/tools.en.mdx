---
title: Tools
description: Every tool Studio's MCP server offers, grouped by what it works on.
---

Studio's MCP server has 77 tools of its own, listed below, and plugins can add more; see [Plugin tools](#plugin-tools). Their descriptions are in English, because agents read them, and each one says when to use it. The title is how Studio names the call in the **Agent log** and the status bar.

**Changes the project** marks the tools that are refused while **Allow agents to change projects** is off. In the open project they are also refused while the agent is paused, while the project is frozen, and during a Team live session. The other tools read; play-testing is among them, so an agent can check a game without permission to change it.

Every tool that works on a project takes an optional `project`, the project folder's absolute path. It is needed only when more than one project is open.

## Session and guide

| Tool | Shown in Studio as | Changes the project | Purpose |
| --- | --- | --- | --- |
| `agent_status` | Studio status | No | Says which projects are open in Studio, whether write access and full access are on, whether the agent is paused, and which directories it may import files from. Call it first |
| `agent_guide` | Read the guide | No | Returns one chapter of the NarraLeaf game-making guide as Markdown |
| `request_folder_access` | Ask for folder access | No | Asks you, in one Studio window, to let the agent read the folders that hold the files it names, before a big import. Answers `granted`, `denied` or `pending` |

## Characters and variables

| Tool | Shown in Studio as | Changes the project | Purpose |
| --- | --- | --- | --- |
| `characters_list` | List characters | No | Lists characters with id, name, nicknames, name colour, kind, their looks (a preset character's poses, a layered character's axes and layers, a Live2D or Spine character's model) `entranceTransform` (how big the sprite is drawn and where it stands) and the dialogue avatars |
| `character_upsert` | Create or update a character | Yes | Creates a character, or updates the one with this `id` or exact `name`, including its dialogue avatars |
| `character_layered_set` | Lay out a layered character | Yes | Creates a layered character, or replaces the looks of one: its axes with their tags, and its layers from bottom to top |
| `character_layers_import` | Build a layered character from files | Yes | Builds a layered character from image assets named `<prefix>_<layer>` and `<prefix>_<layer>_<tag>`, or from a PSD |
| `character_preview` | Preview a character look | No | Returns a picture of one look of a character, composited as Studio's editor draws it |
| `character_delete` | Delete a character | Yes | Deletes a character, for example the Skeleton template's demo cast |
| `variables_list` | List variables | No | Lists the project's global variables (saved with the game or persistent across saves) |
| `variable_upsert` | Create or update a variable | Yes | Declares a global variable, or updates one by `id` (the way to rename one, since rows and nodes hold the id) or by exact `name` |
| `variable_delete` | Delete a variable | Yes | Deletes a global variable, for example the Skeleton template's demo variables |

Each character edit is one step of undo. Turning a character of another kind into a layered one, or a layered one back into poses, discards its looks, so `character_upsert`, `character_layered_set` and `character_layers_import` refuse it until the call passes `confirmSwitch: true`. The refusal lists the story rows that chose one of the looks. Live2D and Spine characters are read only; they are set up in Studio's character editor.

The avatar is the face beside a line in the dialogue box and the backlog. `character_upsert` takes a `defaultAvatar`, shown wherever nothing more specific is, and `avatars`, one image per pose, or for a layered character one per combination of the axes named in `avatarAxes`, such as one per expression whatever the outfit. Without them, Studio cuts avatars from the sprites when you open the Characters panel. A Live2D or Spine character has the default avatar only.

## Interface

| Tool | Shown in Studio as | Changes the project | Purpose |
| --- | --- | --- | --- |
| `ui_widgets` | Widget catalogue | No | Lists the interface widget types (`nl.button`, `nl.text`, `nl.container`, `nl.list` …) and where each may be inserted |
| `ui_widget` | Widget details | No | Everything about one widget type: props with defaults, bindable props, parts it builds, blueprint events, commands and notes |
| `ui_usage` | Widget usage examples | No | Real occurrences of a widget in the shipped Skeleton template (or this project), printed in the `.ui` format so they can be pasted and edited |
| `ui_surfaces` | List pages and components | No | Lists pages, Game UI (dialogue box, choice …) and components, with element paths, ids and the blueprints attached to them |
| `ui_show` | Read a page as text | No | Prints a page or component in the `.ui` text format, ids and props included, with its `revision` |
| `ui_selection` | What the author selected | No | The page and elements the author has selected in the interface editor, with their props |
| `ui_screenshot` | Look at a page | No | Renders a page (or one element of it) as it looks in the game and returns the image |
| `ui_apply` | Write pages | Yes | Applies a `.ui` document. Each `surface` or `component` block replaces that page's whole element tree |
| `ui_patch` | Edit elements | Yes | Small edits to one page without rewriting it: add an element, set props, move or resize, re-parent, rename, delete, place a component |
| `ui_page_rename` | Rename a page | Yes | Renames a page or Game UI. Go Page nodes and frames that open it hold its id, so they follow |
| `ui_page_delete` | Delete a page | Yes | Deletes a page or Game UI with its elements and blueprints. Refused for the entry page, and while anything still opens or names it; the refusal lists them |
| `ui_page_set_entry` | Set the entry page | Yes | Makes a page the one the game opens on, such as the splash or the title |
| `ui_install_standard_screens` | Install the standard screens | Yes | Brings the Skeleton template's working screens into the project: splash, title, save, load, settings, backlog, Extra and confirm pages, the dialogue box, choice menu, quick menu and notifications, with their components and every blueprint behind them |
| `ui_templates` | Interface templates | No | Lists interface templates from Studio's online template store. They are layouts: most carry no blueprints, so their buttons do nothing until they are wired |
| `ui_template_apply` | Apply a template | Yes | Adds a template's pages to the project as new pages, never as the entry page, and says for each how many blueprints and bound props came with it |
| `brand_get` | Read the palette | No | The project's brand palette and fonts |
| `brand_set` | Change the palette | Yes | Sets palette colours (by id; new ids are added) and the project font stack |

`ui_install_standard_screens` is for a project made from the Empty template, or one whose interface was lost. Start begins the project's own story, and the files, palette entries, translation keys, input actions, save field and persistent variable the screens use come along. A Game UI slot the project already fills is left alone unless the call passes `replace: true`, and the splash becomes the entry page when the current one is empty. Pages that need a plugin the project does not run, such as the Gallery's Extra page, are left out together with the buttons that open them. The whole installation is one step of undo, and `dryRun: true` reports what it would add without writing.

A page from the template store is a layout without logic: its Start button, save slots and sliders do nothing until the agent wires them with blueprints. For screens that already work, the standard screens are the better start.

## Blueprints

| Tool | Shown in Studio as | Changes the project | Purpose |
| --- | --- | --- | --- |
| `blueprint_nodes` | Blueprint node catalogue | No | Searches blueprint nodes, including those of plugins loaded in this project |
| `blueprint_node` | Blueprint node details | No | Pins, inspector params, graph kinds and scope of one node type |
| `blueprint_list` | List blueprints | No | Lists blueprints with their owner (page or element) and event heads |
| `blueprint_show` | Read a blueprint as text | No | Prints one blueprint (or all of one owner) in the `.bp` text format |
| `blueprint_apply` | Write blueprints | Yes | Applies a `.bp` document: each `blueprint` block replaces every graph of its owner |
| `blueprint_remove` | Remove a blueprint | Yes | Removes one blueprint, typically one left behind when the element it belonged to was deleted. Refused while another blueprint or a bound prop still names it |

The check every `.bp` document passes refuses an Element node that names an element of another page or Game UI, since a blueprint reaches only the elements of its own page, and it warns about a loop whose body never wires back to the loop, which would run once and stop. `blueprint_remove` takes `dryRun: true`.

## Translation and voice

| Tool | Shown in Studio as | Changes the project | Purpose |
| --- | --- | --- | --- |
| `localization_status` | Translation progress | No | How far each target language is translated, by status and by origin, and with one language each scene's lines left to do |
| `localization_list` | List text to translate | No | Lists the translation units of one language in reading order, a page at a time, each with its source, translation, status and `rev` |
| `localization_set` | Write translations | Yes | Writes translations of one language, up to 1000 per call, in one step of undo |
| `voice_status` | Voice-over progress | No | The voice languages, the recording file-name rule, whether choice options are voiced, and per language and character how many lines have a take |
| `voice_list` | List voiced lines | No | Lists the voiced lines of one voice language in story order, each with its expected file name, linked take and status |
| `voice_link` | Link voice takes | Yes | Links audio assets to voiced lines one by one, unlinks them, or approves a take, in one step of undo |
| `voice_auto_link` | Link takes by name | Yes | Links every voiced line to the audio asset named after it by the recording rule, in one step of undo |
| `voice_settings_set` | Change voice settings | Yes | Sets the voice languages, the recording file-name rule and whether choice options are voiced |

A translation unit is a story line, a character, scene, ending or `/rename` name, a word on a page or component, a named translation key, or text a plugin offers. One id runs through all of them, so they are listed and written the same way, and a story line's id is also its voice line.

- **Statuses.** A translation is `missing`, `machine`, `translated`, `reviewed` or `stale`, the last when the source changed after it was translated. `localization_set` writes `machine` unless told otherwise; the translation table shows it as **Machine**. A take is `missing`, `linked`, `approved` or `stale`; the voice table shows a linked take as **Voiced** and a stale one as **Outdated**.
- **Markup.** A unit's source shows the values the game fills in as `{0}` and styled words and pauses as run tags, `‹1›word‹/1›` and `‹2/›`. A translation that loses one, a `{name}` placeholder or a line break is written with a warning for that unit.
- **Revisions.** Each unit carries a `rev`. A unit whose source changed since the agent listed it is skipped and returned with its new source.
- **The recording rule.** The default is `{scene}_{index}_{character}`; it also takes `{locale}` and `{unit}`. Names are compared ignoring case, spaces, punctuation and folders, against each asset's library name. A name that several assets or several lines share is returned as ambiguous, never guessed at.

The game's text languages are set with `project_settings_set`, its voice languages with `voice_settings_set`. `localization_set`, `voice_link` and `voice_auto_link` take `dryRun: true`, which checks and writes nothing, as do `character_layered_set` and `character_layers_import`.

## Checking and building

| Tool | Shown in Studio as | Changes the project | Purpose |
| --- | --- | --- | --- |
| `lint` | Check the project | No | Runs every project lint rule and returns the findings, errors first, a page at a time. The answer opens with a count per rule over the whole report; `rule` narrows it to one rule or a category such as `story/`, and `cursor` and `limit` page through it |
| `test` | Run a project test | No | Runs a built-in test headlessly: `narraleaf-studio:route-coverage` (every scene reachable), `narraleaf-studio:reachable-endings`, `narraleaf-studio:project-diagnostics` |
| `playtest_start` | Play the game | No | Opens the game in Dev Mode, from the title page or from a scene (and row) |
| `playtest_advance` | Advance the game | No | Reads on `steps` lines of a running story, through click-waits, timed waits and videos, and stops at a choice menu or an ending, naming the ending |
| `playtest_screenshot` | Look at the game | No | Screenshot of the running Dev Mode game as the player sees it: the stage with its Game UI and every page or layer open over it. `view: "stage"` gives the stage alone, as a save thumbnail shows it |
| `playtest_click` | Click in the game | No | Clicks an element of the running game's interface the way a player's mouse does, named by its id, a path of names, a unique name or the words it shows, and says what opened, closed or started |
| `playtest_hover` | Point at something in the game | No | Rests the pointer on an element without pressing it, so its hover look and its On Mouse Enter graph run |
| `playtest_key` | Press a key in the game | No | Presses a key the way a player's keyboard does, so the input actions bound to it and the focus navigation answer it; also right click and the mouse wheel |

| `playtest_stop` | Stop playing | No | Closes the Dev Mode game |
| `console_read` | Read Studio's console | No | Recent lines from Studio's console (build, story, blueprint, runtime channels) |

The playtest tools act on the game window without bringing it to the front. Every playtest answer also lists the errors and warnings Dev Mode has reported in the run, with the scene and row or the page each came from: the ones the issue strip of the Dev Mode window counts.

## Plugin tools [#plugin-tools]

A plugin can offer agents tools of its own. They are listed beside Studio's tools, under a name made of the plugin id and the tool's name, with every `.` and `-` turned into `_` and the two parts joined by `__`. The Gallery's `narraleaf.gallery.add_entries` is offered as `narraleaf_gallery__add_entries`.

A plugin's tools are offered only while a project that loads the plugin is open, and the plugin is enabled there. When that changes, clients that keep Studio's notification stream open are told the list changed; others see the new list the next time they ask for it. `agent_status` names the plugin tools each open project offers.

A plugin tool passes the same checks as Studio's own, and its **Changes the project** flag means the same. **Settings → Agent access → Plugin tools** switches off all the tools of one plugin. Plugin authors: see [Agent tools](/docs/studio/plugin/studio/agent-tools).

A plugin may also ship a guide chapter, read with `agent_guide` and `plugin:<plugin id>`.

### Gallery

The built-in [Gallery](/docs/studio/blueprint/nodes/built-in-plugins/gallery) plugin fills the Extra page. Its guide chapter is `plugin:narraleaf.gallery`. The titles are the plugin's own and are not translated.

| Tool | Shown in Studio as | Changes the project | Purpose |
| --- | --- | --- | --- |
| `narraleaf_gallery__list` | Read the gallery | No | The Extra page's catalogue: groups, entries of every kind (cg, scene, music, voice) with their ids and variants, and the locked look |
| `narraleaf_gallery__add_entries` | Add gallery entries | Yes | Adds entries to the Extra page in one undo step |
| `narraleaf_gallery__update_entries` | Edit gallery entries | Yes | Edits existing entries in one undo step |
| `narraleaf_gallery__remove_entries` | Remove gallery entries | Yes | Removes entries (by id) from the gallery in one undo step |
| `narraleaf_gallery__set_groups` | Set gallery groups | Yes | Replaces the gallery's group list, in order, in one undo step |
| `narraleaf_gallery__set_settings` | Set the gallery's locked look | Yes | Sets what a locked entry looks like on the Extra page, in one undo step |

## Text formats

An agent reads and writes the project's content as text, through three formats:

| Format | Holds | Read with | Write with |
| --- | --- | --- | --- |
| `.story` | One scene: its header, its rows and its branches | `story_show` | `story_apply` |
| `.ui` | A page, Game UI or component: its elements and their props | `ui_show` | `ui_apply`, `ui_patch` |
| `.bp` | The blueprints of one owner | `blueprint_show` | `blueprint_apply` |

Each read returns a `revision`, and a write that carries it back is refused with `stale_revision` if the content changed in between. `story_apply`, `ui_apply`, `ui_patch` and `blueprint_apply` take `dryRun: true`, which checks the text and writes nothing.

Some of what a `.story` scene can say:

- **Styled words.** Dialogue, narration and choice options can style part of a line with `{b}…{/b}`, `{i}…{/i}` and `{color=…}…{/color}`, nested on one line. A line with styling the format has no tag for, such as ruby or a size, reads back as a `»` row and is kept as it is.
- **Exact positions.** `pos=x,y` on `/show`, `/image`, `/text` and `/transform` places the object's centre. `x` and `y` are shares of the stage: `x` from the left edge (0) to the right (1), `y` from the bottom edge (0) up to the top (1). `left`, `center` and `right` are `0.25,0.5`, `0.5,0.5` and `0.75,0.5`. Beside a `pos=`, `xoffset=` and `yoffset=` add design pixels; a positive `yoffset` moves up.
- **A row that runs a blueprint.** A story row can run a blueprint of its own when play reaches it, including one that calls a plugin's node: unlocking a gallery CG the moment it shows, or granting an achievement. The agent writes the blueprint with `blueprint_apply` and the row with `story_apply`.

The formats are described in the guide's `story-format`, `ui-format` and `blueprint-format` chapters. Which commands, widgets and nodes exist is answered by the catalogue tools, `story_commands`, `story_command`, `story_targets`, `ui_widgets`, `ui_widget`, `ui_usage`, `blueprint_nodes` and `blueprint_node`, which read it from the Studio that is running. An agent should ask them rather than rely on memory.

## Guide

`agent_guide` takes one `chapter`. Without one, it lists the chapters there are:

| Chapter | Covers |
| --- | --- |
| `workflow` | The order of work, from the brief to the build |
| `story-format` | The `.story` format |
| `ui-format` | The `.ui` format |
| `blueprint-format` | The `.bp` format |
| `ui-design` | Designing visual-novel interfaces |
| `script-adaptation` | Turning a script into scenes |
| `layered-sprites` | Layered characters: axes, layers, building one from files or a PSD |
| `verify-and-ship` | Checks, tests, play-testing and building |
| `localization-and-voice` | Translating the game and linking voice recordings |
| `troubleshooting` | Refusals and what to do about them |
| `plugin:<plugin id>` | The chapter an enabled plugin ships, such as `plugin:narraleaf.gallery` |

The same chapters are MCP resources at `narraleaf://guide/<chapter>`, and a plugin's at `narraleaf://guide/plugin/<plugin id>`; the `make_game` prompt starts the `workflow` with an optional `brief`.
