title: Tools
description: Every tool Studio's MCP server offers, grouped by what it works on.
---

Studio's MCP server has 66 tools of its own, listed below, and plugins can add more; see [Plugin tools](#plugin-tools). Their descriptions are in English, because agents read them, and each one says when to use it. The title is how Studio names the call in the **Agent log** and the status bar.

**Changes the project** marks the tools that are refused while **Allow agents to make changes** is off. In the open project they are also refused while the agent is paused, while the project is frozen, and during a Team live session. The other tools read; play-testing is among them, so an agent can check a game without permission to change it.

Every tool that works on a project takes an optional `project`, the project folder's absolute path. It is needed only when more than one project is open.

## Session and guide

| Tool | Shown in Studio as | Changes the project | Purpose |
| --- | --- | --- | --- |
| `agent_status` | Studio status | No | Says which projects are open in Studio, whether write access and full access are on, whether the agent is paused, and which directories it may import files from. Call it first |
| `agent_guide` | Read the guide | No | Returns one chapter of the NarraLeaf game-making guide as Markdown |
| `request_folder_access` | Ask for folder access | No | Asks you, in one Studio window, to let the agent read the folders that hold the files it names, before a big import. Answers `granted`, `denied` or `pending` |

## Characters and variables

| Tool | Shown in Studio as | Changes the project | Purpose |
| --- | --- | --- | --- |
| `characters_list` | List characters | No | Lists characters with id, name, nicknames, name colour, kind, their looks (a preset character's poses, a layered character's axes and layers, a Live2D or Spine character's model) and `entranceTransform` (how big the sprite is drawn and where it stands) |
| `character_upsert` | Create or update a character | Yes | Creates a character, or updates the one with this `id` or exact `name` |
| `character_layered_set` | Lay out a layered character | Yes | Creates a layered character, or replaces the looks of one: its axes with their tags, and its layers from bottom to top |
| `character_layers_import` | Build a layered character from files | Yes | Builds a layered character from image assets named `<prefix>_<layer>` and `<prefix>_<layer>_<tag>`, or from a PSD |
| `character_preview` | Preview a character look | No | Returns a picture of one look of a character, composited as Studio's editor draws it |
| `character_delete` | Delete a character | Yes | Deletes a character, for example the Skeleton template's demo cast |
| `variables_list` | List variables | No | Lists the project's global variables (saved with the game or persistent across saves) |
| `variable_upsert` | Create or update a variable | Yes | Declares a global variable, or updates one by `id` (the way to rename one, since rows and nodes hold the id) or by exact `name` |
| `variable_delete` | Delete a variable | Yes | Deletes a global variable, for example the Skeleton template's demo variables |

Each character edit is one step of undo. Turning a character of another kind into a layered one, or a layered one back into poses, discards its looks, so `character_upsert`, `character_layered_set` and `character_layers_import` refuse it until the call passes `confirmSwitch: true`. The refusal lists the story rows that chose one of the looks. Live2D and Spine characters are read only; they are set up in Studio's character editor.

## Translation and voice

| Tool | Shown in Studio as | Changes the project | Purpose |
| --- | --- | --- | --- |
| `localization_status` | Translation progress | No | How far each target language is translated, by status and by origin, and with one language each scene's lines left to do |
| `localization_list` | List text to translate | No | Lists the translation units of one language in reading order, a page at a time, each with its source, translation, status and `rev` |
| `localization_set` | Write translations | Yes | Writes translations of one language, up to 1000 per call, in one step of undo |
| `voice_status` | Voice-over progress | No | The voice languages, the recording file-name rule, whether choice options are voiced, and per language and character how many lines have a take |
| `voice_list` | List voiced lines | No | Lists the voiced lines of one voice language in story order, each with its expected file name, linked take and status |
| `voice_link` | Link voice takes | Yes | Links audio assets to voiced lines one by one, unlinks them, or approves a take, in one step of undo |
| `voice_auto_link` | Link takes by name | Yes | Links every voiced line to the audio asset named after it by the recording rule, in one step of undo |
| `voice_settings_set` | Change voice settings | Yes | Sets the voice languages, the recording file-name rule and whether choice options are voiced |

A translation unit is a story line, a character, scene, ending or `/rename` name, a word on a page or component, a named translation key, or text a plugin offers. One id runs through all of them, so they are listed and written the same way, and a story line's id is also its voice line.

- **Statuses.** A translation is `missing`, `machine`, `translated`, `reviewed` or `stale`, the last when the source changed after it was translated. `localization_set` writes `machine` unless told otherwise; the translation table shows it as **Machine**. A take is `missing`, `linked`, `approved` or `stale`; the voice table shows a linked take as **Voiced** and a stale one as **Outdated**.
- **Markup.** A unit's source shows the values the game fills in as `{0}` and styled words and pauses as run tags, `‹1›word‹/1›` and `‹2/›`. A translation that loses one, a `{name}` placeholder or a line break is written with a warning for that unit.
- **Revisions.** Each unit carries a `rev`. A unit whose source changed since the agent listed it is skipped and returned with its new source.
- **The recording rule.** The default is `{scene}_{index}_{character}`; it also takes `{locale}` and `{unit}`. Names are compared ignoring case, spaces, punctuation and folders, against each asset's library name. A name that several assets or several lines share is returned as ambiguous, never guessed at.

The game's text languages are set with `project_settings_set`, its voice languages with `voice_settings_set`. `localization_set`, `voice_link` and `voice_auto_link` take `dryRun: true`, which checks and writes nothing, as do `character_layered_set` and `character_layers_import`.

## Plugin tools [#plugin-tools]

A plugin can offer agents tools of its own. They are listed beside Studio's tools, under a name made of the plugin id and the tool's name, with every `.` and `-` turned into `_` and the two parts joined by `__`. The Gallery's `narraleaf.gallery.add_entries` is offered as `narraleaf_gallery__add_entries`.

A plugin's tools are offered only while a project that loads the plugin is open, and the plugin is enabled there. When that changes, clients that keep Studio's notification stream open are told the list changed; others see the new list the next time they ask for it. `agent_status` names the plugin tools each open project offers.

A plugin tool passes the same checks as Studio's own, and its **Changes the project** flag means the same. **Settings → Agent access → Plugin tools** switches off all the tools of one plugin. Plugin authors: see [Agent tools](/docs/studio/plugin/studio/agent-tools).

A plugin may also ship a guide chapter, read with `agent_guide` and `plugin:<plugin id>`.

### Gallery

The built-in [Gallery](/docs/studio/blueprint/nodes/built-in-plugins/gallery) plugin fills the Extra page. Its guide chapter is `plugin:narraleaf.gallery`. The titles are the plugin's own and are not translated.

| Tool | Shown in Studio as | Changes the project | Purpose |
| --- | --- | --- | --- |
| `narraleaf_gallery__list` | Read the gallery | No | The Extra page's catalogue: groups, entries of every kind (cg, scene, music, voice) with their ids and variants, and the locked look |
| `narraleaf_gallery__add_entries` | Add gallery entries | Yes | Adds entries to the Extra page in one undo step |
| `narraleaf_gallery__update_entries` | Edit gallery entries | Yes | Edits existing entries in one undo step |
| `narraleaf_gallery__remove_entries` | Remove gallery entries | Yes | Removes entries (by id) from the gallery in one undo step |
| `narraleaf_gallery__set_groups` | Set gallery groups | Yes | Replaces the gallery's group list, in order, in one undo step |
| `narraleaf_gallery__set_settings` | Set the gallery's locked look | Yes | Sets what a locked entry looks like on the Extra page, in one undo step |

## Text formats

An agent reads and writes the project's content as text, through three formats:

| Format | Holds | Read with | Write with |
| --- | --- | --- | --- |
| `.story` | One scene: its header, its rows and its branches | `story_show` | `story_apply` |
| `.ui` | A page, Game UI or component: its elements and their props | `ui_show` | `ui_apply`, `ui_patch` |
| `.bp` | The blueprints of one owner | `blueprint_show` | `blueprint_apply` |

Each read returns a `revision`, and a write that carries it back is refused with `stale_revision` if the content changed in between. `story_apply`, `ui_apply`, `ui_patch` and `blueprint_apply` take `dryRun: true`, which checks the text and writes nothing.

The formats are described in the guide's `story-format`, `ui-format` and `blueprint-format` chapters. Which commands, widgets and nodes exist is answered by the catalogue tools, `story_commands`, `story_command`, `story_targets`, `ui_widgets`, `ui_widget`, `ui_usage`, `blueprint_nodes` and `blueprint_node`, which read it from the Studio that is running. An agent should ask them rather than rely on memory.

## Guide

`agent_guide` takes one `chapter`. Without one, it lists the chapters there are:

| Chapter | Covers |
| --- | --- |
| `workflow` | The order of work, from the brief to the build |
| `story-format` | The `.story` format |
| `ui-format` | The `.ui` format |
| `blueprint-format` | The `.bp` format |
| `ui-design` | Designing visual-novel interfaces |
| `script-adaptation` | Turning a script into scenes |
| `layered-sprites` | Layered characters: axes, layers, building one from files or a PSD |
| `verify-and-ship` | Checks, tests, play-testing and building |
| `localization-and-voice` | Translating the game and linking voice recordings |
| `troubleshooting` | Refusals and what to do about them |
| `plugin:<plugin id>` | The chapter an enabled plugin ships, such as `plugin:narraleaf.gallery` |

The same chapters are MCP resources at `narraleaf://guide/<chapter>`, and a plugin's at `narraleaf://guide/plugin/<plugin id>`; the `make_game` prompt starts the `workflow` with an optional `brief`.
