---
title: エージェントを接続する
description: Studio でエージェント連携をオンにし、MCP クライアントに Studio を追加して、エージェントにスキルを渡す
---

接続に必要なのは 3 つです。Studio でエージェント連携をオンにすること、エンドポイントをエージェントの設定に追加すること、エージェントがスキルを探す場所にスキルを置くことです。

## エージェント連携をオンにする

<Steps>

<Step>

### 設定を開く

**設定 → エージェント連携**を開きます。プロジェクトのウィンドウでは、メニューバーの**エージェント**メニューにある**エージェント連携の設定…** から同じ場所に移動できます。

</Step>

<Step>

### エージェントの接続を許可する

**エージェントの接続を許可**をオンにします。**エンドポイントのアドレス**にはエンドポイントが表示されます。ポートを変えていなければ `http://127.0.0.1:47219/mcp` です。提供が始まると**待ち受け中**と表示されます。

**エンドポイントのポート**の変更はすぐに反映され、1024 から 65535 まで指定できます。Studio はこのポートでだけエンドポイントを提供します。ほかのプログラムが使用しているか、システムが予約しているときはエンドポイントは起動せず、**エンドポイントのアドレス**に **起動できなかった：ポート 47219 は他のプログラムが使用している** のように表示され、プロジェクトのウィンドウの**エージェント**メニューにも同じ行が表示されます。別のポートを入力し、それ以前に設定したエージェントには設定をコピーし直してください。

既定のポートは Studio 1.6.2 で 54080 から 47219 に変わりました。それより前のリリースから持ち越し、ポートを手で変えていない設定は、一度だけ新しいポートへ移されます。そのとき**エンドポイントのアドレス**には **エンドポイントのポートが 47219 に変わった。それ以前に設定したクライアントには、接続設定をコピーし直す** と表示され、設定を一度コピーすると消えます。

</Step>

<Step>

### 変更を許可する

エージェントに編集させるときは、**エージェントによるプロジェクトの変更を許可**をオンにします。既定ではオフです。オフの間、エージェントはプロジェクトを読み取れますが、変更はすべて拒否されます。

メニューバーの**エージェント → エージェントによるプロジェクトの変更を許可**からオンにする場合は、先に Studio のウィンドウで確認を求められます。

その下の**エージェントにフルアクセスを許可**は既定でオフで、ゲーム作りには必要ありません。オンにすると、エージェントはプロジェクトを変更でき、確認なしで任意のフォルダーを読み取れるようになります。オンにする前に[フルアクセス](/ja/docs/studio/agent/security#full-access)を読んでください。

</Step>

<Step>

### 素材のあるフォルダーを追加する

**エージェントが読み込めるフォルダー**の**フォルダーを追加…** で、エージェントに読み込ませる画像や音声のあるフォルダーを追加します。プロジェクト内のファイルはいつでも読み込めます。

この手順は省略できます。エージェントがほかのフォルダーのファイルを必要とすると、Studio が**エージェントにフォルダーの読み取りを許可する？**というウィンドウで確認し、許可したフォルダーはこの一覧に追加されます。[プロジェクト外のフォルダー](/ja/docs/studio/agent/security#folders)を参照してください。

</Step>

<Step>

### アプリを選んで設定をコピーする

**エージェントアプリ**で使っているアプリを選びます。Claude Code、Claude Desktop、Codex、opencode、Cursor、Gemini CLI、**その他**のいずれかです。下の**接続設定**と **Agent Skill** は、選んだアプリのものになります。

**接続設定**は、エンドポイントのアドレスとアクセストークンを入れた、そのまま貼り付けられる設定を示し、どこに置くのかも書かれています。Claude Code は**ターミナルで実行**するコマンド、ほかのアプリは**… に追記**、**その他**は **Streamable HTTP。クライアントの MCP 設定にこのアドレスとヘッダーを入力** です。**エージェントの接続を許可**がオフの間は、**「エージェントの接続を許可」をオンにすると使える**と表示されます。

**Agent Skill** の欄は、そのアプリがスキルを読む場所にスキルをインストールします。[スキルを入れる](#skill)を参照してください。

プロジェクトのウィンドウの**エージェント → 接続設定をコピー**には 6 つの形式があります。Claude Code、Claude Desktop、Codex、opencode、Gemini CLI、JSON です。

**エンドポイントのアドレス**と**アクセストークン**には、それぞれ**アドレスをコピー**と**トークンをコピー**のボタンがあります。トークンそのものは末尾 4 文字しか表示されず、全体が表示されることはありません。**アクセストークンを再生成 → 再生成**のあとは、古いトークンで設定したクライアントは接続できなくなります。

</Step>

</Steps>

## エージェントメニュー

プロジェクトのウィンドウのメニューバーには**エージェント**メニューがあります。

| 項目 | 働き |
| --- | --- |
| 状態の行 | 接続中のクライアントとその状態。たとえば**エージェント：Claude Code · 作業中**。クリックはできません |
| **エージェントを一時停止** / **エージェントを再開** | 再開するまで、このプロジェクトに対するエージェントの変更をすべて拒否します |
| **エージェントの編集を追う** | 変更が反映されたエディタを開きます |
| **エージェントログ** | このプロジェクトでのすべての呼び出しのログを開きます |
| **エージェント連携を有効にする** | **エージェントの接続を許可**と同じスイッチです |
| **エージェントによるプロジェクトの変更を許可** | 設定にある同じ名前のスイッチで、オンにするときに確認があります。フルアクセスがオンの間はオンと表示され、切り替えられません |
| **エージェントにフルアクセスを許可** | 設定にある同じ名前のスイッチで、オンにするときに確認があります |
| **接続設定をコピー** | Claude Code、Claude Desktop、Codex、opencode、Gemini CLI、JSON の 6 形式 |
| **Agent Skill を書き出す…** | スキルのフォルダーを、選んだ場所に書き出します |
| **エージェント連携の設定…** | **設定 → エージェント連携**を開きます |

一時停止、追従、ログについては[エージェントでゲームを作る](/ja/docs/studio/agent/make-a-game#watching)で説明しています。

## エージェントに Studio を追加する

以下のクライアントはいずれも、サーバーを `narraleaf` という名前で登録します。例の `<PORT>` と `<TOKEN>` には、**エンドポイントのアドレス**と**アクセストークン**の値を入れます。

### Claude Code

**設定をコピー → Claude Code** でコマンドが得られます。ターミナルで一度だけ実行します。

```sh
claude mcp add --scope user --transport http narraleaf http://127.0.0.1:<PORT>/mcp --header "Authorization: Bearer <TOKEN>"
```

`--scope user` を付けると、サーバーはすべてのフォルダーで使えるようになり、ターミナルがどのフォルダーにあってもゲーム制作を頼めます。付けない場合、サーバーはコマンドを実行したフォルダーにしか存在しません。`claude mcp list`、または Claude Code の中で `/mcp` を実行して確認します。

ゲームを 1 本作るには 100 回以上のツール呼び出しが必要で、Claude Code は既定で呼び出しのたびに確認を求めます。最初の確認で narraleaf のツールに **Yes, and don't ask again** を選ぶか、`~/.claude/settings.json` で事前に許可します。

```json
{ "permissions": { "allow": ["mcp__narraleaf"] } }
```

エージェントが何かを変更できるかどうかは、引き続き Studio のスイッチが決めます。一時停止も同じように効きます。

### Claude Desktop

Claude Desktop は設定ファイルからローカルのプログラムを起動します。Studio 自身がそのプログラムになれます。`--mcp-stdio` を付けて起動された Studio はウィンドウを開かず、接続を起動中の Studio に転送します。

**設定をコピー → stdio** で、Studio のパスが入ったエントリーが得られます。

```json
{
  "mcpServers": {
    "narraleaf": {
      "command": "/Applications/NarraLeaf Studio.app/Contents/MacOS/NarraLeaf Studio",
      "args": ["--mcp-stdio"]
    }
  }
}
```

パスは Studio 自身の実行ファイルです。

- macOS: アプリケーションフォルダーに置いた場合は `/Applications/NarraLeaf Studio.app/Contents/MacOS/NarraLeaf Studio`
- Windows: インストール先フォルダーの `NarraLeaf Studio.exe`。JSON ではバックスラッシュを 2 つずつ書きます。コピーしたエントリーはすでにそうなっています
- Linux: AppImage ファイルそのもの

このエントリーを `claude_desktop_config.json`（Claude Desktop の **Settings → Developer → Edit Config**）にマージし、Claude Desktop を再起動します。

このエントリーにトークンは含まれません。ブリッジはアドレスとトークンを毎回 Studio の設定から読み取るので、トークンを変更したりポートを変えたりしても使い続けられます。Claude Desktop は起動のたびに設定されたすべてのサーバーへ接続しますが、接続だけで Studio が起動することはありません。`initialize`、`ping`、ツール・リソース・プロンプトの一覧は、Studio が動いていなくてもブリッジが自分で返します。Studio を起動するのは最初の実際のツール呼び出しで、エンドポイントが使えるようになるまで最大 1 分待ちます（Studio 1.6.3 以降）。エージェント連携がオフの場合は、どのリクエストにも、オンにする場所を示すメッセージを返します。

ブリッジが合わない場合は、サードパーティの npm パッケージ `mcp-remote`（Node.js が必要）でも同じことができます。

```json
{
  "mcpServers": {
    "narraleaf": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://127.0.0.1:<PORT>/mcp", "--header", "Authorization:${NARRALEAF_AUTH}"],
      "env": { "NARRALEAF_AUTH": "Bearer <TOKEN>" }
    }
  }
}
```

URL でカスタムコネクターを追加できる Claude Desktop なら、そこにアドレスとトークンを入れることもできます。

### opencode

**設定をコピー → opencode** でブロックが得られます。作業フォルダーの `opencode.json`、またはすべてのフォルダーで使うなら `~/.config/opencode/opencode.json` にマージします。

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "narraleaf": {
      "type": "remote",
      "url": "http://127.0.0.1:<PORT>/mcp",
      "enabled": true,
      "headers": { "Authorization": "Bearer <TOKEN>" }
    }
  }
}
```

`opencode mcp list` で確認します。

### Codex CLI

`~/.codex/config.toml` に追加します。

```toml
[mcp_servers.narraleaf]
url = "http://127.0.0.1:<PORT>/mcp"
http_headers = { "Authorization" = "Bearer <TOKEN>" }
```

トークンをファイルに書きたくない場合は、シェルで `NARRALEAF_TOKEN` として export し、`http_headers` の代わりに `bearer_token_env_var = "NARRALEAF_TOKEN"` と書きます。`codex mcp list`、または Codex の中で `/mcp` を実行して確認します。

### Cursor

作業フォルダーの `.cursor/mcp.json`、またはすべてのフォルダーで使うなら `~/.cursor/mcp.json` として保存し、**Cursor Settings → MCP** でサーバーを有効にします。

```json
{
  "mcpServers": {
    "narraleaf": {
      "url": "http://127.0.0.1:<PORT>/mcp",
      "headers": { "Authorization": "Bearer <TOKEN>" }
    }
  }
}
```

### Gemini CLI

`~/.gemini/settings.json`、または作業フォルダーの `.gemini/settings.json` にマージします。

```json
{
  "mcpServers": {
    "narraleaf": {
      "httpUrl": "http://127.0.0.1:<PORT>/mcp",
      "headers": { "Authorization": "Bearer <TOKEN>" }
    }
  },
  "context": { "fileName": ["AGENTS.md", "GEMINI.md"] }
}
```

`context.fileName` によって Gemini CLI は `AGENTS.md` を読み、そこからスキルにたどり着きます。Gemini CLI の中で `/mcp` を実行して確認します。

### その他のクライアント

| 設定 | 値 |
| --- | --- |
| トランスポート | Streamable HTTP |
| URL | `http://127.0.0.1:<PORT>/mcp` |
| ヘッダー | `Authorization: Bearer <TOKEN>` |

ローカルのプログラムしか起動できないクライアントでは、Claude Desktop のエントリーと同じように `--mcp-stdio` を付けて Studio を起動するか、`mcp-remote` などのブリッジを使います。

## スキルを入れる [#skill]

いちばん簡単なのは Studio に入れてもらう方法です。**設定 → エージェント連携 → エージェントアプリ**で使うアプリを選ぶと、**Agent Skill** の欄に **Agent Skill をインストール** があり、**… にインストールする。ほかのスキルはそのまま残る** と書かれています。入れたあとはボタンが**再インストール**になり、隣に **… にインストール済み** と表示されます。Studio は、各アプリがスキルを読む場所に入れます。

| アプリ | インストール先 |
| --- | --- |
| Claude Code | `~/.claude/skills/` |
| Codex、opencode、Cursor、Gemini CLI | `~/.agents/skills/`。4 つが共通で読む 1 つの場所です |
| Claude Desktop | **zip を保存…** で zip を書き出し、Claude の **Settings → Capabilities → Skills** でアップロードします |
| その他 | インストールは不要です。これらのアプリは Studio の MCP サーバーから同じガイドを読みます。[スキルがない場合](#no-skill)を参照してください |

Studio を更新したら**再インストール**を一度押せば、スキルはその Studio のものになります。入れる場所にある `SKILL.md` がその Studio のものと違う場合、古い版でも作者自身の変更でも、Studio は置き換える前に自分のウィンドウで確認します。初回起動時のセットアップのエージェント連携の画面にも、同じ手順があります。

すでに動いているエージェントのセッションは、読み込んだテキストをそのまま使います。入れ直したあとは、新しいセッションを始めてください。

### 自分で入れる

**エージェント → Agent Skill を書き出す…** は、選んだフォルダーに `NarraLeaf-Skills` という名前のフォルダーを書き出します。同じ名前のファイルは置き換えられ、フォルダー内のほかのファイルはそのまま残ります。

<Files>
  <Folder name="NarraLeaf-Skills" defaultOpen>
    <File name="README.md" />
    <File name="AGENTS.md" />
    <Folder name="mcp-configs" />
    <Folder name="narraleaf-make-game" />
    <Folder name="narraleaf-port-renpy" />
  </Folder>
</Files>

スキルは `narraleaf-make-game` フォルダーです。`SKILL.md` だけでなくフォルダーごと、上の表の場所にコピーします。`~/.agents/skills/` は Codex、opencode、Cursor、Gemini CLI が共通で読む場所です。このうちいくつかは自分専用の場所（`~/.config/opencode/skills/`、`~/.cursor/skills/`、`~/.gemini/skills/`）も持ち、Cursor と opencode は `~/.claude/skills/` も読むので、両方に置くと同じスキルが 2 つ並ぶことがあります。1 つのプロジェクトだけに入れるときは、そのプロジェクトの `.claude/skills/` か `.agents/skills/` に置きます。

`AGENTS.md` を読むエージェント（opencode、Codex、Cursor、上記の設定をした Gemini CLI など）は、`NarraLeaf-Skills` の中で起動すれば自分でスキルを見つけます。

Node.js があれば、サードパーティの [`skills`](https://github.com/vercel-labs/skills) コマンドでリポジトリから直接入れられます。`npx skills add NarraLeaf/Skills -g` の `-g` は現在のユーザーに入れるという意味で、あとから `npx skills update` で新しい版を取得できます。

Ren'Py のゲームを移植するには `narraleaf-port-renpy` も必要です。Studio が書き出すフォルダーにも 1 部入っていますが、このスキルは Ren2Leaf ウィザードとともに [MewBaka/Ren2Leaf](https://github.com/MewBaka/Ren2Leaf) で公開されており、そちらのほうが新しいことがあります。入れ方は `narraleaf-make-game` と同じで、両方を入れます。サーバーはこれをガイドとして提供しないため、エージェントはフォルダーから読み取ります。[Ren'Py のゲームを移植する](/ja/docs/studio/agent/make-a-game#renpy)を参照してください。

### スキルがない場合 [#no-skill]

サーバー自身がガイドを提供するので、スキルを入れていないエージェントもガイドを受け取れます。

- **`make_game` プロンプト**は、MCP のプロンプトを表示するクライアントで作業全体を始めます。多くは `/make_game` のようなスラッシュコマンドで、Claude Code では `/mcp__narraleaf__make_game` です。
- **`agent_guide` ツール**は任意の章を返します。`workflow`、`story-format`、`ui-format`、`blueprint-format`、`ui-design`、`script-adaptation`、`layered-sprites`、`verify-and-ship`、`localization-and-voice`、`troubleshooting` があります。
- 同じ章は MCP リソース `narraleaf://guide/<chapter>` としても提供されます。

どの MCP クライアントでも、最初のメッセージとして次の文が使えます。

> Use the NarraLeaf Studio tools. Call agent_guide with chapter "workflow" and follow it to make my game.
