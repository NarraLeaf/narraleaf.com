---
title: "Example: affection and multiple endings"
description: A saved variable records affection, choices change it, a Blueprint Value shows it on the dialogue box, conditions and a graph condition pick the ending, and the title page counts the endings reached.
---

This page builds an affection system on a project made from the **Skeleton** template. The player's choices raise Narra's affection, and hearts on the right of the dialogue box show its current value. When affection is high enough, Narra asks one more question; the story then ends in one of three endings, decided by affection and an earlier choice. The title page shows how many endings have been reached.

| Part | Where | What it does here |
| --- | --- | --- |
| Saved variable `Affection` | **Variables** panel | Holds affection; saved and loaded with the game |
| `/inc`, `/if`, `/ending` | Scenes | Raise affection, branch on it, mark the endings |
| Blueprint Value | A text in the Game UI **Dialogue** | Reads affection and shows it as hearts |
| Graph condition | The ending branch | Checks affection and `Honest` together in a blueprint |
| `Get Endings` | A text on the page **Title** | Shows the number of endings reached |

The three endings:

| Ending | Condition |
| --- | --- |
| Festival for two | Affection at least 35, and "Something honest." chosen in the clubroom |
| Same time tomorrow | Affection at least 20 |
| The empty seat | Anything else |

## Before you start

Create a project from the **Skeleton** template, as described in [Getting started](/docs/studio/getting-started). The Skeleton has three scenes in order: **The corridor**, **The clubroom** and **Last light**. The menu in **The clubroom** writes the choice into the saved variable `Honest`, **Last light** shows a different line depending on `Honest`, and the story ends with the ending **Same time tomorrow**.

The steps below declare the variable first, then change the three scenes in turn, and finally change the Game UI **Dialogue** and the page **Title**.

## 1. Declare the variable

Open **Variables** in the right sidebar and click **Add** next to **Saved variables**. Name the new variable `Affection`, set its type to **Number** and leave the default at `0`.

A saved variable belongs to the whole project, and every scene and every blueprint can read and write it. Its value goes into the save, comes back when the save is loaded, and returns to the default when a new game starts. The other scopes are described in [Variables](/docs/studio/blueprint/variables).

## 2. Let choices change affection

<Steps>
<Step>

### The corridor

After Narra's line "One and a half. You keep leaving before it gets dark.", add a row, type `/menu` and press Enter twice. Studio inserts a menu with its first option. Click **Add option** on the menu row to add a second option, double-click each option to write its text, then click **Add action inside** on an option to write the rows that follow it:

| Option | Rows inside the option |
| --- | --- |
| I'll stay till the end today. | Narra: "...I'm holding you to that."<br />`/inc Affection 10` |
| The club isn't going anywhere. | Narra: "The club isn't. People are." |

</Step>
<Step>

### The clubroom

Each of the two options in the menu **What do we make?** holds a `/set Honest …` row. After each of those rows add:

| Option | Row to add |
| --- | --- |
| Something honest. | `/inc Affection 20` |
| Something people will actually come to. | `/inc Affection 10` |

</Step>
</Steps>

Type `/inc Affection 20` and press Enter, and the row reads **inc Affection 20**. Without a number `/inc` adds 1, and `/dec` subtracts; `/set Affection Affection + 20` does the same.

## 3. Show affection on the dialogue box

The right of the dialogue box shows five hearts, and every 10 points of affection fills one.

<Steps>
<Step>

### Add a text

Choose **UI** in the activity bar on the left, set **Interface Type** to **Game UI** and open **Dialogue**. Drag a **Text** from the toolbar under the canvas to the right of the dialogue band, name it `Affection` and align its text to the right. The Skeleton leaves room to the right of the nametag: position X 1420, Y 754, size 320 × 46.

</Step>
<Step>

### Hand the text to a Blueprint Value

With the text selected, go to **Content** in the properties panel and switch **Text** from **Direct** to **Blueprint Value**. Studio creates a Blueprint Value for it, and the old text becomes the **Sample text**, which only the editor shows. Click **Open Blueprint Value**.

<Figure
    src="/static/img/docs/studio/en/affection-meter-text.webp"
    alt="The Game UI Dialogue open in the UI editor; the selected text Affection takes its text from a Blueprint Value in the properties panel, and its sample text is two filled and three empty hearts"
/>

</Step>
<Step>

### Build the graph

The Blueprint Value already has `Init` connected to `Return Value`, with a `String` supplying the old text. Delete the `String`, then add and connect the nodes below:

| Node | Setting | Connects to |
| --- | --- | --- |
| `Init` | | Exec to `Get Saved Var` |
| `Get Saved Var` | **Saved variable**: `Affection` | Exec to `Return Value`; **Value** to **A** of `÷` |
| `÷` | **B**: `10` | **Result** to **Number** of `Floor` |
| `Floor` | | **Result** to **Count** of `Repeat` |
| `Repeat` | **Value**: `♥` | **Result** to **Value** of `Pad End` |
| `Pad End` | **Length**: `5`, **Pad**: `♡` | **Result** to **Value** of `Return Value` |

<Figure
    src="/static/img/docs/studio/en/affection-meter-graph.webp"
    alt="The Blueprint Value for Affection: Init into Get Saved Var into Return Value, with the value passing through divide by 10, Floor, Repeat and Pad End"
/>

</Step>
</Steps>

The text is worked out again each time the saved variable it reads is written: the moment the story runs `/inc`, when a save is loaded, and when a new game starts, the hearts on the dialogue box change with it.

<Figure
    src="/static/img/docs/studio/en/affection-stage.webp"
    alt="Dev Mode showing the two options after Narra's question, with three filled and two empty hearts on the right of the dialogue box"

## 4. Branch on affection

In **Last light**, add a row after the condition on `Honest` and before Narra's line "Same time tomorrow. Don't be late.", type `/if Affection >= 20` and press Enter. Under **If**, add:

- Narra: "On the way back... want to walk to the station together?"
- A menu. Inside the option "Sure.", Narra: "It's a deal." and `/inc Affection 15`; inside the option "Not today.", Narra: "...Right. Sure."

With affection below 20 the story skips the whole branch. This condition has no **Else**, so when it does not hold the next row runs.

The condition of an `/if` is an expression, which can use comparisons, `&&`, `||` and `!`. In the properties panel the condition can also be switched to **Variable**, which picks the variable and the comparison from dropdowns.

## 5. Three endings

Delete the two lines of narration and the ending **Same time tomorrow** at the end of **Last light**. At the end of the scene type `/if Affection >= 35 && Honest` and press Enter, then click **Else if** and **Else** on the condition row to add the other two branches:

| Branch | Condition | Rows in the branch |
| --- | --- | --- |
| If | `Affection >= 35 && Honest` | Narration "On festival day, the first one through the clubroom door was Narra."<br />`/ending Festival for two` |
| Else if | `Affection >= 20` | `/ending Same time tomorrow` |
| Else | | Narration "The next day, I didn't go to the club."<br />`/ending The empty seat` |

`/ending` ends the story on that row and records which ending the player reached.

### Work out the condition in a blueprint

A blueprint can work out the condition instead. The steps below turn the first branch into a graph condition that gives the same result as the expression `Affection >= 35 && Honest`.

<Steps>
<Step>

### Switch to Graph

Select the **If** row of the first branch, switch the condition in the properties panel from **Expression** to **Graph**, then click the preview card below it. Studio creates the condition blueprint and opens it in a **Condition** tab. The row's condition now reads **Graph condition**.

<Figure
    src="/static/img/docs/studio/en/affection-endings.webp"
    alt="The three branches at the end of Last light, each ending in an ending row; the first branch's condition reads Graph condition, and the properties panel shows the condition type Graph"
/>

</Step>
<Step>

### Build the graph

The graph already has `On Call` connected to `Return Value`, with a `Boolean` supplying the value. Delete the `Boolean` and add the nodes below:

| Node | Setting | Connects to |
| --- | --- | --- |
| `On Call` | | Exec to the first `Get Saved Var` |
| `Get Saved Var` | **Saved variable**: `Affection` | Exec to the second `Get Saved Var`; **Value** to **A** of `Greater Than Or Equal` |
| `Get Saved Var` | **Saved variable**: `Honest` | Exec to `Return Value`; **Value** to **A** of `And` |
| `Greater Than Or Equal` | **B**: `35` | **Result** to **B** of `And` |
| `And` | | **Result** to **Value** of `Return Value` |

<Figure
    src="/static/img/docs/studio/en/affection-condition.webp"
    alt="The condition blueprint: On Call into two Get Saved Var nodes into Return Value; Affection goes through Greater Than Or Equal 35 and meets Honest in an And node"
/>

</Step>
</Steps>

The graph runs each time the story reaches this branch, and the branch is taken when the value handed to `Return Value` is true. A graph condition cannot use nodes that wait, such as `Get Persistent`; a calculation an expression cannot write, such as `Random Integer`, can go in a graph condition.

The live preview treats a graph condition as false. Check ending branches in Dev Mode.

## 6. Return to the title after an ending

Open **Project** → **App**, expand **main** under **Build variants**, and set **Page shown when the story ends** to **Title**. An ending row shows this page once the story ends. A single ending row can pick a different page under **Page shown afterwards** in the properties panel.

## 7. Show the endings reached on the title page

The endings a player has reached are recorded outside the save: loading a save, starting a new game or restarting the game does not clear them.

Open the page **Title**, put a **Text** under the title rule and name it `Endings`. Switch its **Text** to **Blueprint Value**, open it and build the graph below:

| Node | Setting | Connects to |
| --- | --- | --- |
| `Init` | | Exec to `Return Value` |
| `Get Endings` | **Story**: `Skeleton` | **Endings** to **Array** of `Array Filter By Key` |
| `Boolean` | True | To **Value** of `Array Filter By Key` |
| `Array Filter By Key` | **Key**: `isReached` | **Array** to `Array Length` |
| `Array Length` | | **Length** to **Item 1** of `Make Array` |
| `Get Endings` | **Story**: `Skeleton` | **Endings** to the second `Array Length` |
| `Array Length` | | **Length** to **Item 2** of `Make Array` |
| `Make Array` | Two items | **Array** to **Values** of `Format` |
| `Format` | **Template**: `Endings reached {0} / {1}` | **Result** to **Value** of `Return Value` |

`Get Endings` lists every ending row in the story, and each entry's `isReached` says whether the player has reached it. The first `Get Endings` keeps the endings reached; the second counts them all.

<Figure
    src="/static/img/docs/studio/en/affection-endings-graph.webp"
    alt="The Blueprint Value for Endings: two Get Endings nodes, one through Array Filter By Key and Array Length, the other through Array Length alone; both numbers go into Make Array and Format writes them into one line"
/>

The template is text written in the graph and does not change with the game's language. In a project with more than one language, supply the template with `Translation Key Text`.

## Play and check

- Press **F5** to run the project in Dev Mode. Click **Play from this row** on a row to start from that row.
- The debug button at the bottom left of Dev Mode → **Story** → **Variables** lists the current values of the saved variables and can change them. Set `Affection` to 40, turn `Honest` on, then play to the end to check **Festival for two**.
- The arrow next to the Dev Mode button → **Reset player data** → **Dev Mode** clears every save and the endings record of Dev Mode. The title page goes back to `Endings reached 0 / 3`.
- Click **Open Scene Flow** in the **Story** panel and pick `Affection` in the variable list. Each scene shows the range affection can have on arrival; **Show branches** shows what each option adds and which branches end the story.
- When a condition asks for more than any route can reach, the **Problems** panel reports **Condition no path can satisfy** and gives the range of affection at that point.
