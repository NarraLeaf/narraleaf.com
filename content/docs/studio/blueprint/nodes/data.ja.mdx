Data は、ブループリントが計算に使う値を保持するカテゴリです。定数が必要なとき、値が想定と違う型で届いたとき、あるいは文字列・配列・JSON ドキュメントを分解する必要があるときに使います。ここにあるノードのほとんどは実行ピンを持ちません——Data ノードは、その出力に配線された側から読み取られます。`Memo`だけが例外であり、それについてはこのページの末尾で説明します。

## 値の型 [#value-types]

以下のピンには10種類の`valueType`が現れます。

| `valueType` | 内容 | 生成元 |
| --- | --- | --- |
| `string` | テキスト。 | `String`、およびすべての文字列ノード。 |
| `integer` | 整数。 | `Integer`、および各種の長さ・添字・件数。 |
| `float` | 数値。 | `Float`、`To Float`、`Parse Float`。 |
| `boolean` | 真または偽。 | `Boolean`、およびすべての型判定と文字列判定。 |
| `json` | 任意の JSON 値——object、array、string、number、boolean、`null`のいずれか。 | `JSON`、`Parse JSON`、`Get JSON Field`、`Make Object`。 |
| `array` | JSON 配列。ただし独立した型として扱われます。 | `Make Array`、配列を返す`Array …`ノード群、`Object Keys`、`Object Values`。 |
| `any` | 何であってもよい値。 | `Memo`、`Get Item Field`、およびカードの選択に応じて形状が決まるプロパティ読み取り。 |
| `RGBAColor` | `{ r, g, b, a }`。 | `Color`。 |
| `Vector2D` | `{ x, y }`。 | `Vector2D`、`Make Vector2D`、`Rect Center`、`Get Center`。 |
| `Rect` | `{ x, y, width, height }`。 | `Rect`、`Make Rect`、`Get Bounds`、`Get Measured Rect`。 |

2つのデータピン間の接続は、型が完全に一致する場合、または次のいずれかが成り立つ場合に許可されます。

| 元 | 先 | 理由 |
| --- | --- | --- |
| `integer` | `float` | すべての整数は浮動小数点数です。 |
| `integer`、`float` | `string` | 入力を読み取る際に、数値はテキストへ変換されます。これは値を書き換える唯一の暗黙変換です——それ以外の許可された接続はすべて値をそのまま通します。 |
| `array` | `json` | 配列は JSON 値そのものです。 |
| `Rect` | `json` | 構造化された値についての規則ではなく、移行のために許されている経路です——下記参照。 |
| `any` | 任意の型 | `any`はどちらの方向にも一致します。 |
| 任意の型 | `any` | |

他のカテゴリの型も同じ形でのみ広がります——`element`はどの`element:nl.…`ピンにも接続でき、その逆方向にも接続できます。`ImageAsset`と`string`はどちらも`ImageAsset|null`入力に届きます。

それ以外はすべて拒否されます。作者が動くはずだと思い込みがちな逆方向の接続も含めてです。

- **`json` → `array`、`json` → `Rect`。** どの拡張規則も一方向にしか成り立ちません。任意のオブジェクトが矩形であるとは限りません。
- **`float` → `integer`。** `To Integer`を挟んでください。これはゼロ方向に切り捨てます。
- **`string` → `integer`または`float`。** `Parse Int`、`Parse Float`、`To Integer`、`To Float`のいずれかを挟んでください。
- **`boolean` → `string`、`json` → `string`。** テキストへ暗黙変換されるのは数値だけです。`To String`または`Stringify JSON`を挟んでください。
- **`string`、`integer`、`float`、`boolean` → `json`。** `json`入力に暗黙に届く型は`array`と`Rect`だけです。`To JSON`を挟んでください。
- **`RGBAColor` → `json`、`Vector2D` → `json`。** これらはそれぞれ独立した構造化型であり、JSON ドキュメントではありません。`Break Vector2D`で分解するか、`Make Object`でドキュメントを組み立ててください。

<Callout type="info">
`Rect` → `json`は、`Rect`が独立した型になる前に書かれたグラフのために存在します。`Rect`が型になるまでは、`Rect`リテラルと`Get Bounds`はどちらも`json`を公開していました。そのため当時作成された矩形は今も`Get JSON Field`へ渡せて動作し続けます。`Vector2D`は`json`ピンであったことが一度もなく、狭いままです。
</Callout>

<Callout type="info">
`array`は`json`入力に渡せるが、逆方向は決してできません。たまたま配列を保持している`json`の値——`Split`の結果、`Parse JSON`、`Get JSON Field`——は、`Array Length`や List の`Set Items`のような`array`入力には接続できません。[Flow](/ja/docs/studio/blueprint/nodes/flow)の`For Each`は`json`を受け取るため、それを使った反復は引き続き機能します。`Array …`ノード群はそうはいきません。
</Callout>

## 規約

- **このページのノードは、1つを除いてすべて純粋です。** 接続できる実行ピンがないため、Data ノードは実行経路の上に置くことができません。その出力は、消費側が読み取るときに計算され、次の読み取りで再計算されます。`Memo`は例外です——値をそのまま保持することは、純粋なノードにはできないことそのものであるため、これは実行ノードになっています。
- **3種類のグラフすべてがこれらを受け付けます**——`event`、`function`、`macro`——そして Blueprint Value グラフも同様です。ここでも`Memo`は例外であり、`event`と`macro`でのみ利用できます。
- **インプレースでの変更は存在しません。** 書き込みを行うノードは、出力ピンに新しい値を返し、入力にはまったく手を加えません。
- **カード上のリテラルが存在するのは`string`、`integer`、`float`、`boolean`のピンだけです。** `json`または`array`の入力にはカード上のエディタが存在しません——`JSON`リテラル、または`Make Object` / `Make Array`ノードを渡してください。
- **未配線の入力はエラーではありません。** そのピンのカード上のリテラルを読み取り、リテラルがなければ何も読み取りません。そして各ノードはそれを正規化します——欠けた配列は空として、欠けた文字列は`""`として、欠けた数値は`0`として読み取られます。
- **純粋なノードの連鎖は、最大32段まで解決されます。** それを超えると、読み取りは何も返さず、静かに終わります。

<Callout type="warn">
`Array Push`、`Set JSON Field`、`Object Set Field`、そしてこのページの他のすべての書き込みノードは、**新しい**値を返し、入力にはまったく手を加えません。`Get Var → Array Push`と配線しただけでは何も変わりません——結果を`Set Var`へ配線し直す必要があります。[Variables](/ja/docs/studio/blueprint/variables)を参照してください。
</Callout>

## 変換

これらは、接続ルールがあなたを導く先のノード群です。どれも失敗しません——読み取れない入力は、エラーではなくその型のゼロ値を生成します。

### To String

`blueprint.string.toString` · Pure

`null`と未配線の入力はどちらも`""`として読み取られます。オブジェクトや配列は JSON テキストにシリアライズされます。

| ピン | 方向 | 型 | 備考 |
| --- | --- | --- | --- |
| `value` | in · data | `any` | |
| `result` | out · data | `string` | |

### To Integer

`blueprint.data.toInteger` · Pure

ゼロ方向に切り捨てます——`-2.7`は`-3`ではなく`-2`になります。`true`は`1`、`false`は`0`として読み取られ、数値の文字列は受け付けられます。それ以外はすべて`0`になります。

| ピン | 方向 | 型 | 備考 |
| --- | --- | --- | --- |
| `value` | in · data | `any` | |
| `result` | out · data | `integer` | |

### To Float

`blueprint.data.toFloat` · Pure

`To Integer`と同じ受け付け方ですが、切り捨ては行いません。有限の数値でない値は`0`になります。

| ピン | 方向 | 型 | 備考 |
| --- | --- | --- | --- |
| `value` | in · data | `any` | |
| `result` | out · data | `float` | |

### To Boolean

`blueprint.data.toBoolean` · Pure

文字列はトリムして小文字化したうえで照合されます——`""`、`"false"`、`"0"`、`"no"`は偽、`"true"`、`"1"`、`"yes"`は真であり、それ以外の空でない文字列はすべて真になります。`0`と有限でない数値は偽になります。

| ピン | 方向 | 型 | 備考 |
| --- | --- | --- | --- |
| `value` | in · data | `any` | |
| `result` | out · data | `boolean` | |

### To JSON

`blueprint.data.toJson` · Pure

文字列は JSON としてパースされ、パースできなければ元の文字列のまま保たれます——そのためこのノードがテキストを壊すことはありません。それ以外の値は JSON セーフな形にされます——有限でない数値や循環参照は`null`に、関数やシンボルはそのテキスト形式になります。

| ピン | 方向 | 型 | 備考 |
| --- | --- | --- | --- |
| `value` | in · data | `any` | |
| `result` | out · data | `json` | |

### Parse Int

10進数として扱われ、先頭の数値部分が採用されます——`"12px"`は`12`になります。数字がまったくない場合は`0`になります。

## 文字列

ここでのすべての`value`入力はカード上のリテラルを受け付けるため、一度きりの文字列のために専用のリテラルノードを用意する必要はありません。添字は0始まりであり、範囲外の添字は拒否されるのではなくクランプされます。

### Concat

| `b` | in · data | `string` | カード上のリテラルを受け付けます。 |
| `result` | out · data | `string` | |

### Format

`blueprint.string.format` · Pure

テンプレート内の`{name}`を、`values`の対応するフィールドで置き換えます。`values`が配列の場合は`{0}`、`{1}`……で置き換えます。一致しないプレースホルダーは空になり、`values`がオブジェクトでも配列でもない場合はすべてのプレースホルダーが空になります。

| ピン | 方向 | 型 | 備考 |
| --- | --- | --- | --- |
| `template` | in · data | `string` | カード上のリテラルを受け付けます。 |
| `values` | in · data | `json` | `JSON`リテラルまたは`Make Object`を配線してください。 |
| `result` | out · data | `string` | |

## ジオメトリ

## 値を保持する

### Memo

`blueprint.data.memo`

実行がそこを通過するときに一度だけ入力を読み取り、次に実行がそこを通過するまで、その値を出力に保持し続けます。

これは、このカタログの中で**複数**の消費先に供給してよい唯一のデータ出力です。それ以外はすべて単一消費であり、その理由は2つあります——純粋なノードは読み取るたびに再評価されるため、1つの`Random Float`を3つのピンに配線すると3つの数値が得られてしまいます。そして実行ノードの出力は、それを生成したパルスに属します。Memo にはただ1つの書き手——自分自身——しかいないため、どの読み取りも、その書き込みが残した値を返し、複数へ分岐させても誰も驚きません。

| ピン | 方向 | 型 | 備考 |
| --- | --- | --- | --- |
| `in` | in · exec | — | |
| `next` | out · exec | — | |
| `value` | in · data | `any` | 実行が通過する際に一度だけ読み取られます。 |
| `result` | out · data | `any` | カード上では Value と表示されます。 |

意図的に latent ではなく同期的です——待つべきものが何もなく、latent なノードはインラインのストーリー値の中では使えないためです。`function`グラフは純粋なままであるため、Memo をその中に置くことはできません。
