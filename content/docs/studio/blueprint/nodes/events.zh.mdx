事件 Head 是一张`event`图的起点。它没有执行入口——运行时从 Head 进入这张图，执行链从`then`开始。本页其余内容都由这一点展开：Head 的数据输出就是这次事件的 payload，而你能用到哪些 Head，取决于蓝图挂在什么宿主上

## 约定

- **Head 没有执行入口。** 没有任何东西可以连进去。一张图里可以放多个 Head，各自的事件到达时各跑各的执行链
- **数据输出就是 payload。** 除`then`以外的每个输出引脚，都按引脚 id 读取本次运行时事件 payload 的一个字段。派发没有设置的字段读到`null`——不是`0`，也不是`""`
- **坐标是设计坐标。** 元素的鼠标 Head 使用该元素自己的本地设计坐标系；放在 Surface 蓝图上的`Mouse Click`和`Right Click`则使用该 [Surface](/zh/docs/studio/blueprint/surfaces) 的设计坐标系
- **图类型。** 本页节点都只允许`event`图，只有`Send Broadcast`和`Get Listener Count`同时允许`macro`图。Blueprint Value 图只接受两个 Head：`Init`和`On Flush`
- **不可交互的元素不派发。** 控件处于禁用或文本编辑等不可交互状态时，完全不派发它的交互 Head

## 哪些 Head 可用

创建浮窗按蓝图 owner 过滤 Head。没有为你的 owner 列出的 Head，不是被某个开关藏起来了——在那里它根本不存在

| 宿主 | 提供的 Head |
| --- | --- |
| 全局蓝图（`globalMain`） | `App Boot`、`On Game Ready`、`On Fullscreen Changed`、`On Window Close Requested`、四个键盘 Head、两个 preference Head |
| Surface 蓝图（`surfaceMain`） | `Surface Init`、`Surface Unmount`、`Before Surface Exit`、`After Surface Enter`、`Mouse Click`、`Right Click`、`On Fullscreen Changed`、`On Window Close Requested`、四个键盘 Head、两个 preference Head、两个 broadcast Head、`Element Flush`、`Element Click` |
| 控件私有蓝图（`widgetMain`、`componentWidgetMain`） | 由该控件类型声明的能力决定，见下表 |
| Blueprint Value（`widgetValue`） | `Init`与`On Flush` |
| Story Action 蓝图 | `On Call` |

对控件来说，owner 只是规则的一半：每种内建控件都声明了一组事件能力，只有该控件自己列出的 Head 才会出现。这就是为什么`nl.list`没有`Mouse Enter`，而`nl.container`没有`Item Click`

| 控件类型 | Head |
| --- | --- |
| 所有支持私有蓝图的控件 | `Init`、`On Flush`、`Unmount`、`Before Surface Exit`、`After Surface Enter`、四个键盘 Head、`On Fullscreen Changed`、`On Broadcast`、`On Any Broadcast`、`Element Flush`、`Element Click` |
| `nl.container`、`nl.text`、`nl.image`、`nl.button`、`nl.dialog.sentence`、`nl.nvl.texts` | 九个鼠标 Head、`Focus`、`Blur`、`List Item Refresh` |
| `nl.list`、`nl.notification.list`、`nl.choice.list`、`nl.nvl.list` | `Scroll`、`Scroll End`、`Item Render`、`Item Click`、`Item Hover`、`Selection Changed` |
| `nl.slider` | `Drag Start`、`Value Changed`、`Drag End` |
| `nl.textInput` | `Value Changed`、`Submit`、`Focus`、`Blur` |
| `nl.frame` | `Page Event` |

控件蓝图内部还有两层收窄。`List Item Refresh`只有当元素确实位于 List 的 item 模板之内时才提供。另外，创建时绑定了某个事件的事件图层只提供该事件的 Head；创建时 Event 字段保持`-`的图层没有绑定，提供该控件类型允许的全部 Head

## 事件冒泡

元素事件只在运行时命中的那个元素上触发，然后就停在那里——它不会向上传给祖先，父元素也不会默默接管子元素的事件。[Element 分类](/zh/docs/studio/blueprint/nodes/element)里的两个节点负责改变这一点：

曾经用来控制它的两个节点 `Continue Event Bubble` 与 `Stop Event Bubble` 已经被删除。它们真正被稳定用到的那一件事 —— 把窗口关闭挂住 —— 现在是 App 分类下的 [`Keep Window Open`](/zh/docs/studio/blueprint/nodes/app)，它只做这一件事

<Callout type="warn">
焦点位于文本输入元素时，窗口级键盘派发被整体跳过：全局与 Surface 的`On Key Down`/`Any Key Down`都不会执行，所以输入名字时按 Space 不会推进对话、按 Escape 不会打开菜单。获得焦点的控件自己的键盘 Head 仍然照常触发——它们走的是 DOM 冒泡，不是窗口监听
</Callout>

### On Game Ready

`blueprint.event.head.gameReady`

On Game Ready（游戏就绪时）在每个被接受的 NarraLeaf session 触发一次：此时`LiveGame`对象已创建并存入 Studio runtime，但`liveGame.newGame()`还没有启动第一段剧情

运行时把 NarraLeaf 环境初始化当作一个加载项，放在 **Surface 系统启动之前**：它以 Story 库默认 Story 的入口场景的 compiled story 挂载 Player，因此`LiveGame`已经存在、该场景资源开始预热，而玩家仍停留在主菜单。真正「进入游戏」只发生在`Start Game`或读档时，并且复用同一个已初始化的`LiveGame`：当`Start Game`的目标就是已预热的默认场景时为秒开，**不会**再次触发该 Head；只有`Start Game`指向不同场景时才会重新挂载环境并第二次触发。项目未配置默认 Story 时改为挂载一个空环境，该 Head 在启动时依然触发

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `then` | out · exec | — | |

<Callout type="info">
把 NarraLeaf Preference 的初始化放在这里——`Set Auto Forward`、`Set Game Speed`、`Set Voice Volume`、`Set Sentence Speed`——这样它们在玩家进入游戏之前就已就绪。不要放在`App Boot`里：名字虽然像最早的钩子，它并不最先执行（`On Game Ready`先于它触发），而且它不保证此刻存在活动的 live game
</Callout>

### On Fullscreen Changed

`blueprint.event.head.fullscreenChanged`

On Fullscreen Changed（全屏状态变更时）在应用窗口进入或退出全屏时触发，包括在游戏之外切换全屏的情况。它是环境型窗口事件，因此派发是扇出的：先全局蓝图，再当前 active Surface 蓝图，最后该 Surface 上所有声明了该 Head 的控件蓝图。所以设置面板里的控件不必拥有整个 Page 也能跟随窗口状态

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `then` | out · exec | — | |
| `isFullscreen` | out · data | `boolean` | 变化后的状态|

### On Window Close Requested

`blueprint.event.head.windowCloseRequested`

On Window Close Requested（窗口关闭请求时）在玩家请求关闭窗口时触发。主进程会把这次关闭挂起，等全局蓝图、再等 Surface 蓝图跑完；两者中任意一个执行了 `Keep Window Open` 就取消关闭，没有则窗口继续关闭。在 Studio Dev Mode 中它覆盖 Dev Mode 窗口，在预览和正式产物中覆盖游戏窗口

只在全局蓝图和 Surface 蓝图中提供。取消动作依附于本次派发共享的 event control，而控件派发路径不传递它——这和键盘 Head 止步于 Surface 是同一个原因

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `then` | out · exec | — | |

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `then` | out · exec | — | |

### On Flush

`blueprint.event.head.flush`

On Flush（刷新时）在当前蓝图所属元素被蓝图 Host API 显式改写属性、并因此触发重绘时执行。渲染器自动计算的 CSS 状态样式（hover、focus 变体）不会触发它。在 Blueprint Value 中它兼作显式求值入口：默认 Dialog Nametag 就是靠这个入口在 Dialog 不重新挂载的情况下随对话推进刷新

Flush 是属性提交后的批处理通知。运行时按帧合并同一元素的 flush；flush 处理器内部再次改写该元素时，新的 flush 进入**下一帧**的批次——不存在同步重入

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `then` | out · exec | — | |
| `element` | out · data | `element` | 被刷新的元素引用|

## 键盘

键盘事件由运行时窗口级监听派发，不依赖元素焦点。全局蓝图、当前 active Surface 蓝图，以及所有已挂载且拥有该 Head 的控件，都会收到同一次窗口事件，并各自执行自己的链。控件的键盘监听随控件挂载注册，卸载时自动移除

Surface 完成 prepaint 之后，Page 进退场期间键盘事件仍会派发。需要在过渡期间屏蔽时，在图里用 Page 分类的`Is Surface Entering`、`Is Surface Exiting`或`Is Surface Transitioning`分支

只想匹配一个绑定时用带过滤的一对，想拿到按键本身时用`Any Key`一对：`On Key Down`/`On Key Up`匹配卡片上配置的绑定且不携带 payload，而`Any Key Down`/`Any Key Up`对每个按键都触发，并给出`key`和各修饰键状态

## 绑定元素的 Head

这两个 Head 先绑定同一 Surface 内的目标控件——和`Element`节点一样——然后监听**那个**控件而不是自己。它们同时也是元素绑定来源：Element 派生节点只有在当前图里已经存在兼容的`Element`、`Element Flush`或`Element Click`时才出现在创建浮窗中，而它们的`element`输出可以直接连到这类节点的目标输入

### Element Flush

`blueprint.event.head.elementFlush`

Element Flush（元素刷新）监听绑定目标的 flush。目标控件被 Host API 显式改写属性并重绘后，当前蓝图中的该 Head 执行

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `then` | out · exec | — | |
| `element` | out · data | `element` | 被刷新的绑定元素引用|

### Element Click

`blueprint.event.head.elementClick`

Element Click（元素点击）监听绑定目标自己的`mouseClick`。目标控件收到真实点击后该 Head 执行；它不依赖点击穿透，也不依赖父子冒泡。默认 Dialog 模板用它把推进逻辑集中在一处：Dialog Content 蓝图自己用`Mouse Click`，同时用`Element Click`绑定全屏透明的 Dialog Interaction Layer、可见的 Dialog Panel 和默认内容子控件，全部连到同一个 Game `Next`

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `then` | out · exec | — | |
| `element` | out · data | `element` | 被点击的绑定元素引用|
| `x` | out · data | `float` | 使用目标元素的本地设计坐标|
| `y` | out · data | `float` | 使用目标元素的本地设计坐标|

## Game Preference

两个 Head 都订阅当前活动`LiveGame`的 preference 派发器，因此只在全局蓝图和当前 active Surface 蓝图中提供。没有活动 game runtime 时不会订阅，也不会触发；`On Game Ready`之后运行时在新的`LiveGame`上重新订阅。Preference Setter（如`Set BGM Volume`）和 NarraLeaf 内部写入都会触发它们，并且写入相同值不保证被去重——所以不要在监听某个偏好的图里再写入同一个偏好，那会构成自触发循环。Getter 和 Setter 见 [Game 节点](/zh/docs/studio/blueprint/nodes/game)
