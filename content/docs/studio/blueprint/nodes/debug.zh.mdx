两个节点，只有一个会执行。Log（日志）在游戏运行时写出一行可读的内容；Comment（注释）只是画布上的一个文本框，运行时根本看不见它

## Log

`blueprint.log`

写一行，然后继续往下走。要回答「这条分支到底跑没跑，那个引脚里是什么」，这是最省事的办法

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `in` | in · exec | — | |
| `next` | out · exec | — | 写完这一行后触发|
| `value` | in · data | `string` | 接受卡片内联字面量|

这一行会落在**控制台**面板的 [Blueprint 频道](/zh/docs/studio/getting-started/workspace-overview)，来源标记为`Blueprint Log`，级别为 info；超过 4096 个字符的部分会被裁掉，并附上`… [truncated]`标记。同一行还会带`[Blueprint]`前缀完整镜像到窗口的开发者控制台

`value`不是这个节点唯一的输入。卡片上的添加输入控件会追加更多`string`引脚——`in_1`、`in_2`……，标签从`Input 2`开始——它们之间不加分隔符，直接拼成一行，所以`"score: "`和一个数字得到`score: 42`，中间不需要`Concat`节点。上表只列出节点初始就有的那个引脚。不是字符串的值会先按 JSON 编码；JSON 编不了的值退回它的普通字符串形式

当所有输入都解析不出值时，这一行是`Log node reached`——这个默认值的用处在于，`Init`直接接`Log`就能证明某条路径确实执行了，而你一个字都不用填。空字符串仍然算一个值，会记录成空行

`Log`只在`event`和`macro`图中可用。它对图外的世界有影响，而`function`图不允许这样的节点

<Callout type="info">
控制台面板的内容来自正在运行的游戏。编辑器画布上没有运行时宿主来接收这一行，因此只有窗口的开发者控制台能拿到它——`Log`的输出要在开发模式里看
</Callout>

## Comment

`blueprint.flow.comment` · Pure

画布上一个可调整大小的说明框。它完全不声明引脚：没有东西能连到它，它永远不执行，也不产出任何值。在`event`、`function`和`macro`图中都合法，也可用于 Blueprint Value——因为它身上没有任何会出问题的东西

节点卡本身*就是*这段注释，它没有属性面板。你编辑的就是这个框：

**卡片字段**

| 字段 | 作用 |
| --- | --- |
| `text` | 注释正文。多行，直接在框里输入|
| `color` | `amber`（默认）、`cyan`、`violet`或`slate`，从悬停时出现在标题栏上的色块中选取|
| `background` | 默认开启。关掉之后框的填充仍然可见，但会渲染在其它节点之下——要框住一组节点而不是盖住它们，就这样做|
| `width` | 框的宽度。拖动右下角的手柄调整|
| `height` | 框的高度，用同一个手柄拖动|

类型 ID 仍然是`blueprint.flow.comment`。保持不变是为了让节点归入 Debug 分类之前创作的图仍能加载；分类才是你在创建浮窗里找到它的地方
