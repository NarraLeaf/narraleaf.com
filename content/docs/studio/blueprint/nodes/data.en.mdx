Data holds the values a blueprint computes with. Reach for it when you need a constant, when a value arrives as the wrong type, or when you have to take apart a string, an array, or a JSON document. Almost nothing here has an exec pin — a Data node is read by whoever is wired to its output. `Memo` is the one exception, and it explains itself below.

## Value types

These `valueType`s appear on the pins below.

| `valueType` | Holds | Produced by |
| --- | --- | --- |
| `string` | Text. | `String`, every string node. |
| `integer` | A whole number. | `Integer`, lengths, indices, counts. |
| `float` | A number. | `Float`, `To Float`, `Parse Float`. |
| `boolean` | True or false. | `Boolean`, every type test and string test. |
| `json` | Any JSON value: object, array, string, number, boolean, or `null`. | `JSON`, `Parse JSON`, `Get JSON Field`, `Make Object`. |
| `array` | A JSON array, as a type of its own. | `Make Array`, the `Array …` nodes that return an array, `Object Values`. |
| `array<T>` | An array whose items are all of type `T`. The card shows it as a list of that type, such as **Ending list** or **string list**. | `Get Endings`, `Get History`, `Split`, `Object Keys`, `Array Range`. |
| `struct:<id>` | An object whose fields are declared, such as an ending or a save entry. The card shows the struct's name, such as **Ending**. See [Structs](#structs). | `Array First` on endings, `Item Click` on a List, `For Each` over endings. |
| `any` | Anything. | `Memo`, and the pins whose type follows what is picked on the card, such as `Get Field` and `Get Var`, until something is picked. |
| `RGBAColor` | `{ r, g, b, a }`. | `Color`. |
| `Vector2D` | `{ x, y }`. | `Vector2D`, `Make Vector2D`, `Rect Center`, `Get Center`. |
| `Rect` | `{ x, y, width, height }`. | `Rect`, `Make Rect`, `Get Bounds`, `Get Measured Rect`. |

An edge between two data pins is allowed when the types are identical, or when one of these holds:

| From | To | Why |
| --- | --- | --- |
| `integer` | `float` | Every integer is a float. |
| `integer`, `float` | `string` | The number is converted to text as the input is read. This is the only coercion that rewrites the value — every other permitted edge passes it through untouched. |
| `array` | `json` | An array is a JSON value. |
| `array<T>` | `array`, `json` | An array of known items is still an array. |
| `array<T>` | `array<U>` | When a `T` connects to a `U`. |
| `struct:<id>` | `json` | A struct is a JSON object. |
| `struct:<id>` | another struct | When both have the same fields, in the same order, with the same types. |
| `Rect` | `json` | A migration allowance rather than a rule about structured values — see below. |
| `any` | anything | `any` matches in both directions. |
| anything | `any` | |

Types from other categories widen the same way and nowhere else: `element` connects to any `element:nl.…` pin and back, element pins do not connect to `any` in either direction, and `ImageAsset` and `string` both reach an `ImageAsset|null` input.

Everything else is refused, including the reverses authors expect to work:

- **`json` → `array`, `json` → `Rect`.** Every widening rule runs one way only. An arbitrary object is not a rectangle.
- **`json` → a struct.** An object whose fields are not declared, such as the result of `Parse JSON`, does not connect to `Get Field`. Read it with `Get JSON Field`.
- **`float` → `integer`.** Insert `To Integer`, which truncates toward zero.
- **`string` → `integer` or `float`.** Insert `Parse Int`, `Parse Float`, `To Integer`, or `To Float`.
- **`boolean` → `string`, `json` → `string`.** Only numbers coerce to text. Insert `To String` or `Stringify JSON`.
- **`string`, `integer`, `float`, `boolean` → `json`.** `array` and `Rect` are the only types that reach a `json` input implicitly. Insert `To JSON`.
- **`RGBAColor` → `json`, `Vector2D` → `json`.** They are structured types of their own, not JSON documents. Take them apart with `Break Vector2D`, or build a document with `Make Object`.

<Callout type="info">
`Rect` → `json` is there for graphs written before `Rect` was a type. The `Rect` literal and `Get Bounds` both published `json` until it became one, so rectangles authored back then still feed `Get JSON Field` and keep working. `Vector2D` never was a `json` pin and stays narrow.
</Callout>

<Callout type="info">
`array` feeds a `json` input, never the reverse. A `json` value that happens to hold an array (`Parse JSON`, `Get JSON Field`) will not connect to an `array` input such as `Array Length` or List's `Set List Content`. `For Each` in [Flow](/docs/studio/blueprint/nodes/flow) takes `json`, so iterating over it still works; the `Array …` nodes do not.
</Callout>

<Callout type="info">
The `array<T>` and struct types decide what connects and what the card offers. They do not change the values: an ending is the same object when the game runs. A wire that connected in a graph from an earlier version still connects.
</Callout>

## Conventions

- **Every node here is pure but one.** There are no exec pins to connect, so a Data node cannot sit on the execution path. Its output is computed when a consumer reads it, and recomputed on the next read. `Memo` is the exception: it is an exec node, because holding a value still is exactly what a pure node cannot do.
- **A Blueprint Value graph accepts all of them**, `Memo` included.
- **Nothing is modified in place.** A node that writes returns a new value on its output pin and leaves its input alone.
- **On-card literals exist for `string`, `integer`, `float`, and `boolean` pins only.** A `json` or `array` input has no on-card editor; feed it a `JSON` literal or a `Make Object` / `Make Array` node.
- **An unwired input is not an error.** It reads the pin's on-card literal, or nothing when there is none, and each node normalizes: a missing array reads as empty, a missing string as `""`, a missing number as `0`.
- **A chain of pure nodes resolves at most 32 links deep.** Past that the read returns nothing, silently.

<Callout type="warn">
`Array Push`, `Set JSON Field`, `Remove JSON Field`, and every other writer on this page hand you a **new** value and leave the input untouched. Wiring `Get Var → Array Push` changes nothing on its own — you have to wire the result back into `Set Var`. See [Variables](/docs/studio/blueprint/variables).
</Callout>

### To Boolean

`blueprint.data.toBoolean` · Pure

Strings are matched after trimming and lowercasing: `""`, `"false"`, `"0"`, and `"no"` are false; `"true"`, `"1"`, and `"yes"` are true; any other non-empty string is true. `0` and a non-finite number are false.

| `value` | in · data | `any` | |

### To JSON

`blueprint.data.toJson` · Pure

A string is parsed as JSON, and kept as the original string when it does not parse — so this node never destroys text. Other values are made JSON-safe: a non-finite number and a cycle become `null`, a function or symbol becomes its text form.

## Strings

Every `value` input here takes an on-card literal, so a one-off string does not need its own literal node. Indices are zero-based, and out-of-range indices are clamped rather than rejected.

### Format

`blueprint.string.format` · Pure

Replaces `{name}` in the template with the matching field of `values`, or `{0}`, `{1}` … when `values` is an array. A placeholder with no match becomes empty, and every placeholder becomes empty when `values` is neither an object nor an array.

`Format` is the one formatter the palette offers, and it works in a Blueprint Value and in a function. For a template in the player's language, wire [`Translation Key Text`](/docs/studio/blueprint/nodes/localization#translation-key-text) into `template`.

| Pin | Direction | Type | Notes |
| --- | --- | --- | --- |
| `template` | in · data | `string` | Accepts an on-card literal. |
| `values` | in · data | `json` | Wire a `JSON` literal, a `Make Object`, or a `Make Array` for `{0}`, `{1}` …. |
| `result` | out · data | `string` | |

## Structs

A struct is an object whose fields are declared: an ending, a history entry, a save entry, a gallery entry, or a row of a List. A pin that carries one shows the struct's name on the card, such as **Ending**, and a pin that carries an array of them shows **Ending list**. `Get Field` reads one field, picked from a dropdown.

| Struct | Fields | Handed out by |
| --- | --- | --- |
| **Ending** | `endingId`, `name`, `sceneId`, `sceneName`, `isReached` | [`Get Endings`](/docs/studio/blueprint/nodes/game#get-endings) |
| **History entry** | `id`, `type`, `text`, `character`, `avatar`, `voice`, `voiceId`, `selected`, `isPending` | [`Get History`](/docs/studio/blueprint/nodes/game#get-history), [`Get Future History`](/docs/studio/blueprint/nodes/game#get-future-history) |
| **Save entry** | `id`, `slot`, `timestamp`, `createdAt`, `preview`, `line`, `speaker`, `metadata` | [`List Auto Saves`](/docs/studio/blueprint/nodes/game#list-auto-saves) |
| **Notification** | `id`, `message` | [`Get Notifications`](/docs/studio/blueprint/nodes/game#get-notifications) |
| **Language** | `code`, `displayName`, `isSource` | [`Get Available Languages`](/docs/studio/blueprint/nodes/localization#get-available-languages) |
| **Voice language** | `code`, `displayName` | [`Get Available Voice Languages`](/docs/studio/blueprint/nodes/voice#get-available-voice-languages) |
| **Choice** | `text`, `index`, `disabled`, `voiceId` | The rows of the choice list in the Game UI |
| **NVL line** | `index`, `nametag`, `isActive` | The rows of the NVL list in the Game UI |
| **Confirm button** | `id`, `text`, `index`, `disabled` | The buttons `Show Confirm` opens its page with |

The fields are described with the node that hands them out. A plugin can declare the structs its own nodes hand out, such as the Gallery's **Gallery entry**; see [Manifest](/docs/studio/plugin/manifest#structs). The rows of a List have the struct set under **Edit content**, which is one of the structs above or the fields written for that List; see [Lists](/docs/studio/workspace/ui-editor#lists).

- **The type follows the wires.** The array nodes pass the item type on, as described under [Arrays](#arrays). `For Each` in [Flow](/docs/studio/blueprint/nodes/flow#for-each) gives one item of the array it walks. The List nodes and the item heads give and take rows of the List's struct; see [List](/docs/studio/blueprint/nodes/list#conventions).
- **A field's type becomes the pin's type.** A String field gives `string`, Number `float`, Boolean `boolean`, Image `ImageAsset|null`, Color `RGBAColor` and JSON `json`.
- **Dragging a wire off a struct.** Release a wire dragged from a struct pin on empty canvas, and the add-node menu opens on **Fields**, which lists **Get** for each field, such as **Get isReached**. A wire dragged from an array of structs lists **Filter by**, **Sort by** and **Find by** for each field, such as **Filter by isReached**. Each entry adds the node with the field already chosen and wires it to the pin. **Filter by** and **Find by** on a boolean field compare against True.
- **A field the struct does not have is reported.** A `Get Field` set to a field the struct lacks, and a `key` on `Array Filter By Key`, `Array Sort By Key` or `Array Find By Key` that names no field of the items, are warnings on the canvas and the project check **Field not in shape** (`blueprint/field-missing`). Such a node reads nothing: `Get Field` gives an empty value, a filter keeps no items, and a sort keeps the order. This happens after a List's field is deleted or a key is typed by hand. Only nodes whose struct is known are checked.

### Get Field

`blueprint.list.getItemField` · Pure

One field of a struct. Wire the struct into **Object** and pick the field under **Field**. The output takes the field's type, so `isReached` from an ending wires straight into `Branch`.

| Pin | Direction | Type | Notes |
| --- | --- | --- | --- |
| `object` | in · data | `struct:*` | Any struct, shown as **Struct**. Can stay unwired inside a List row. |
| `value` | out · data | `any` | Takes the type of the picked field. `null` when the value has no such field. |

**On-card fields**

| Field | What |
| --- | --- |
| `Field` | The field to read, from the fields of the struct wired into **Object**. A field the struct no longer has stays in the list as **Missing field “…”**. |

- **The first struct wired in is kept.** From then on **Object** accepts only that struct, even after its wire is removed. To read another struct, add another `Get Field`.
- **Inside a List row, Object can stay unwired.** The node then reads the row being drawn, and the card shows **Object · Current row**. A row is in reach in the places listed under [List](/docs/studio/blueprint/nodes/list#conventions): the blueprints of the elements in the List's item template, the List's own item heads, and component definitions.
- **Unwired anywhere else, it reads nothing.** The card reports **Object** as not connected. A `Get Field` that kept a struct and lost its wire also reads nothing; it does not read the row instead.
- **An object without declared fields** does not connect. Read it with `Get JSON Field`.

The node was named **Get Item Field** and read only List rows. Its type id is unchanged, so graphs that hold it keep the node, and one left unwired in a row reads the row as before.

## Holding a value

### Memo

`blueprint.data.memo`

Reads its input once, when execution passes through, and keeps that value on its output until the next time execution passes through. Before the first pass the output reads `null`. The value is kept in the same store as the blueprint's [variables](/docs/studio/blueprint/variables#blueprint-variables): one held during `Init` is still there for a later `Mouse Click`, and it starts over when that owner instance does.

Its output may feed **several** consumers. A computed data output feeds only one, and a second wire from it replaces the first, for two different reasons: a pure node re-evaluates at every read, so the same `Random Float` read twice gives two numbers; and an exec node's output belongs to the pulse that produced it. A Memo has exactly one writer — itself — so every read returns what that write left, and fanning it out cannot surprise anybody. The literals on this page, `Element` bindings and the parameter pins of an [`Fn`](/docs/studio/blueprint/nodes/functions#fn) fan out as well, because every read of them gives the same value.

| Pin | Direction | Type | Notes |
| --- | --- | --- | --- |
| `in` | in · exec | — | |
| `value` | in · data | `any` | Read once, as execution passes. |
| `next` | out · exec | — | |
| `result` | out · data | `any` | Labelled Value on the card. |

Synchronous rather than latent on purpose: there is nothing to await, and a latent node would be barred from an inline story value.
