List 节点用于驱动当前私有蓝图所属列表控件的运行时内容、选中项和滚动位置。当行是在游戏运行时才决定的——存档槽、历史回顾、设置菜单——而不是在检视器里一次性写好时，就用它们。把数组和对象整理成最终形状的工作仍然留在 [Data](/zh/docs/studio/blueprint/nodes/data)。

## 约定

- **List 渲染的是运行时条目数组。** `Set List Content`（设置列表内容）写入的是实例级的运行时数组；`Append`、`Insert`、`Remove`、`Clear` 和 `Refresh` 更新的是同一份存储。条目按 JSON-safe 形式保存，因此撑不过一次 JSON 往返的东西在写入时就会丢掉。
- **`itemsBinding` 只是 fallback。** 没有写入过运行时条目时才读取元素的 items binding；连 binding 也没有时，由检视器里的预览条目顶上。对运行时存储的第一次写入就终结了这条 fallback。
- **改写节点会把 fallback 固化下来。** 除 `Set List Content` 和 `Clear List` 之外的每个改写节点都会先读当前条目、再把整个数组写回去。在一个从未被写入过的 List 上，这次读取取自 fallback，而这次写回把该快照变成了运行时条目——从此 binding 不再生效。
- **卸载会清空实例。** List 实例完全卸载时，运行时条目、选中项和待处理的滚动指令都会被丢弃。系统不会替你持久化；把内容写进变量或状态，并在 List 回来时显式恢复。
- **读取是纯节点，改写是 latent。** `Get` 系列节点可用于 `event`、`function` 和 `macro` 图。每个改写节点都是 latent（会挂起执行），只能用于 `event` 和 `macro`——function 图要同步把值返回给调用者，没有地方去接一次待完成的写入。
- **内容与选中项的写入会排队触发 flush，滚动节点不会。** 滚动节点只是记录一个供渲染器消费的意图，因此不会重新跑那些由 flush 驱动的工作。
- **这些都是 Self 节点。** 它们作用于拥有当前图的 list-like 控件——`nl.list`、`nl.notification.list`、`nl.choice.list`、`nl.nvl.list`——并且没有目标引脚。要操作另一个 List，请使用 [Element](/zh/docs/studio/blueprint/nodes/element) 分类下的 `blueprint.element.list.*` 对应节点，它们带有 `list` 输入，且只在当前图中已存在绑定到 `nl.list` 的节点时才出现。
- **条目上下文需要模板后代。** 四个 `Get List Item …` 节点只出现在 List item template 内部元素所拥有的蓝图中，读取的是该元素当前渲染所处的那个条目作用域。

<Callout type="warn">
`Clear List` 写入的是一个空的运行时数组，而空数组同样算作已写入的内容——`itemsBinding` 不会回来，List 会一直空着，直到你再次写入条目。唯一能恢复 fallback 的是卸载 List 实例，而它会连同选中项和滚动状态一起丢弃。
</Callout>

## Set List Content

`blueprint.list.setItems` · Latent

`Set List Content` 整体替换运行时条目数组。不是数组的值会被当成空数组写入，而不是被拒绝，因此一条接错的 `items` 连线会悄无声息地把 List 清空。

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `in` | in · exec | — | |
| `next` | out · exec | — | |
| `items` | in · data | `array` | 非数组值按空数组写入。 |

## Insert List Item

`blueprint.list.insertItem` · Latent

`Insert List Item`（插入列表条目）在指定下标之前插入。下标会夹到 `0…length`，不是数字的下标则回退为末尾，因此越界位置不会抛错。

| 引脚 | 方向 | 类型 | 说明 |

| `in` | in · exec | — | |

| `item` | in · data | `any` | |

## Get List Item Props

`blueprint.list.getItemProps` · Pure

`Get List Item Props`（获取条目 props）输出当前行正在渲染的条目：条目本身是 object 时就是它，否则是 `{ value: item }`，因此哪怕是一个纯字符串的 List，也照样有一个字段可读。没有条目上下文时输出 `{ value: null }`。

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `props` | out · data | `json` | |

<Callout type="info">
四个条目上下文节点读取的是正在渲染那一行的条目作用域，并且除事件图之外也能用于 Blueprint Value 图——模板里的一个文本元素之所以能逐行显示不同的字符串，靠的就是这个。重复渲染出来的行彼此隔离，因此每份副本都保有自己的事件 locals 和自己解析出的 Blueprint Value，尽管所有副本都来自同一个源 element id。
</Callout>
