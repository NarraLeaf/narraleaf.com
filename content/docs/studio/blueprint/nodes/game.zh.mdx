Game 分类是蓝图与运行中剧情之间的接缝。这里的一切都在和活着的 NarraLeaf 运行时说话：游玩本身、屏幕上的对话、玩家的偏好、项目的本地存档，以及对话历史。标题画面、设置画面、存读档网格和对话记录界面，都由本页的节点搭起来

<Callout type="warn">
本页每一个节点都需要运行中的游戏。编辑器画布没有游戏：放在那里的 Game 节点会以`该节点仅在游戏运行时可用，需在开发模式中运行`失败，读取它的 Blueprint Value 预览为空。这些行为一律在开发模式中验证
</Callout>

## 约定

- **基本上要么 pure 要么 latent。** 四十四个节点是`Pure`，可以支撑 Blueprint Value。五十一个是`Latent`，Blueprint Value 一个都不提供。第九十六个是 `Clear Visited`，也是唯一的怪例：有副作用但同步，所以 Blueprint Value 和对待 latent 节点一样不提供它，它自己却不是 latent
- **Story Action 蓝图不提供。** 由故事行调用的蓝图没有游戏宿主，因此它的创建浮窗里没有本页的节点，`Get Build Variant` 除外
- **有 Host API 不等于有一局游戏。** `List Saves`、`Get Save Metadata`、`Get Save Time`、`Get Save Line`、`Get Save Story`、`Get Save Playtime`、`Get Save Preview`、`Delete Save`、`List Auto Saves`和`Get Latest Auto Save`读取项目的存档库，在两局游戏之间、没有游戏运行时也能工作。结局、走过的路线、DLC 与构建变体那几组读取节点同样如此——结局画廊本来就是从标题界面打开的，那时还没有任何游戏。凡是序列化、反序列化或指挥活动游戏的节点都需要一局游戏，没有就失败
- **状态取值节点会降级，偏好取值节点不会。** 每一个纯状态读取——`Is In Game`、`Is Game Overlay`、`Get Nametag`、`Get Speaker Avatar`、`Get Speaker Color`、`Get Dialog Text`、`Is Narrator`、`Is Dialog Waiting`、`Get Choice Count`、`Get Notifications`、`Is NVL Mode`、`Is Text Read`、`Has Read Text`、`Can Undo History`、`Can Redo History`、`Get Track Volume`、两个游玩时长读取，以及结局、走过的路线、DLC、构建变体与角色的那些读取——在什么都没有播放时都给出中性值：`false`、`null`、`0`、空数组，颜色给不透明白，音轨音量给 1。正因如此，同一个共享 Page 才能按它们分支，画廊的一行也才能把「锁住」的样子直接绑到引脚上。十八个偏好取值节点是例外：它们读的是活动`GamePreference`，没有游戏就失败。`Is Dialog Shown` 也是其中之一——它读的是 `showDialog` 偏好，只是名字按问题起而不是按键名起
- **偏好初始化挂在`On Game Ready`上，不要挂`App Boot`。** `App Boot`可能早于`LiveGame`存在就运行，而没有活动游戏的偏好写入会失败。参见[事件](/zh/docs/studio/blueprint/nodes/events)
- **存档 id 会被校验。** id 会被 trim，不能为空，不能含路径分隔符或控制字符。磁盘上的文件名由 id 的哈希派生；你选的 id 保存在记录的 metadata 里

## 游玩

`Start Game`和`Quit Game`是尾节点：它们把控制权交给运行时，没有执行出口，所以后续该发生的事属于剧情，或者属于它们打开的那个 Page

### Start Game

`blueprint.game.startStory` · Latent

Start Game（开始游戏）启动节点卡片上选中的 Story 与 Scene，并切换到游戏舞台。游戏首帧就绪后，当前 Page 栈会被藏到游戏下面，因此之后调用`Go Page`是把目标叠加在舞台之上，而不是替换舞台

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `in` | in · exec | — | |
| `storyId` | in · data | `string` | 可选。连线优先于卡片 |
| `sceneId` | in · data | `string` | 可选。连线优先于卡片——`Import Progress` 的 `Scene` 就接到这里 |
| `startBlockId` | in · data | `string` | 可选，卡片上标作 **From Row**，只能连线。从该行进入场景，而不是从场景开头 |
| `inheritFrom` | in · data | `SaveSlot` | 可选。新游戏要继承其进度的存档，见下文|

**卡片字段**

| 字段 | 含义 |
| --- | --- |
| `Story` | 要运行的剧本。除非 `storyId` 已连线，否则必填|
| `Scene` | 要进入的场景。选项按选中的 Story 过滤。除非 `sceneId` 已连线，否则必填|

十次里有九次作者要的是选择器：它列出项目自己的剧本，也拼不错。这几个引脚是为第十次准备的——写图的时候还不知道目标是哪一个，比如一个「继续」按钮要从玩家上次的位置接着走

接上 `inheritFrom` 时，游戏仍然从选中的场景开始新的一局，然后取入该存档的[存档变量](/zh/docs/studio/blueprint/variables#存档变量)和其中走过的场景（即 `Is Scene Visited` 读取的那份记录）。舞台、对话记录和剧情位置不会被带过来；恢复这些是 `Load Save` 的事。[`Save Slot`](#save-slot) 带来存档库里的一份存档，用于从通关存档开始的二周目。[`Current Game`](#current-game) 带来正在进行的这一局，用于在另一个故事里继续的路线。存档槽指向的存档不存在时，节点在剧情开始之前就失败

### Quit Game

`blueprint.game.quit` · Latent

Quit Game（退出游戏）结束当前游玩，并打开卡片上选中的 Page。一次调用做完全部事情：丢弃活动游戏与会话、取消仍在等待的启动请求、打开 Page，然后清空对话名牌并恢复普通 Page 显示。不需要再接一个`Go Page`。Page 打开之前，屏幕上保留游戏的最后一帧，而 `Is In Game` 此时已经返回 `false`

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `in` | in · exec | — | |
| `surfaceId` | in · data | `string` | 可选，卡片上标为 **页面 Id**。连线优先于卡片|

**卡片字段**

| 字段 | 含义 |
| --- | --- |
| `Page` | 游戏结束后打开的 [Surface](/zh/docs/studio/blueprint/surfaces)。除非 `surfaceId` 已连线，否则必填|

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `isInGame` | out · data | `boolean` | |

### Is Game Overlay

`blueprint.game.isGameOverlay` · Pure

Is Game Overlay（是否为游戏覆盖层）：当前 Surface 实例是否以游戏之上的 UI 叠层身份运行。`Start Game`或`Load Save`之后用`Go Page`打开的 Page 返回 `true`，游戏进行中用`Show Layer`显示的页面同样返回 `true`，内建的游戏 UI Surface（例如对话槽位）也返回 `true`；通过`nl.frame`嵌入的子 Page 继承父级的答案。普通应用 Page、游戏之外显示的叠加页面、Page 预览，以及`Quit Game`打开的那个 Page 返回 `false`

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `isGameOverlay` | out · data | `boolean` | |

答案在 Page 或叠加页面实例创建时就锁定，所以正在播放退出动画的暂停菜单仍返回 `true`，哪怕`Quit Game`已经开始拆掉会话。要问运行时是否还在，用`Is In Game`；要问一个共享 Page 该显示成什么样，用这个

**应用逻辑**不属于任何 Surface，在应用逻辑中该节点回答的是游戏的状态，而不是某个页面的答案。游戏进行中，舞台上方画着页面或显示着模态叠加页面时返回 `true`；舞台上什么都没有，或只有非模态叠加页面（HUD、提示）时返回 `false`。答案在节点被求值的那一刻读取，应用逻辑发起的`Call Fn`得到同样的答案。不在游戏中时，应用逻辑读到的是当前页面自己的答案

## 偏好

下面每一对都对应活动游戏上引擎`GamePreference`的一个字段。取值节点是 pure 的，可安全放进 Blueprint Value；设值节点是 latent 的，写入前先校验——值不合法时节点失败，而不是被夹到范围内。`showDialog`在这里没有配对节点，由`Show Dialog`、`Hide Dialog`、`Toggle Dialog Display`和`Is Dialog Shown`覆盖

本节的设值节点在没有活动游戏运行时都会失败，取值节点也一样，只有 `Get Track Volume` 例外——它读的是引擎的混音器而不是`GamePreference`。要为新一局游戏播种偏好，把设值节点接在`On Game Ready`上——它在`LiveGame`已存在之后、第一句剧情之前运行

## 存档

存档是项目本地的，以你自己选的 id 为键。同一个 id 写第二次就是覆盖

下面每个针对单份存档的节点都有两种指定方式：`id` 引脚上的 id，或可选的 `slot` 引脚上的 `SaveSlot`。`slot` 连线时优先于 `id`。[`Save Slot`](#save-slot) 用 id 做出一个存档槽，一个 id 就能接给多个节点。[`Current Game`](#current-game) 为正在进行的这一局做出存档槽，只有 `Start Game` 接受它；其他存档节点收到它都会失败

<Callout type="warn">
`List Saves`只返回玩家存档。自动存档住在保留 id 命名空间里——`@autosave.<n>`——由`List Auto Saves`列出；两个集合永不重叠。这是刻意的：基于`List Saves`做的存读档网格从不需要过滤掉 Studio 自己的簿记条目，自动存档界面也从不需要藏起玩家的存档位。在别的地方，自动存档 id 就是一个普通存档 id，可以原样喂给`Load Save`、`Get Save Preview`、`Get Save Metadata`和`Delete Save`
</Callout>

### Save fields

一份存档携带两类数据。一类由引擎在每次存档时写入：存档将从哪一句继续、那句话由谁说出、以及时间戳。另一类由你决定，**存档字段**就是声明它的地方

从 `Save Game` 或 `Get Save Metadata` 卡片底部的按钮打开。每个字段有名称、类型和默认值

声明过的字段会成为具名引脚：在 `Save Game` 上是输入，在 `Get Save Metadata` 上是输出。这份列表属于项目，不属于打开它的那个节点，因此项目内所有存档节点显示的字段完全一致，一个字段只需声明一次

重命名字段只更换引脚标签，已有的连线全部保留。改变类型会重置它的默认值

| 行为 | 结果 |
| --- | --- |
| 从声明该字段之前写下的存档中读取它 | 该字段的默认值 |
| 删除字段 | 已写入的值仍留在持有它们的存档文件中 |
| 会执行到的 `Save Game` 上，声明过的字段留空 | 项目检查以 error 报告 `blueprint/save-field-empty` |

两个节点上的 `metadata` 引脚都保留。在 `Save Game` 上，声明字段会覆盖写在它之上，因此同名的键以声明字段为准；在 `Get Save Metadata` 上，它仍然返回完整的存储对象

## 历史

对话历史——也就是对话记录——是引擎自己保存的、已经过去的台词与选择菜单，并且可以回放到其中任意一点

## 结局

### Get Build Variant

`blueprint.game.getAppTag` · Pure

这个包是项目的哪一个[变体](/zh/docs/studio/patches)。

它是整份目录里唯一一个在游戏存在之前就已经定下值的节点。一次构建产出一个变体，它的名字在这里被代入，消费它的那次比较被折叠，这一版不走的那条分支被**删除**——于是变体判断背后的内容是从包里**不存在**，而不只是在包里到不了。如果一张图里的 `Get Build Variant` 最终没有决定任何分支，它会在构建闸门上被拒绝，每一种构建包括正式版都是如此：这里没有可以退回去的运行期值，所以这样的图不是一个可以容忍的泄漏，而是根本编译不出来

这也是它不收任何输入、也没有卡片字段的原因。能给它的任何东西，都是给一个已经只有一个答案的问题再加一个输入

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `appTag` | out · data | `string` | 变体的名字。完整正式版是 `main` |

### Is DLC Installed

`blueprint.game.isDlcInstalled` · Pure

某一份额外内容此刻是不是就在运行中的游戏旁边。

这个问题问的刻意是**在不在**，而不是有没有买。DLC 是作为一个文件出现在游戏旁边的，是玩家从哪里买的、哪里就把它放过来；它在不在，是这个包看得见的事实。玩家是否**拥有**它，是商店的事实、是商店插件的节点去回答的——而拿它来挡内容，会在玩家离线时把他买过的章节夺走，问「在不在」永远不会

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `isInstalled` | out · data | `boolean` | 没选 DLC 时为 `false`，于是连了一半的菜单行保持隐藏 |

**卡片字段**

| 字段 | 含义 |
| --- | --- |
| `DLC` | 项目声明的某一个 DLC |

## 在版本之间携带进度

试玩版和完整版是两个独立的包、两个独立的 app id，因此各有各的用户数据目录，资产保护密钥也刻意不同：正式版读不了试玩版的存档文件，也不该去读。这两个节点就是那条确实跨过去的通道，而且它刻意不是一个存档文件——它是每个作品一份的普通 JSON 文档，装着项目级变量、玩家走到哪里，以及他见过哪些场景

那份文档放在哪里由执行这件事的宿主决定，绝不由图决定：桌面宿主把这件事交给自己的主进程，Web 导出则拒绝，因为一个网页没有共享文件可写。所以两个节点都带一条失败分支和一个原因，图必须听得懂「不行」

### Export Progress

`blueprint.game.progress.export` · Latent

把这一局持有的一切写进该作品的进度文档。它不收任何输入：跨过去的是项目声明的那一整套，而不是某一张图替**另一个版本**必须能读的文档挑出来的一个子集

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `in` | in · exec | — | |
| `next` | out · exec | — | |
| `failed` | out · exec | — | 写不了的宿主、没有进度键的构建，或者磁盘拒绝了 |
| `error` | out · data | `string` | 是其中哪一种 |

### Import Progress

`blueprint.game.progress.import` · Latent

读那份文档，并把它持有的内容应用到运行中的游戏上。

**它不会跳转。** `Scene` 只是作为数据交出来，节点就停在这里。启动剧情的是 `Start Game`，而标题界面通常还有别的事要先做——一次淡出、一次确认、一个章节选择。一个自己就跳过去的节点，会成为绕开这一切的第二种开始剧情的方式

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `in` | in · exec | — | |
| `found` | out · exec | — | |
| `missing` | out · exec | — | 没有人导出过 |
| `failed` | out · exec | — | 读不出来的文档 |
| `sceneId` | out · data | `string` | 玩家走到了哪里。文档没有锚点时为空。接给 `Start Game` |
| `error` | out · data | `string` | |

三条出路，因为作者对三者的回答不一样。`Missing` 是所有从没导出过的人的常态——全新安装、直接买完整版的玩家——它通向「开始新游戏」，而不是一句道歉；把它并进 `Failed` 会让每一个第一次玩的人先看到一个错误。`Failed` 是读不出来的文档：更新的构建写的、属于别的作品的，或者已经损坏

## 存储

### Check Storage Durability

`blueprint.game.storageDurability` · Latent

这个构建写下去的东西留不留得住——关于玩家存档，唯一一件宿主知道而游戏自己推不出来的事。

打包的桌面游戏把文件放在没人会去回收的用户数据目录里。Web 导出则是浏览器的客人：一个没有拿到持久化存储授权的站点，可能在存储压力下被整体清除，存档、持久变量和已读记录一起没。页面在加载时申请那份授权，而这里给出的就是它得到的答复

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `in` | in · exec | — | |
| `durable` | out · exec | — | |
| `evictable` | out · exec | — | |
| `unknown` | out · exec | — | |

三条分支，因为它们通向三种不同的措辞。`Evictable` 是「这个浏览器可能会删掉存档」；`Unknown` 是浏览器不肯说，而在真相是后者时告诉玩家前者，是一个没人许下过的承诺。这里不替你做任何决定——存储可能被回收的页面，仍然是一个能把游戏打通的页面，而玩家要不要听说这件事，属于作品本身
