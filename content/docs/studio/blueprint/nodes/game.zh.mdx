Game 分类是蓝图与运行中剧情之间的接缝。这里的一切都在和活着的 NarraLeaf 运行时说话：游玩本身、屏幕上的对话、玩家的偏好、项目的本地存档，以及对话历史。标题画面、设置画面、存读档网格和回顾界面，都由本页的节点搭起来。

<Callout type="warn">
本页每一个节点都需要运行中的游戏。编辑器画布没有游戏——放在那里的 Game 节点会以`Host API unavailable (use Dev Mode)`失败，读取它的 Blueprint Value 预览为空。这些行为一律在开发模式中验证。
</Callout>

## 约定

- **要么 pure，要么 latent，没有中间态。** 二十个取值节点是`Pure`，可用于`event`、`function`、`macro` 图，也可以支撑 Blueprint Value。其余三十三个是`Latent`，因此只能用于`event`和`macro`——latent 节点在`function`图里没有地方安放一个待定的结果。
- **有 Host API 不等于有一局游戏。** `List Saves`、`Get Save Metadata`、`Get Save Time`、`Get Save Preview`、`Delete Save`、`List Auto Saves`和`Get Latest Auto Save`读取项目的存档库，在两局游戏之间、没有游戏运行时也能工作。凡是序列化、反序列化或指挥活动游戏的节点都需要一局游戏，没有就失败。
- **状态取值节点会降级，偏好取值节点不会。** `Is In Game`、`Is Game Overlay`、`Get Nametag`、`Get Speaker Avatar`、`Get Choice Count`、`Get Notifications`、`Is NVL Mode`和`Is Text Read`在什么都没有播放时给出中性值——`false`、`null`、`0`、空数组——正因如此，同一个共享 Page 才能按它们分支。十二个偏好取值节点读的是活动`GamePreference`，没有游戏就失败。
- **偏好初始化挂在`On Game Ready`上，不要挂`App Boot`。** `App Boot`可能早于`LiveGame`存在就运行，而没有活动游戏的偏好写入会失败。参见[事件](/zh/docs/studio/blueprint/nodes/events)。
- **存档 id 会被校验。** id 会被 trim，不能为空，不能含路径分隔符或控制字符。磁盘上的文件名由 id 的哈希派生；你选的 id 保存在记录的 metadata 里。

## 游玩

`Start Game`和`Quit Game`是尾节点：它们把控制权交给运行时，没有执行出口，所以后续该发生的事属于剧情，或者属于它们打开的那个 Page。

### Start Game

`blueprint.game.startStory` · Latent

Start Game（开始游戏）启动节点卡片上选中的 Story 与 Scene，并切换到游戏舞台。游戏首帧就绪后，当前 Page 栈会被藏到游戏下面，因此之后调用`Go Page`是把目标叠加在舞台之上，而不是替换舞台。

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `in` | in · exec | — | |

**卡片字段**

| 字段 | 含义 |
| --- | --- |
| `Story` | 要运行的剧本。必填。 |
| `Scene` | 要进入的场景。选项按选中的 Story 过滤。必填。 |

### Quit Game

`blueprint.game.quit` · Latent

Quit Game（退出游戏）结束当前游玩，并打开卡片上选中的 Page。一次调用做完全部事情：丢弃活动游戏与会话、取消仍在等待的启动请求、清空对话名牌、恢复普通 Page 显示，然后导航——不需要再接一个`Go Page`。

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `in` | in · exec | — | |

**卡片字段**

| 字段 | 含义 |
| --- | --- |
| `Page` | 游戏结束后打开的 [Surface](/zh/docs/studio/blueprint/surfaces)。必填。 |

### Is In Game

`blueprint.game.isInGame` · Pure

Is In Game（是否在游戏中）：只要游戏舞台可见且存在会话就为 `true`——即使上面开着 Page 叠层也一样。普通 Page 预览、首次`Start Game`之前、`Quit Game`之后为 `false`。

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `isInGame` | out · data | `boolean` | |

### Is Game Overlay

`blueprint.game.isGameOverlay` · Pure

Is Game Overlay（是否为游戏覆盖层）：当前 Surface 实例是否以游戏之上的 UI 叠层身份运行。`Start Game`或`Load Save`之后用`Go Page`打开的 Page 返回 `true`，内建的游戏 UI Surface（例如对话槽位）也返回 `true`；通过`nl.frame`嵌入的子 Page 继承父级的答案。普通应用 Page、Page 预览，以及`Quit Game`打开的那个 Page 返回 `false`。

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `isGameOverlay` | out · data | `boolean` | |

答案在 Page 实例创建时就锁定，所以正在播放退出动画的暂停菜单仍返回 `true`，哪怕`Quit Game`已经开始拆掉会话。要问运行时是否还在，用`Is In Game`；要问一个共享 Page 该显示成什么样，用这个。

## 对话

对话文本、说话人或完成状态变化时，绑定到对话的元素都会被 flush，因此在`On Flush`里读取下列取值节点的控件会随剧情推进保持最新，而不需要重新挂载。

### Get Nametag

`blueprint.game.getNametag` · Pure

Get Nametag（获取名牌）：当前说话人的名字。旁白、没有说话人、说话人名为空或全是空白时为 `null`。

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `nametag` | out · data | `string` | 没有说话人时为 `null`。 |

默认对话模板用普通`nl.text`做名牌，并在该控件自己的蓝图里驱动它——`Init`与`On Flush`接到`Get Nametag`，再用一次判空控制文本和不透明度。这里没有任何特殊的名牌控件。

`blueprint.game.getSpeakerAvatar` · Pure

## 偏好

下面每一对都对应活动游戏上引擎`GamePreference`的一个字段。取值节点是 pure 的，可安全放进 Blueprint Value；设值节点是 latent 的，写入前先校验——值不合法时节点失败，而不是被夹到范围内。`showDialog`在这里没有配对节点，由`Show Dialog`、`Hide Dialog`和`Toggle Dialog Display`覆盖。

这二十四个节点在没有活动游戏运行时都会失败。要为新一局游戏播种偏好，把设值节点接在`On Game Ready`上——它在`LiveGame`已存在之后、第一句剧情之前运行。

## 存档

存档是项目本地的，以你自己选的 id 为键。同一个 id 写第二次就是覆盖。

<Callout type="warn">
`List Saves`只返回玩家存档。自动存档住在保留 id 命名空间里——`@autosave.<n>`——由`List Auto Saves`列出；两个集合永不重叠。这是刻意的：基于`List Saves`做的存读档网格从不需要过滤掉 Studio 自己的簿记条目，自动存档界面也从不需要藏起玩家的存档位。在别的地方，自动存档 id 就是一个普通存档 id，可以原样喂给`Load Save`、`Get Save Preview`、`Get Save Metadata`和`Delete Save`。
</Callout>

### Save Game

`blueprint.game.save.write` · Latent

Save Game（保存游戏）把活动游戏序列化进项目的本地存档库。`Capture`为 `true` 时还会截一张舞台 PNG 存为该存档的预览图；截图失败会被上报，但不会连累存档本身。

尾节点，没有执行出口。存档缺失、损坏，或没有活动游戏运行时都会失败。

### Get Save Time

`blueprint.game.save.getTime` · Latent

Get Save Time（获取存档时间）读取一个槽位是什么时候写的。存档库会给每条写入的记录盖时间戳，这个节点把它们读回来——存档界面不用再把时间写进自己的 `metadata` 并保持同步。

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `in` | in · exec | — | |
| `next` | out · exec | — | |
| `id` | in · data | `string` | 支持卡片字面量。 |
| `savedAt` | out · data | `float` | 槽位最后一次写入的时间。存档不存在时为 `0`。 |
| `createdAt` | out · data | `float` | 槽位首次写入的时间。存档不存在时为 `0`。 |
| `exists` | out · data | `boolean` | |

两个时间都是 1970 年 1 月 1 日 UTC 以来的毫秒数——与 `List Auto Saves` 报告的单位相同，[Time](/zh/docs/studio/blueprint/nodes/time) 分类的每个节点都接受它。

<Callout type="warn">
空槽位要看 `exists`。存档不存在时 `savedAt` 为 `0`，而 `0` 同时也是 1970 年的一个真实时刻。
</Callout>

## 自动存档

自动存档按项目配置，位置在**项目 → 游戏**：开关、间隔，以及环保留多少个槽位。它随项目一起出货。图里不排任何日程——调度器自己在跑，并且只在剧情自上次写入以来推进过时才写，所以间隔再短，闲置的游戏也不产生开销。写入沿环轮转，最旧的先被覆盖，因此一直自动存档也只占用有界的磁盘。

### Auto Save

`blueprint.game.autoSave.write` · Latent

Auto Save（自动保存）立刻写一次自动存档，落在调度器所用的同一个环的下一个槽位，并附带截图。它同时忽略开关设置和「剧情已推进」这道门——这一次是作者显式要求的——写完之后与定时产生的自动存档没有任何区别。执行继续：自动存档不会打断正在进行的游玩。

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `in` | in · exec | — | |
| `next` | out · exec | — | |

没有正在运行的游戏时会失败，与其它存档写入节点一致。

### List Auto Saves

`blueprint.game.autoSave.list` · Latent

List Auto Saves（列出自动存档）列出保留命名空间里的全部自动存档，**从新到旧**。调小环容量后遗留的槽位仍会被列出——改配置不该让玩家的存档凭空消失——只是不会再被轮转覆盖。

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `in` | in · exec | — | |
| `next` | out · exec | — | |
| `entries` | out · data | `array` | 对象数组，字段见下。 |
| `count` | out · data | `integer` | |

**条目字段**

| 字段 | 含义 |
| --- | --- |
| `id` | 存档 id。可直接喂给`Load Save`、`Get Save Preview`、`Get Save Metadata`和`Delete Save`。 |
| `slot` | 在环内的槽位序号。 |
| `timestamp` | 最后写入时间，Unix 毫秒。 |
| `createdAt` | 首次写入时间，Unix 毫秒。 |
| `metadata` | 写入方附带的内容，没有时为 `null`。 |

条目带的是 **id，而不是序列化后的存档**：`SavedGameData` 那样的数据块在图里毫无用处，而 id 能直接接进既有的存档节点。

## 历史

对话历史——也就是回顾记录——是引擎自己保存的、已经过去的台词与选择菜单，并且可以回放到其中任意一点。

### Get History

`blueprint.game.history.get` · Latent

Get History（获取历史）把回顾记录作为一个扁平数组给出，从旧到新，可以直接绑到列表控件上。

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `in` | in · exec | — | |
| `next` | out · exec | — | |
| `entries` | out · data | `array` | 对象数组，字段见下。 |
| `count` | out · data | `integer` | |

**条目字段**

| 字段 | 含义 |
| --- | --- |
| `id` | 历史 token。喂给`Restore From History`。 |
| `type` | 台词为 `"say"`，已确定的选择为 `"menu"`。 |
| `text` | 句子文本，或菜单的提示语。源里没有时为空字符串。 |
| `character` | say 条目的说话人名牌；菜单与旁白为 `null`。 |
| `voice` | say 条目的语音 id；没有时为 `null`。 |
| `selected` | menu 条目里被选中的选项文本；say 条目与未确定的菜单为 `null`。 |
| `isPending` | 当前还在屏幕上、尚未提交的那一条为 true。 |

没有游戏运行时为空数组。

### Restore From History

`blueprint.game.history.restore` · Latent

Restore From History（从历史恢复）把游戏跳回某一条回顾记录，丢弃它之后的一切。引擎允许时按该条目的快照恢复，否则退回到 undo——正因如此，它在刚刚读档、undo 栈是空的游戏上依然有效。

| `in` | in · exec | — | |
| `next` | out · exec | — | |
| `id` | in · data | `string` | 卡片上标为 **Entry Id**。必填；空 id 会让节点失败。支持卡片字面量。 |

没有活动游戏运行时会失败。

## 已读文本

一句话在文字显示完毕的那一刻被标为已读——ADV 下是打字结束，NVL 下是等待推进。记录以消息稳定的文本 id 为键，因此能挺过剧本改动，并且跨越项目里的每一个 Story；它按项目级持久化，与任何存档文件无关。「只跳过已读文本」这类选项就建立在它之上。

### Is Text Read

`blueprint.game.isTextRead` · Pure

Is Text Read（文本是否已读）：当且仅当屏幕上有一句对话**并且**它的消息被标为已读时为 `true`——要么早先的游玩里见过，要么刚刚显示完毕。没有台词在显示时为 `false`。

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `isRead` | out · data | `boolean` | |

### Clear Text Read

`blueprint.game.clearTextRead` · Latent

Clear Text Read（清除已读记录）清空已读记录，内存与磁盘一起清，覆盖项目里的每一个 Story。仍在屏幕上、且已经显示完毕的那一句会立刻重新标为已读——玩家正看着它。

| --- | --- | --- | --- |
| `in` | in · exec | — | |
| `next` | out · exec | — | |
