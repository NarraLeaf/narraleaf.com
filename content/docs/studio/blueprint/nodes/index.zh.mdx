内置目录共 655 个节点，分布在 28 个分类中。分类就是你在创建浮窗里导航时看到的分组，因此这些页面的组织方式与编辑器一致。Studio 内置插件添加的节点单独列在 [内置插件](/zh/docs/studio/blueprint/nodes/built-in-plugins) 下

## 如何阅读一个节点

每个节点写成这样：

> **Delay**
>
> `blueprint.flow.delay` · Latent

标题下第一行是节点的 **type id**——存进文档的值，也是你从插件注册时要用的值。其后是该节点为真的标记：

| 标记 | 含义 |
| --- | --- |
| `Pure` | 无副作用，没有执行引脚。有东西读取它的输出时才计算，也是能进入 Blueprint Value 的条件之一|
| `Latent` | 会挂起执行直到完成。Blueprint Value（`Call Fn` 除外）、内联故事值和分支条件都不提供它|

打开**设置 → 常规 → 开发者选项**后，创建浮窗还会在每个节点那一行的右侧显示它的 type id

`Pure` 本身**并不**意味着该节点能在 [Blueprint Value](/zh/docs/studio/blueprint) 里使用。那是另一条更窄的规则：节点必须同时是纯节点、非 latent，且属于允许的分类（Data、List、Math、Time、Text、Slider、Displayable、Element、Game、Localization），外加一小串特例（`Init` 与 `On Flush` 事件头、除 `Skip Delay` 以外非 latent 的 Flow、本地变量读写、`Memo`、`Call Fn`、注释、`Return Value`、`Get Saved Var`，以及五个 Page 读取节点：`Get Page Props`、`Get Page Param` 和三个 `Is Surface …`）。scope 限定为 `widgetMain` 的 Self 节点无论标记如何都被排除；在 Blueprint Value 里要触及某个控件，走 `Element` 字面量加 Element 分类的读取节点

然后是引脚表：

| 引脚 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- |
| `in` | in · exec | — | |
| `duration` | in · data | `float` | 秒。可在节点卡上直接填字面量|
| `completed` | out · exec | — | 等待结束后触发|
| `token` | out · data | `Timer` | 接给 `Skip Delay` 可提前结束等待|

执行引脚传递执行，数据引脚传递值。`array<struct:nl.ending>` 这样的类型是结局的数组，在卡片上显示为**结局列表**；各种结构见[结构](/zh/docs/studio/blueprint/nodes/data#structs)。*可在节点卡上直接填字面量*意味着你可以在卡片上输入该值，而不必拉一条连线。部分节点带**动态引脚**，由所选变量、所选 fn 的签名或你追加的分支推导出来。这类引脚以文字说明，因为没有固定的表可列

## 可用性

节点出现在本目录里，不代表它会出现在你的创建浮窗中。有以下几层过滤：

- **Blueprint Value。** Blueprint Value 只提供上面那条规则允许的节点
- **内联故事值。** 内联故事值和分支条件拒绝 latent 节点
- **宿主与控件能力。** Self 节点只在具备该能力的控件蓝图里出现；Text 控件的蓝图里不会提供 `Set Slider Value`
- **已存在的绑定。** Element 节点只有在图中已有可兼容的 `Element`、`Element Flush` 或 `Element Click` 节点可供连接时才会出现
- **列表项上下文。** `Get List Item Index`、`Get List Item Key`、`Get List Item Count` 与 `Get List Item Props` 读取元素所渲染的那一项，所以只在可能有某一行处于作用域的地方出现，例如 List 项模板内元素的蓝图。`Get Field` 在所有蓝图中都提供，在这些位置不连接**对象**时读取当前行
- **Story Action 蓝图。** 由故事行调用的蓝图不提供任何驱动运行中游戏或其界面的节点：没有 App、Localization、Network、Sound、Voice 节点，Game 分类也几乎全部不提供

<Callout type="info">
存在多个兼容来源时，创建浮窗只列出该节点一次。若来源恰好唯一，添加时会自动连上；若有多个，则保留目标输入由你选择
</Callout>

## 同类节点 [#node-families]

有些节点是同一种操作的不同形式，例如六个比较节点、四个按键事件 Head。创建浮窗把这样的每一组节点作为一组同类节点列出

- **浏览。** **搜索节点**框为空时，一组同类节点只占一行：上面是组名，下面是分类与节点数，例如*数学 · 6 个节点*。鼠标悬停在这一行上会列出组内的节点。选择这一行会添加组内的第一个节点，即下表中列在最前面的那个。Element 节点也这样合并，每个已绑定的元素各有一行
- **搜索。** 搜索时，组内每个节点各占一行。输入`>`或`大于`都会找到`Greater Than`；输入组名（例如`比较`）会列出组内全部节点
- **切换已放置的节点。** 节点属于某一组时，卡片标题旁有一个 ▾ 按钮（**切换为同类的其他节点**）。点击后列出组内当前蓝图能放置的节点，当前节点带勾选标记。选择另一个节点，卡片会在原位置变成该节点

卡片切换为组内另一个节点时：

- 新节点有对应的引脚且该引脚接受这条连线时，连线保持连接。连到`Set BGM Volume`的`bgmVolume`的连线，在卡片变成`Set SFX Volume`后改连到`soundVolume`
- 新节点无法接受的连线会被移除
- 新节点有相同的设置时，设置保留：`Integer`常量上的`3`在卡片变成`Float`后仍是`3`。其他设置会被移除（例如`On Key Down`变成`Any Key Down`时原先选定的按键），新节点的设置从默认值开始
- 卡片上填写的值，在对应引脚接受同一类型的值时移到该引脚上，否则被移除
- **Ctrl+Z**（macOS 上为 **Cmd+Z**）一步恢复原来的节点及其连线和值

同类节点只影响创建浮窗中节点的列出方式。每个节点仍保留自己的名称和 type id，已有的图不受影响
