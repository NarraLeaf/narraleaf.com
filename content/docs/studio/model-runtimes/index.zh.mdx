视觉小说里的大多数角色都是图片：一张成品差分对应一个姿态，或者一叠按标签切换的图层。这两种 Studio 自己就能画。

而 **Live2D** 或 **Spine** 角色不是图片。它是一个带骨骼绑定、自带动画系统的模型，负责绘制它的东西叫 *运行时*——由模型格式的厂商编写的渲染器。Studio 不包含它们中的任何一个，也绝不代你下载。运行时由你提供，每个工程一次；之后 Studio 就把这个角色当作普通角色对待：它站在脚本安排的位置、随摄像机运动、被剧本摆姿势、并在读档后正确复原。

## 为什么由你提供

这是许可协议的**必然结果**，不是缺失的功能。

Studio 是公开源码的免费软件。这些渲染器所用的许可协议不允许这个组合——Live2D 的协议**禁止**让「源码分发且可被第三方修改」的许可覆盖它的代码，而 Spine 的协议要求**集成**运行时的一方持有付费的 Editor 授权。所以 NarraLeaf 不能把任何一个渲染器放进 Studio；而**代你去取它就等于分发它**，那是同一个问题换了张面孔。

Studio 能做的是渲染器周围的一切：

| Studio 负责 | 你负责 |
| --- | --- |
| 拥有角色本身：站位、图层、变换、不透明度、存档条目 | 从厂商处获取运行时，并在此过程中接受其许可协议 |
| 把运行时安装进你的工程并校验它 | 承担你所发行游戏的许可义务 |
| 读取模型，填出它的动作、表情与参数 | 提供模型本身 |
| 把运行时打包进你构建的游戏 | |

实际效果是：**分发渲染器的人是你**，在你构建的游戏里。Ren'Py 与 TyranoScript 接 Live2D 用的是同一套安排，这也是为什么没有任何免费引擎捆绑 Cubism Core。

<Callout type="warn">
    商业发行前请阅读厂商的条款。Studio 在安装时会向你展示要点，但它不能替代厂商自己的许可协议——而 NarraLeaf 并非该协议的当事方。
</Callout>

## 运行时放在哪里

每个运行时一个文件夹，位于你的工程内：

<Files>
    <Folder name="runtimes" defaultOpen>
        <Folder name="puppet" defaultOpen>
            <Folder name="live2d" defaultOpen>
                <File name="index.js" />
                <File name="README.md" />
                <Folder name="licenses" />
            </Folder>
            <Folder name="spine">
                <File name="index.js" />
            </Folder>
        </Folder>
    </Folder>
</Files>

文件夹名**就是**运行时的名字——角色引用的是它，引擎在运行时解析的也是它。`index.js` 是唯一必需的文件；没有它的文件夹会被报告为「安装不完整」，并在打包时被跳过，而不是带着残缺出货。

这是**工程内容，不是缓存**。它应当和你的素材一起进版本控制，并会被复制进你构建的每个游戏。Live2D 的那个文件约一兆，因为渲染器就编译在里面。

## 管理运行时

**项目 → 运行时** 会列出 Studio 认识的每个运行时，以及它在你工程里发现的每一个，并给出状态：

| 状态 | 含义 |
| --- | --- |
| **已安装** | `index.js` 在，且能加载。 |
| **已安装但不完整** | 文件夹在，但没有 `index.js`——半成品安装，或者解错了东西进去。 |
| **本工程未安装** | 什么都没有。对不使用模型的工程来说这是常态。 |

同一套安装流程也可以从需要它的角色处进入，通常你就是在那里第一次遇到它的。

<Callout type="info">
    在装有运行时的机器上创建的角色，到没装的机器上依然引用那个名字。角色**没有损坏**，Studio 也不会改写它——它会报告**本工程未安装**并提供安装入口。刚 clone 下来的工程就是这个状态。
</Callout>

## 创建角色

在**创建角色时**选择运行时，而不是事后再改：**新建角色 → Live2D Cubism / Spine / 自定义运行时**。kind 在创建时就固定，因为三种角色 kind 之间没有共享数据，切换会丢弃前一种持有的内容。

新建的模型角色会显示两件待办：

<Steps>
<Step>

### 绘制运行时

这个角色需要的运行时在本机装了没有。没装的话，**安装** 会打开对应产品的流程。

</Step>
<Step>

### 模型

模型本身，作为工程资产。模型是一个**目录**——它的清单文件，加上清单所指名的贴图、动作与物理——所以它按目录导入，而不是按文件。如果工程里还没有任何模型资产，这一行会直接提供导入入口。

</Step>
</Steps>

只有这两件都齐备之后，检视面板的其余部分才会出现，因为其余部分是**从模型读出来的**：Studio 通过你安装的运行时挂载模型并询问它包含什么。动作、表情、皮肤与参数会变成可供挑选的列表，上方的预览则会以静止姿态画出真实的模型。

<Callout type="info">
    运行时可以选择不回答。如果它不报告模型内容，每个控件都会退化为文本框、由你自己输入名字——除此之外没有任何变化。
</Callout>

## 在剧本中摆姿势

除了普通角色能用的一切，模型角色还接受四条命令：

| 命令 | 别名 | 设置 |
| --- | --- | --- |
| `/motion Doll run` | `/anim` | 动画。不给名字则清除——模型回到静止。 |
| `/face Doll smile` | `/expr`、`/expression` | 表情。与切换图片角色姿态的是同一条命令。 |
| `/skin Doll winter` | `/costume` | 皮肤，用于支持皮肤的格式。 |
| `/param Doll ParamAngleX 12` | | 模型的某个数值参数。 |

每个名字都从模型报告的内容中给出，所以你是在列表里挑，而不是靠记字符串。

## 引擎看到的是什么

在底层，模型角色会被编译成引擎的 [木偶 (Puppet)](/zh/docs/narraleaf-react/core/elements/puppet) 元素——一个由引擎拥有、由后端绘制内部的盒子。Studio 的职责是安装那个后端并交给它一个模型；关于盒子的一切是引擎的职责。如果你要编写运行时，或者想理解运行时被要求做什么，那一页就是契约。
