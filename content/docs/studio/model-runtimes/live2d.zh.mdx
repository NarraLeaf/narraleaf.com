Live2D Cubism 通过**变形**一张 2D 插画来做动画——画本身保持平面，由绑定来让它动。一个 Cubism 模型是一个目录：`.model3.json` 清单、`.moc3` 绑定、贴图页，以及动作、表情、物理与姿态各自的文件。

Studio 安装 Cubism 运行时的方式是**在你的机器上编译它**，用你提供的 SDK。这不是为了方便，而是**唯一存在的路径**。如果你还没读过 [模型运行时](/zh/docs/studio/model-runtimes)，先读它——那里解释了为什么 Studio 不自带渲染器。

## 开始之前

<Callout type="warn">
    **Live2D Cubism 的授权方是 Live2D Inc.，不是 NarraLeaf。** 你在从 Live2D 下载时接受 Cubism SDK 许可协议，并且在你构建的游戏中，分发它的人是你。免费使用是有边界的：超过 Live2D 公布的年营收阈值后，商业发行需要另行向他们申请 **Publication License**。发行前请在 [Live2D 的许可页面](https://www.live2d.com/en/sdk/license/) 核对现行条款——NarraLeaf 并非该协议的当事方，无法就其向你授予任何权利。
</Callout>

你需要的是 **Cubism SDK for Web**——不是 Cubism Editor，也不是 SDK for Native。它是单个 `.zip`，约 20 MB，来自 [Live2D 的下载页](https://www.live2d.com/en/sdk/download/web/)。**保持下载时的原样，不要解压**；Studio 直接读取压缩包。

## 安装

<Steps>
<Step>

### 打开安装器

要么从角色进入——用 **新建角色 → Live2D Cubism** 建一个，然后点它*绘制运行时*那行的 **安装**——要么走 **项目 → 运行时 → Live2D Cubism → 安装**。

</Step>
<Step>

### 阅读条款

对话框会说明你要同意什么，并给出 Live2D 下载页的链接。Studio 不代取 SDK：下载页正是你接受 Live2D 许可协议的地方，所以必须由你亲自去。勾选确认后继续。

</Step>
<Step>

### 选择压缩包

**选择 SDK 压缩包**，挑那个 `.zip`。Studio 会检查它确实是 SDK 包——它会找 `cubism-info.yml`、Core、Framework 源码与 shader——如果你选错了文件，它会告诉你这个压缩包**实际**装的是什么。

</Step>
<Step>

### Studio 构建运行时

它解出 Core、Framework 与 shader 源码，连同 Studio 自己的适配器代码一起编译，把结果写进你的工程。这需要一两秒。完成后对话框会报告它是由哪个 SDK 版本构建的。

</Step>
</Steps>

你会得到：

<Files>
    <Folder name="runtimes/puppet/live2d" defaultOpen>
        <File name="index.js" />
        <File name="README.md" />
        <Folder name="licenses" />
    </Folder>
</Files>

`index.js` 是生成的，约一兆——渲染器就编译在里面。`licenses/` 保存了 Live2D 自己的许可文本，与你压缩包里的原样一致；`README.md` 记录了产出该文件的 SDK 版本。**这些都要提交**：它们是工程的一部分，且你构建的每个游戏都会带着它们。

<Callout type="info">
    **重新构建**——换更新的 SDK，或者 Studio 更新改进了适配器——直接再装一次覆盖即可。工程里没有任何东西引用那个文件的内容，只引用 `live2d` 这个名字，所以角色不受影响。
</Callout>

## 加入模型

Cubism 模型是一个目录，所以按目录导入。Studio 会找到里面的 `.model3.json` 并把它当作入口；其余一切——贴图、动作、物理——都相对它解析，与清单指名的方式完全一致。

<Steps>
<Step>

### 导入模型目录

在角色的 **模型** 那行，如果工程里已有模型就直接选，没有就直接导入目录。**目录必须是含 `.model3.json` 的那一层**。

</Step>
<Step>

### 让 Studio 读它

运行时与模型都到位后，Studio 会挂载模型并询问它有什么。预览会画出它，下面的字段随之填好。

</Step>
</Steps>

## Live2D 角色支持什么

模型读出来之后，这些内容来自模型而不是来自你：

| 字段 | 填入 |
| --- | --- |
| **动作** | 清单里的每个动作，命名为 `<组>_<序号>`——`Idle_0`、`Idle_1`、`TapBody_0`。裸的组名（`Idle`）也可用，表示该组第一条。清空该字段让模型停在中性姿态。 |
| **表情** | 清单里每个表情的 `Name`。 |
| **皮肤** | 空。Cubism 没有皮肤这个概念，Studio 如实报告而不去发明一个——给 Live2D 角色设的皮肤会被忽略并给出警告。 |
| **参数** | 绑定暴露的每个 Cubism 参数，带真实的最小值、最大值与默认值——`ParamAngleX`、`ParamEyeLOpen` 等等。 |

另有四个参数来自适配器而非模型，它们带前缀，因此不会与绑定自己的参数冲突：

| 参数 | 范围 | 作用 |
| --- | --- | --- |
| `@scale` | 0.05 – 4 | 在盒子内缩放模型。 |
| `@x`、`@y` | −2 – 2 | 在盒子内微调位置。 |
| `@timeScale` | 0 – 4 | 加快或减慢它的动画。`0` 冻结。 |

**没有应用任何动作的模型并不是静止的**：Cubism 的呼吸与眨眼独立于动作轨道运行，所以待机角色看起来依然是活的。

### 运行时选项

**选项** 映射会原样交给运行时。Live2D 适配器读取：

| 键 | 作用 |
| --- | --- |
| `scale`、`offsetX`、`offsetY` | `@scale` / `@x` / `@y` 的初始值。 |
| `diagnostics` | `true` 打开绘制报告：首帧之后，适配器统计它实际画出的像素并记录下来。模型不出现时很有用——它能区分**什么都没画**和**画出了一个纯白剪影**（后者是贴图上传被拒的特征）。默认关闭，因为它每个角色都要付一次整画布读取的代价。 |

## 如果模型没出现

适配器会记录它加载过什么，并在挂载失败时把这条轨迹交给控制台，所以先从那里看——有用的信息通常是清单里**哪一个**文件出了问题，而不是最后那条报错。

| 现象 | 通常是 |
| --- | --- |
| 「本工程未安装该运行时」 | 本机没装。刚 clone，或这个工程从来没装过。 |
| 「无法绘制该模型」并附带原因 | 原因就是那个具体原因——入口文件缺失、包读不了，或运行时不在了。 |
| 游戏里角色是个空盒子 | 角色上的 backend 名与任何已安装的运行时都不匹配。查 **项目 → 运行时**。 |
| 模型画成纯白色块 | 贴图上传被拒了。打开 `diagnostics` 看控制台。 |
| 什么都没有，也没有报错 | 确认你导入的是含 `.model3.json` 的那个目录，而不是它的上一层。 |
