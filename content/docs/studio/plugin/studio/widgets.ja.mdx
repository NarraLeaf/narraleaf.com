title: widgets

---

`app.services.widgets` は**ウィジェットモジュール**を登録します。これはカスタムウィジェット型のエディター側半分です。1 つのモジュールが、そのウィジェットのキャンバス上のレンダリング、プロパティ検査パネル、ドッカーバーのコントロールを担います。同じ型のゲーム側レンダラーは、runtime エントリーから [`app.game.widgets`](/ja/docs/studio/plugin/api-reference) を使って別途登録します。

各 `type` は `contributes.widgets` に、あなたのプラグイン id を前置して宣言されていなければなりません。

## メソッド

| メソッド | シグネチャ | 備考 |
| --- | --- | --- |
| `register` | `(module: PluginWidgetModule) => PluginCleanup` | |
| `registerMany` | `(modules: PluginWidgetModule[]) => PluginCleanup` | |
| `get` | `(type: string) => PluginWidgetTypeInfo \| undefined` | |
| `list` | `() => PluginWidgetTypeInfo[]` | |
| `has` | `(type: string) => boolean` | |

`get` と `list` が返すのはウィジェット型の説明であり、そのモジュールではありません。`PluginWidgetTypeInfo` は `{ type, displayName, extends?, ownerPluginId? }` で、Studio 自身のウィジェットには `ownerPluginId` がありません。

## PluginWidgetModule

エディターのコールバックが受け取るのは、インターフェースドキュメントを読み要素を書き込む `documentService` と、ドッカーバーの場合はさらに選択を読み取り移動する `stateService` です。それらからワークスペースのほかのものには到達できません。

| メンバー | 型 | 備考 |
| --- | --- | --- |
| `type` | `string` | 一意な型 id。例:`"yourname.plugin.badge"`。 |
| `extends` | `string` | 任意。このウィジェットが特化するウィジェット型。 |
| `displayName` | `string` | 要素パレットのオーバーフローメニューに、プラグイン名と並んで表示されます。 |
| `icon` | `LucideIcon` | パレットのアイコン。 |
| `createDefaultElement` | `() => Partial<UIElement>` | ユーザーがこのウィジェットを追加したときに挿入される要素。システムの既定値とマージされます。 |
| `render` | `(props: RuntimeWidgetRendererProps) => ReactElement \| null` | キャンバス上のレンダリング。ゲーム側レンダラーと同じ props を受け取るため、1 つの関数で両方のエントリーをまかなえます。[レンダリングの props](#render-props) を参照してください。 |
| `logicApi` | `WidgetLogicApi` | 任意。ウィジェットのブループリントイベントを宣言します。[ウィジェットのイベント](#widget-events)を参照してください。 |
| `acceptsChildren` | `boolean` | 任意。Container と同じように、作者がほかの要素をこのウィジェットの中に置けるようにします。`render` はそれらを描画済みの `children` として受け取ります。 |
| `partSlots` | `string[]` | 任意。ウィジェットが自分で作るパーツのスロット名です。パーツを持つウィジェットはそれらだけを収め、ほかには何も収めません。Slider がトラックとハンドルを収めるのと同じです。`createDefaultChildElements` が作る各パーツは、`extra: { partSlot: "<slot>" }` で自分が埋めるスロットを示します。パーツを持つウィジェットは `acceptsChildren` を無視します。 |
| `createInspector` | `(context) => PropertyEditorSchema \| undefined` | 任意。共通のレイアウトフィールドのあとに追加されるフィールド。 |
| `createDefaultChildElements` | `(context) => { elementPatch?, children }` | 任意。ウィジェットと一緒に作成される構造的な子要素。 |
| `listEditorStates` | `(element) => { id: string \| null; name: string }[]` | 任意。キャンバス上でウィジェットを表示できる状態。`id: null` が通常の状態です。 |
| `createDockerBarItems` | `(context) => DockerBarItem[]` | 任意。ウィジェットが選択されたときに表示されるコントロール。 |
| `createContextMenuItems`、`createFloatingToolbarItems`、`createMultiSelectDockerBarItems`、`createLayoutSizeField` | | 任意のエディター機能。 |

モジュールに `registerBlueprintNodes` はありません。ウィジェットのノードは [`app.services.blueprintNodes`](/ja/docs/studio/plugin/studio/blueprint-nodes) で登録してください。

```ts
app.services.widgets.register(myWidgetModule);
```

<Callout type="info">
公開したゲームでレンダリングされなければならないウィジェットには、両方の半分が必要です。エディター用のこのモジュールと、runtime エントリーから `app.game.widgets` で登録するゲーム側のレンダラーです。エディターモジュールだけを登録すると、ウィジェットはキャンバス上には現れますが、Dev Mode とゲームではその位置に **Unknown widget**（不明なウィジェット）のブロックが描かれます。
</Callout>

## レンダリングの props [#render-props]

`render` は、キャンバス上でもゲーム内でも `RuntimeWidgetRendererProps` を受け取ります。

| Prop | 型 | 備考 |
| --- | --- | --- |
| `element` | `UIElement` | 描画中の要素。その props、レイアウト、`extra`。 |
| `surface` | `UISurface` | 要素が描かれている Surface。 |
| `document` | `UIDocument` | インターフェースドキュメント全体。ウィジェット自身のパーツを探すのに使います。 |
| `children` | `ReactNode` | 任意。要素の子要素で、描画済みです。 |
| `instanceKey` | `string` | 任意。1 つの要素の繰り返し描画を区別します。 |
| `listItemScope` | `UIListItemScope \| null` | 任意。この描画が属するリストの行。 |
| `renderChildren` | `(options?) => ReactNode[]` | 任意。指定した行スコープとインスタンスキーで子要素を描画します。1 つのテンプレートを繰り返すウィジェット向けです。 |
| `runtimeData` | `{ surfaceState?, globalState?, pageProps? }` | 任意。作者のブループリントが書き込む状態の読み取り専用ビューと、現在のページが開かれたときの props。 |
| `dispatchEvent` | `(eventName, payload?, options?) => Promise<void>` | 任意。この要素自身のイベントを 1 つ発生させます。[ウィジェットのイベント](#widget-events)を参照してください。エディターのキャンバス上では何もしません。 |
| `game` | `RuntimePluginGame` | 任意。ゲーム内では、`setup(app)` が `app.game` として受け取ったのと同じオブジェクトです。エディターのキャンバス上では、能力ゲート付きの名前空間がすべて欠落しています。 |

`render` が例外を投げると、その要素だけが **Widget failed to draw**（ウィジェットの描画に失敗）のブロックとして描かれ、ページのほかの部分は通常どおり描画されます。

## ウィジェットのイベント [#widget-events]

`logicApi` に `supportsPrivateBlueprint: true` を書いたウィジェットでは、要素が独自のブループリントを持ちます。このブループリントは、Studio がプロパティパネルでプラグインのフィールドのあとに追加する **Interaction**（操作）タブから開きます。`events` の各項目は、ヘッドがその `headNodeTypes` に挙げられているグラフを開始します。

```ts
// shared.ts, imported by both entries
import type { WidgetLogicApi } from "narraleaf-studio/runtime";

export const RATING_LOGIC: WidgetLogicApi = {
    supportsPrivateBlueprint: true,
    events: [
        { id: "mouseClick", displayName: "Mouse click", dispatchKind: "interaction",
          headNodeTypes: ["blueprint.event.head.mouseClick"] },
        { id: "rated", displayName: "Rated", dispatchKind: "interaction",
          headNodeTypes: ["yourname.plugin.onRated"] },
    ],
    commands: [],
    readableState: [],
    writableProps: [],
};

// in render:
props.dispatchEvent?.("rated", { stars: 4 });
```

- **ヘッドは 2 種類のどちらかです。**組み込みウィジェットが同じイベントに使うヘッド(`blueprint.event.head.mouseClick`、`blueprint.event.head.init`、`blueprint.event.head.onBroadcast` など)か、このプラグインが登録した[イベントヘッド](/ja/docs/studio/plugin/studio/blueprint-nodes#event-heads)です。それ以外のヘッドは取り除かれ、ヘッドが 1 つも残らないイベントも取り除かれます。どちらの場合も、コンソールにそのイベントが示されます。
- **ポインター、キーボード、ライフサイクルのイベントは Studio が発生させます。**`logicApi` が宣言していれば、組み込みウィジェットと同じように発生し、ポインターイベントは同じ[イベントのバブリング](/ja/docs/studio/blueprint/nodes/events#event-bubbling)に従います。ウィジェットだけが知っているイベントは、`render` から `dispatchEvent(eventId, payload)` で発生させます。ヘッドのデータ出力ピンは、ペイロードの同名のフィールドを読み取ります。
- **環境イベントは宣言不要です。**独自のブループリントを持つウィジェットは、組み込みウィジェットと同じく、キー入力、ブロードキャスト、2 つのウィンドウイベント(`keyDown`、`keyUp`、`onAnyBroadcast`、`onBroadcast`、`windowFullscreenChanged`、`windowFocusChanged`)を受け取ります。同じ id のイベントを自分で宣言した場合は、そちらが使われます。
- **runtime エントリーにも同じ宣言が必要です。**同じ `logicApi` を `app.game.widgets.register({ type, render, logicApi })` に渡してください。渡さないと、Dev Mode でもゲームでも、ウィジェットのイベントはどのグラフにも届きません。`WidgetLogicApi` と `WidgetLogicEventDef` は `narraleaf-studio/runtime` からエクスポートされています。
- **スクリプトレイヤーもこれらのイベントに応答します。**組み込みのヘッドから始まるイベントは組み込みのエクスポート名(`onMouseClick`)で、プラグイン自身のヘッドから始まるイベントは `on` とイベント id の組み合わせ(`rated` → `onRated`)で応答され、ペイロードがそのイベント引数になります。エクスポート名にできない id や、同じウィジェットの別のイベントがすでに使っているエクスポート名になる id は、グラフでしか使えません。[スクリプト](/ja/docs/studio/scripts)を参照してください。

## プラグインがないとき [#when-the-plugin-is-missing]

プラグインがアンインストールされた、無効にされた、読み込みに失敗した、あるいは[このプロジェクトでスキップされた](/ja/docs/studio/plugin/project-dependencies#スキップされるとはどういうことか)場合も、プロジェクトはそのウィジェットを保持します。各要素は子要素とブループリントごとドキュメントに残り、キャンバスにはその型を示す **Unknown widget**（不明なウィジェット）のブロックが描かれます。プロジェクトチェックはこれを **Unknown widget type**（不明なウィジェット型）として報告し、これはビルドを止めるエラーです。プラグインが再び読み込まれれば、ウィジェットは元どおり描画されます。
