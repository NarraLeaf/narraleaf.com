title: blueprintNodes
description: 在编辑器侧注册蓝图节点定义与动态下拉选项

`app.services.blueprintNodes` 为编辑器注册蓝图节点定义——调板条目、引脚、检查器字段，以及在编辑器内预览用的 `execute`。要在发布的游戏中运行同一个节点，需从 runtime 入口再用 `app.game.blueprintNodes` 注册；把定义写在一个共享模块中一次，然后从两个入口各注册一遍。参见 [创建第一个插件](/zh/docs/studio/plugin/create-first-plugin)

每个节点 `type` 都必须在 `contributes.blueprintNodes` 中声明，并以你的插件 id 为前缀

## 方法

| 方法 | 签名 | 说明 |
| --- | --- | --- |
| `register` | `(def: PluginBlueprintNodeDef) => void` | 会话内持久——返回 `void`，注册后节点类型无法移除|
| `registerMany` | `(defs: PluginBlueprintNodeDef[]) => void` | 同上|
| `registerDynamicSelectOptionsSource` | `(sourceId: string, provider: () => BlueprintInspectorParamSelectOption[]) => PluginCleanup` | 为 `kind: "select"` 检查器参数提供实时选项。源 id 必须以你的插件 id 为前缀。返回一个清理函数|
| `notifyDynamicSelectOptionsChanged` | `() => void` | 在 provider 数据变化后刷新已打开的节点卡片|

## PluginBlueprintNodeDef

核心字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `type` | `string` | 带命名空间的类型 id|
| `displayName` | `string` | 调板标签|
| `category` | `string` | 调板分组|
| `keywords` | `string[]` | 调板搜索词|
| `graphKinds` | `BlueprintGraphKind[]` | 节点可出现的位置。写 `["event"]`：作者搭建的每一张图都是 event 图，列表里没有 `"event"` 的节点永远不会被提供|
| `isPure` | `boolean` | 纯节点无副作用。插件节点只有在执行流运行到它时才输出值，因此纯插件节点无法输出值；见 [返回值](#return-value)|
| `isLatent` | `boolean` | 异步 / 需等待的执行。内联故事值和分支条件不提供 latent 节点|
| `role` | `BlueprintNodeRole` | 可选。设为 `"eventHead"` 时，节点成为插件控件的事件头；见 [事件头](#event-heads)|
| `allowInBlueprintValueGraph` | `boolean` | 可选。让节点出现在 [Blueprint Value](/zh/docs/studio/blueprint#blueprint-value) 图中。基于它的绑定只在它经由 Studio 自身节点读取的元素与属性变化时更新，插件自己的数据变化不会让它更新|
| `assetNames` | `"forward" \| "written" \| "assembled"` | 可选。节点的字符串输出从哪里来：来自它的输入、来自项目里写明的文本，或来自游戏运行时生成的值。未声明按 `"assembled"` 处理，因此只要其中某个输出被用来选取资产，构建就会拒绝该项目|
| `pins` | `BlueprintNodePinDef[]` | 执行引脚与数据引脚|
| `inspectorParams` | `BlueprintInspectorParamDef[]` | 卡片上的字段，运行时从 `ctx.params` 读取|
| `execute` | `(ctx: PluginBlueprintNodeContext) => …` | 节点主体；见下文|

引脚（`BlueprintNodePinDef`）为 `{ id, kind: "input" \| "output", semantic: "exec" \| "data", valueType?, label?, optional?, allowInlineLiteral? }`。`allowInlineLiteral` 只能用在 `valueType` 为 `string`、`integer`、`float`、`boolean` 或 `ImageAsset` 的数据输入上，其他组合在注册时抛错

节点出现在哪里由 Studio 决定。插件节点只要在 `graphKinds` 中列出 `"event"`，就会出现在每一份蓝图里，并受上述限制约束。定义里没有 `scope` 字段：定义上残留的 `scope` 或 `requiresHostApi` 会在注册时被丢弃。唯一的例外是事件头，见 [下文](#event-heads)

## execute 与节点上下文

`execute(ctx)` 收到的是一个窄而固定的上下文——`params`、`resolveInput`、`eventName`、`eventPayload`、`signal` 和 `game`。`ctx.game` 就是那个受能力把关的游戏面，与 runtime 入口的 `setup(app)` 收到的 `app.game` 是同一个对象

```ts
execute: async ctx => {
    const message = String(ctx.params.message ?? "");
    ctx.game.log("info", message);
    return { nextPort: "next" };
}
```

<Callout type="warn">
从 **studio** 入口注册节点，意味着它同样会在编辑器画布预览中运行，而那里没有游戏——`ctx.game` 上每个受能力把关的命名空间都缺席。请用可选链防护（`ctx.game.store?.…`），让同一份 `execute` 在编辑器里降级、在发行的游戏里正常工作
</Callout>

从 `ctx.game` 可触及的一切，都记录在 [运行时接口参考](/zh/docs/studio/plugin/runtime) 中

## 返回值 [#return-value]

`execute` 返回一个包含下列任意字段的对象，或者什么都不返回：

| 字段 | 类型 | 效果 |
| --- | --- | --- |
| `nextPort` | `string \| null` | 执行流从哪个执行输出引脚继续。默认为 `next`；`null` 结束这次运行|
| `nextPorts` | `string[]` | 多个执行输出引脚，按顺序依次执行|
| `outputValues` | `Record<string, unknown>` | 节点各数据输出引脚的值，以引脚 id 为键。连到这些引脚的节点读取它们|

```ts
execute: async ctx => {
    const rows = await loadRows(ctx);
    return { nextPort: "next", outputValues: { entries: rows, count: rows.length } };
}
```

插件节点只通过 `outputValues` 发布数据输出，而且只在执行流到达它时才发布。要输出值的节点请给它执行引脚，并设为 `isPure: false`

## 事件头 [#event-heads]

插件控件自己的事件从插件注册的事件头开始（见 [控件事件](/zh/docs/studio/plugin/studio/widgets#widget-events)）。事件头是满足以下条件的节点：

- `role: "eventHead"`，且 `graphKinds: ["event"]`
- 有一个 id 为 `then` 的执行输出引脚，图从这里开始
- 它暴露的每个载荷字段各对应一个数据输出引脚，引脚 id 就是字段名

Studio 只在 `logicApi` 的 `headNodeTypes` 点名了它的插件控件的蓝图里提供这个事件头，页面蓝图和**应用逻辑**里都没有。它的 `execute` 永远不会运行；返回 `{ nextPort: "then" }` 作为占位即可。和其他节点一样，从两个入口各注册一次

```ts
export const ON_RATED: PluginBlueprintNodeDef = {
    type: `${PLUGIN_ID}.onRated`,
    displayName: "On Rated",
    category: "Events",
    graphKinds: ["event"],
    isPure: false,
    role: "eventHead",
    pins: [
        { id: "then", kind: "output", semantic: "exec", label: "Then" },
        { id: "stars", kind: "output", semantic: "data", valueType: "integer", label: "Stars" },
    ],
    execute: () => ({ nextPort: "then" }),
};
```

## 动态下拉选项

```ts
const off = app.services.blueprintNodes.registerDynamicSelectOptionsSource(
    `${PLUGIN_ID}.items`,
    () => [{ value: "a", label: "A" }],
);
// 底层数据变化时：
app.services.blueprintNodes.notifyDynamicSelectOptionsChanged();
```

声明为 `{ kind: "select", dynamicOptionsSource: "yourname.plugin.items" }` 的检查器参数会渲染该源返回的选项

<Callout type="info">
要读取已连线的**数据输入引脚**，在 `execute` 内调用 `ctx.resolveInput?.(pinId)`。它沿着连线惰性求值，对未连线或未声明的引脚返回 `undefined`。卡片上的静态字段仍然来自 `inspectorParams` + `ctx.params`
</Callout>

## 插件缺失时 [#when-the-plugin-is-missing]

插件被卸载、被关闭、加载失败，或 [在这个项目中被跳过](/zh/docs/studio/plugin/project-dependencies#被跳过意味着什么) 时，项目仍保留它的节点。每个这样的节点显示为一张**未知节点**卡片，上面写着它的类型，以及插件加载时 Studio 记录下的引脚，它的连线保持原样。项目检查把它报为**未知的节点类型**，这是一个会阻止构建的 error。插件重新加载后，这些节点照常工作
