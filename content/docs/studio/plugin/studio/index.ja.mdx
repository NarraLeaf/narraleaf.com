Studio API は `narraleaf-studio/plugin` サーフェスです。プラグインが**エディタープロセス**(ワークスペースウィンドウ)で到達できるすべてを指します。プラグインが Studio 自身に貢献する場所――パネル、アクション、キーバインド、ブループリントノードのメタデータ、ウィジェット、言語パック――であり、プロジェクトのアセットや自身のストレージを読み取る場所でもあります。

これは、実行中のゲームに作用する[Runtime API](/ja/docs/studio/plugin/runtime)のエディター側の対応物です。プラグインの `studio` エントリーは Studio API とやり取りし、`runtime` エントリーはゲームとやり取りします。[2 つのエントリー](/ja/docs/studio/plugin/create-first-plugin)を参照してください。

## definePlugin

```ts
import { definePlugin } from "narraleaf-studio/plugin";

export default definePlugin({
    setup(app) {
        // 注册贡献内容、读取服务
        return () => { /* 可选的清理 */ };
    },
});
```

`setup(app)` はワークスペースウィンドウがプラグインを読み込むときに実行されます。非同期でもかまいません。アンロード時に実行するクリーンアップを返してください――ホストがどのみち各登録を追跡しているため、何も返さなくてもかまいません。

## `app` オブジェクト

| プロパティ | 型 | 内容 |
| --- | --- | --- |
| `app.plugin` | `PluginIdentity` | 識別情報:`id`、`name`、`version`、`publisher`。 |
| `app.manifest` | `NormalizedPluginManifestV2` | 正規化されたマニフェスト。 |
| `app.services` | `PluginServices` | 厳選されたエディター API――以下のサービス群。 |
| `app.privileged` | `BoundPrivilegedFacade` | マニフェストの権限によって制御される特権的な能力(ファイルシステム、bash)。 |

## 登録に関する規約

これらは、何かを登録するすべてのサービスにわたって成り立ちます。

- **`register` はクリーンアップを返します。** 各 `register` / `registerMany` は、自分が登録したものだけを取り除く `PluginCleanup`(`() => void | Promise<void>`)を返します。`registerMany` はバッチ全体に対して 1 つのクリーンアップを返します。
- **アンロードがすべてを回収します。** ホストは各登録を追跡しているため、返されたクリーンアップを一度も呼ばなくても、プラグインをアンロードすればそれは取り除かれます。クリーンアップはべき等です。
- **id には名前空間が付きます。** 登録する任意の id や型には、あなたのプラグイン id を前置しなければなりません(`yourname.plugin.thing`)。前置していない id はエラーになります。
- **命令的な呼び出しはクリーンアップではなく、その値を返します。** `ui.editors.*`、`ui.notifications.*`、`i18n.format*`、`blueprintNodes.notifyDynamicSelectOptionsChanged` はいずれも操作です。
- **ブループリントノードの登録は `void` を返します。** ノード定義はセッションを通じて永続するため――1 つを取り除くと開いているドキュメント内のノードが孤立してしまいます――破棄すべきものが何もないのです。

<Callout type="warn">
プラグインはサンドボックス化されていません。Studio API は厳選されたホワイトリストですが、マニフェストが対応する権限を宣言すると、`app.privileged` は実際のファイルシステムとシェルに到達します。すべては Studio 自身のアクセス権のもとで実行されます。
</Callout>
