---

两个设置，都在项目设置的**安全**一节下，都按项目保存。它们在打包版和预览版中生效，对开发模式没有任何影响

## Network access（网络访问）

游戏能向网络伸多远。三个档位，按从小到大排列

**关闭**——每个新项目的默认值。游戏被限制在自身的内部协议内，它发出的所有 HTTP、HTTPS 和 WebSocket 请求都会被取消

**白名单**——只允许工程列出的地址，加上它的插件在 `contributes.network` 里声明的主机。选中它会在选择器下方展开白名单编辑器；插件自带的模式会标明属于哪个插件地列在那里，于是这份列表能说出一个主机为什么可达，而不是默默地给它腾地方

**任意主机**——游戏可以请求任何东西。它和白名单都能让 [Network 节点](/zh/docs/studio/blueprint/nodes/network)跑起来

这份构建认不出来的设置——比如来自更新版本的一个词——会被读成**关闭**而不是最宽的那一档：一个设置都看不懂的工程，这份构建也担保不了它，而拒掉请求是作者当场就会发现的那种失败，而不是跟着产物出去的那种

该设置在三处被检查：关闭期间工程检查把网络节点报为错误、生产构建被拒绝、运行时请求本身被拒绝

<Callout type="warn">
在 **Web 导出**中不生效。它依靠的机制只有桌面构建才有，而通过 HTTP(S) 提供的游戏本身就在网络中。网络节点在 Web 构建里会运行。上面那条构建拒绝仍然适用，所以关闭该设置的项目无论如何也产不出含有这些节点的 Web 构建
</Callout>

## Encrypt assets（加密资源）

构建出的游戏内部的内容是否受保护

**关闭**——游戏的文件以普通文件形式发出。任何人打开安装目录都能读取图片、音频和视频，也能读取剧本文本和插件代码

**开启**——以下内容在打包版和预览版中被加密：

- 图片、音频和视频
- 编译后的剧本
- 插件代码
- 玩家的存档文件

加密由 [NarraLeaf/Encryption](https://github.com/NarraLeaf) 提供，保护强度达到 KiriKiri 级别

<Callout type="info">
Web 构建始终不带加密。浏览器必须直接读取这些文件，没有可供隐藏的位置
</Callout>

它做什么、不做什么：它使这些文件无法用普通工具打开，从而阻止随手提取。它不是针对有备而来的攻击者的保证，因为运行中的游戏本身必须能读取自己的内容
