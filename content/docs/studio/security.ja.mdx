---
title: セキュリティ
description: ビルドしたゲームに何ができるか、その中に何が同梱されるかを決める 2 つのプロジェクト設定
---

2 つの設定があり、いずれもプロジェクト設定の**Security**（セキュリティ）にあり、プロジェクトごとに保存されます。どちらもパッケージビルドとプレビュービルドで有効になり、Dev Mode には影響しません。

## Network access（ネットワークアクセス） [#network-access]
ゲームがネットワークにどこまでアクセスできるかを決めます。アクセス範囲が狭い順に 3 つの設定があります。

**Off**（オフ）— すべての新規プロジェクトの既定値です。ゲームは自身の内部プロトコルに閉じ込められ、発行する HTTP、HTTPS、WebSocket のリクエストはすべて取り消されます。

**Allowlist**（許可リスト）— プロジェクトが列挙したアドレスと、プラグインが `contributes.network` で宣言したホストのみが許可されます。選択すると選択肢の下に許可リストのエディタが表示され、プラグイン自身のパターンはそのプラグインに紐づけて表示されます。これにより、あるホストが到達可能な理由をリストが示せるようになり、黙って場所を空けるだけにはなりません。

**Any host**（任意のホスト）— ゲームは何でもリクエストできます。この設定と Allowlist は、[Network ノード](/ja/docs/studio/blueprint/nodes/network) を動作させるために必要です。

このビルドが認識しない設定値——将来のバージョンに由来する語——は、最も広い設定ではなく**Off**として扱われます。設定を理解できないプロジェクトをこのビルドが保証することはできず、リクエストを拒否するという失敗は、そのまま出荷される失敗ではなく、作者がその場で気づける失敗だからです。

この設定は 3 か所でチェックされます。Off の間はプロジェクトチェックがネットワークノードをエラーとして報告し、プロダクションビルドは拒否され、実行時にはリクエスト自体が拒否されます。

<Callout type="warn">
**Web export**（Web エクスポート）では強制されません。この仕組みはデスクトップビルドだけが持つ機構によって動作するもので、HTTP(S) で配信されるゲームはその性質上すでにネットワーク上にあるためです。Network ノードは Web ビルドでも実行されます。上記のビルド拒否は変わらず適用されるため、この設定がオフのプロジェクトは、いずれにしても Network ノードを含む Web ビルドを生成できません。
</Callout>

## Encrypt assets（アセットの暗号化）

ビルドしたゲーム内部のコンテンツを保護するかどうかの設定です。

**Off**（オフ）— ゲームのファイルは通常のファイルとして出荷されます。インストールされたフォルダを開けば誰でも画像、音声、動画を読み取れ、ストーリーテキストとプラグインコードも読み取れます。

**On**（オン）— パッケージビルドとプレビュービルドの内部で、以下が暗号化されます。

- 画像、音声、動画
- コンパイル済みのストーリー
- プラグインコード
- プレイヤーのセーブファイル

暗号化は [NarraLeaf/Encryption](https://github.com/NarraLeaf) によって提供され、保護の強度は KiriKiri と同等です。

<Callout type="info">
Web ビルドには常にこの暗号化は含まれません。ブラウザはファイルを直接読み取る必要があるため、その背後に隠す場所がないためです。
</Callout>

この機能でできること、できないこと。ファイルを通常のツールで開けないようにすることで、何気ない抽出を防ぎます。実行中のゲーム自体が自分のコンテンツを読み取れる必要があるため、本気の攻撃者に対する保証にはなりません。
